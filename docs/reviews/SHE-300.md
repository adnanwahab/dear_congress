# SHE-300 build diagnostics implementation and handoff

Refs: https://linear.app/shel-bernstein/issue/SHE-300/opstoday-stretch-expose-deployed-commit-build-date-and-environment-in

Audited README, source-recovery notes, launch merge policy, server health route,
metadata-aware page renderer, Dockerfile, Fly config and CI/release workflows.
GitHub PR search found no SHE-300 PR; open PRs #20–39 concern other tickets.
Recovered source is present; docs/source-recovery.md explicitly does not prove
live source equality. This stretch change is a review candidate and must not
delay launch or close SHE-281/SHE-280/SHE-300 without human acceptance.

Implemented an image-generated manifest with a required full lowercase SHA and
UTC image build date. Runtime SHA/date variables cannot relabel an old image.
The loader allowlists fields and returns null for missing/invalid local identity.
Public /version supports GET/HEAD, uses security headers/no-store, sets no cookie,
and exposes fixed repository/demo mode, production/development environment and
optional strictly formatted Fly release version. No general environment dump.
The footer is server rendered outside React's root using the endpoint's same
process snapshot. /healthz and persisted state are unchanged.

The existing release-only workflow passes the validated release SHA to Docker
and verifies the deployed API SHA and refreshed page marker afterward. The smoke
script rejects missing identity, wrong SHA, stale HTML, failed requests and timeouts.
It can also verify a restored older image against that image's original SHA.
No live rollback or deployment occurred. An endpoint declaration is not a signed
artifact attestation; a single-machine response is not proof of fleet convergence.

Validation: typecheck passes; focused identity/workflow/verifier tests pass.
Final full bun test reported 207 passes, 21 failures, all listener-dependent
failures with EADDRINUSE on port 0 in this restricted execution environment.
bun run test:routes encounters the same listener failure. Successful real-router,
browser refresh, image build, live release and rollback checks remain required in
an environment permitting listeners and by the authorized release owner. No live
acceptance is claimed. Existing production data was not used for smoke tests.

Governance policy is preserved: disabled/dry-run merge defaults, quorum 10,
24-hour exposure, current-head approval, fail-closed allowlists and active kill
switch are untouched. Required main checks remain bun test, bun run typecheck,
and route smoke test. Human approval and published tagged releases remain required;
PRODUCTION_RELEASES_ENABLED was not enabled. No deploy, merge, release, external
message, issue-state change or production-data write was performed.
