## Finding and bounded fix

Home renders its first sample when no `proposal` query is present, but its primary
Explore link previously pointed to bare `/votes`. WorkflowScreen initializes a
bare Votes route from `civic_demo_selection_v1`, so a previously viewed transit
proposal could replace the sample displayed on home. The primary link now carries
the displayed sample ID once loaded. Explicit URL selection remains authoritative,
including unknown IDs; pre-load/offline links remain actionable. Other routes,
ballots, records, receipts and repository/item/revision isolation are unchanged.

The existing Happy DOM home-start integration now seeds a different prior choice,
loads home, follows the generated destination and verifies the Votes selector
matches the displayed home sample. Existing offline and encoded-ID assertions
remain. This is component-level evidence, not native browser acceptance.
