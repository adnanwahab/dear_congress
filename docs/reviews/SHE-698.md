## Proposed implementation contract

Create separate watch-session, membership, invitation, artifact-grant, message,
report and audit records. Preserve existing vote, proposal, repository/item-kind,
PR head/base and receipt namespaces. Keep the current single-writer persistence
contract; use serialized atomic saves with rollback and restart verification.
Do not migrate or rewrite old snapshots to imply historical sharing consent.

Bind a session to an immutable validated synthetic receipt revision and digest,
source identity, model version, seed and finite recorded horizon. Archive only
the reviewed allowlisted result after explicit sharing confirmation, never raw
provider state or journal text. Reject missing/unavailable receipts and unreviewed
source-to-proposal associations. Initial selected-event support requires a
reviewed stable event contract; until one exists, show event selection unavailable
and expose a separately named recorded-checkpoint selector. Checkpoints cannot
be represented as provenance events.

Use a server-authoritative clock with session revision, paused/playing state,
anchor position, server timestamp and a bounded supported rate. Clamp position to
the receipt horizon and stop at its end. Controller commands require expected
revision; reject stale updates rather than letting a reconnect rewind everyone.
Late joiners and reconnects receive a fresh authorized snapshot. Clients ignore
older revisions, stop on stale/disconnected state, and visibly offer rejoin.
Never rerun the source model to advance playback. Even a controller can change
only watch state, never the source run, receipt, proposal or ballot.

| Audience | Required visible and server-enforced behavior |
| --- | --- |
| Personal | Owner only; no directory, public hub, shared stream or implicit moderator access |
| Invite-only | Explicitly admitted active members; expiring single-use invitations establish membership; a copied URL alone grants no continuing access |
| Public | Only the explicitly approved artifact revision is public; session publicity never publishes all linked artifacts, private notes, roster or reports |

Default to personal. Explain audience before joining and sharing; show it at the
session heading, composer and artifact preview. Sharing a receipt, selected event,
message or excerpt requires its own revision-bound audience grant. Wider sharing
or edits invalidate prior approval. Do not automatically copy public proposal
comments or private journal/draft text into a party.

Observers may read authorized artifacts and leave/report. Explicit scoped grants
may allow discussion or clock control; admission does not confer either. Only
the owner can issue/revoke grants; moderator assignment must be explicit and
limited to that session. Enforce authorization on every read, mutation, export
and stream delivery, including after revocation. Retain same-origin/CSRF checks,
signed identity, bounded JSON, rate limits and server-only moderator credentials.
Never accept a client-supplied owner, role, consent or synthetic-origin assertion.

Leave removes membership and closes streams. Revoke removes future access to
the selected artifact/grant immediately, including queued deliveries and public
projections; reconnect cannot restore it. Stop playback and clear inaccessible
content on denial. Explain that already viewed screenshots/copies cannot be
recalled. Define report/audit retention before enrollment. Use typed session and
artifact revision targets, private reporting receipts, human triage and reasoned
moderation decisions. Public audit projections must omit raw text, invitation
secrets, cookie hashes and reporter identity. Log minimal authorized metadata for
joins/leaves, grants/revocations, control changes and moderation decisions.

Keep any synthetic walkthrough separate, visibly labelled at entry, per demo
message and in attendance summaries. Synthetic model actors never become session
participants, verified contributors or vote totals. Do not fabricate presence or
messages to make an empty real session appear active.

Integrate explicit entry points in `CitizenProposals.tsx`, a separate session
mode/component linked from `LiveRound.tsx`, and only current explicitly public
artifacts in `TopicHubs.tsx`. Preserve the existing advisory round endpoints and
topic exclusions. Update public participation/privacy guidance with actual
implemented behavior, never aspirational guarantees.
