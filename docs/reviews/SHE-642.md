The actual world engine is outside this authorized repository. Receipt v1
contains simulation time and outcome metrics, not elapsed compute time.
Checkpoint spacing, trips, actor activity, and household counts cannot establish
event throughput. Browser fetch duration includes network, queueing and decoding;
it cannot establish provider stage duration. Browser heap cannot measure a remote
worker's memory. Consequently a genuine stage profiler requires provider-produced
instrumentation before a consumer implementation can meet the requested build.
No substitute measurements or invented traces were added.

## Proposed contract for implementation review

Agree a versioned, optional profiling receipt with the provider owner first;
do not silently reinterpret existing v1 fields. Keep the ordinary explorer
usable when profiling is unsupported. The provider work is a dependency, not
authorization to edit HappyBearLandia from this task.

The receipt needs an immutable run ID, source repository/model identity,
model version, source data mode, seed, exact allowlisted inputs, baseline/edited
branch, horizon with units, instrumentation version, and major uncertainty.
Bind every sample to that run and input revision. Capture monotonic elapsed
milliseconds at actual stage boundaries and explicitly define whether intervals
include queueing or overlap. Define event count as executed simulator operations,
separately from modeled resident actions; derive events/second only for positive
measured durations. A zero-duration sample reports unavailable throughput.

Memory must name its measurement scope and units (e.g. sampled worker heap bytes),
sampling method and availability. Do not claim sampled heap is peak RSS or
attribute shared process memory to a stage. Report unsupported memory as
unavailable. Budget must identify its resource, units, configured cap and consumed
amount; distinguish wall-clock deadline, operation cap and policy spending.
Provider admission limits must remain effective with instrumentation enabled.

Use fixed stage identifiers, finite nonnegative values, bounded arrays and bytes,
ordered timestamps, explicit unavailable reasons, and validated totals. Reject
mismatched version/input/run/branch identities and malformed or oversized records.
Keep private journals, votes, identity and arbitrary legal text out of profiling
requests and exports. Preserve existing receipts rather than mutating them.

## Consumer and acceptance work still required

- Put the optional engine room in a closed native details disclosure. Opening it
  should inspect an existing instrumented receipt, not trigger unbounded runs.
- Plot stage activity against measured elapsed time with a readable table
  alternative. Label compute activity separately from social activity. Include
  source data mode, seed, model version, horizon and major uncertainty beside
  every independently viewable/exportable display.
- Replay recorded samples with manual scrubbing and explicit play/pause. Default
  to paused; reduced motion must prevent automatic animation. No fabricated
  interpolation of missing counters or memory samples.
- Retain current allowlisted inputs, deadline, cancellation, stale-response
  rejection and model-version matching. Household effects stay unavailable until
  a reviewed household mechanism exists. Score inspection remains read-only.
- Export a bounded validated receipt and exact input recipe. Reopening restores
  inputs without automatic execution. Deterministic replay means identical stored
  sample selection and model outputs; fresh timing and memory measurements are
  inherently machine/load dependent and must not be promised bit-identical.
- Keep the synthetic/nonforecast warning and the boundary against executing
  arbitrary legal prose visible in the engine room.

Required tests: receipt bounds/identity and missing measurements; actual
instrumented provider fixture integration; known operation counts and stage
ordering; zero-duration throughput; replay and share/reopen without autorun;
keyboard focus and native slider behavior; touch at 320/390px; reduced motion;
loading, cancellation, timeout, retry, unsupported instrumentation, provider
failure, late responses after input changes, and version mismatch. Fixture UI
tests alone cannot establish that provider measurements are real. Existing
law behavior tests do not establish profiler acceptance.
