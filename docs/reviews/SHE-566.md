## Proposed implementation contract

These are recommendations for implementation, not current guarantees or approved
editorial policy. The missing vault does not prevent developing a separate public
cache, but it prevents claiming encrypted private annotation acceptance. The first
safe implementation needs an explicit approved content manifest rather than
guessing eligibility from existing API names or proposal titles.

1. Define a server-owned public projection and reviewed manifest. Include schema,
   approval revision, source repository, item kind, immutable source ID/revision,
   canonical source URLs, fetched time, evidence date, expiry, content digest,
   and model/schema compatibility when relevant. Require finite ordered dates,
   bounded payloads and explicit cache permission. Reject unknown kinds, missing
   provenance, unknown compatibility and unapproved entries. Fetched time means
   retrieval, not evidence verification. Exclude private fields through an
   allowlist projection before serialization.
2. Use an independently versioned public-content store and static-shell cache.
   Cache only successful same-origin GETs on the manifest allowlist. Reject
   redirects, authenticated/user-specific variants and no-store responses. Keep
   mutation routes, cookies/tokens, SSE, journal drafts, ballots and receipts out.
   An installed worker must never intercept mutations with a fabricated success
   or background-sync registration. Existing source and vote identities remain
   untouched. Repository PR identity includes repository, item kind, number,
   head SHA and base binding; a local museum record never authorizes a ballot.
3. Cache a complete, versioned shell and selected explainer modules atomically.
   Activate only after required artifacts pass integrity/availability checks;
   retain the previous working build until replacement is complete. Avoid
   mixing an old shell with newly fetched incompatible data. Serve a dedicated
   read-only museum fallback for uncached routes, rather than exposing cached
   participation UI as current. First-ever offline access must explain that
   nothing has been downloaded. Installation requires HTTPS and browser support.
4. Show **Offline mode** persistently on museum views, plus per-item last-fetched
   time, evidence date, source links and expiration state. Treat navigator status
   as a hint: failed reads can also trigger offline fallback. A cached item must
   never masquerade as a fresh successful network response. Unknown or incompatible
   model versions disable new play; clearly identify compatible recorded playback.
   Use a bundled deterministic fixture model for local play only if its exact
   implementation/version is available and tested. Never extrapolate new results
   from cached output or invoke remote simulations while claiming local execution.
5. Reconnect announces “Refresh available” with an explicit refresh button. Do
   not automatically replace a reading session, publish a draft, retry a vote or
   send a failed public post. Refresh checks current eligibility/revision and
   revocation; expired/unapproved material is excluded from active reading until
   refreshed. Offline revocation cannot be detected before connectivity returns:
   display that limitation. Failed refresh retains clearly marked stale data
   only where its retention policy permits. Do not reset fetched timestamps on
   failed checks. Model mismatch requires a compatible package, not relabeling.
6. Store private annotations separately from public payloads, under a reviewed
   encrypted vault contract when SHE-319 provides one. Never copy private journal
   data into public Cache Storage, telemetry, search indexes or public requests.
   Until then, explicitly memory-only annotation is safer than plaintext durable
   storage labeled private/encrypted. Any durable local draft save must be an
   explicit action with reviewable text and source revision, with no upload/replay
   operation. An empty outbox is sufficient: the requirement permits queuing only
   deliberate drafts; it does not require a publication queue.
7. Bound public storage by both bytes and count, for example a proposed 20 MiB /
   100-item cap pending product review, with oldest unpinned public content evicted
   first. Reject oversized records before writing. A failed quota write must not
   erase the previous valid snapshot or report success. Pins still count toward
   the hard cap. Use browser storage estimates as advisory, not guaranteed quota.
   Distinguish clear downloaded public reading, remove private notes, and uninstall
   offline shell; never call origin-wide storage clear. Preserve existing follows,
   amendment versions, cookies and future encrypted vault keys unless explicitly
   selected in their own controls. Show storage unavailable/evicted honestly.
8. With no service worker or blocked storage, retain in-memory reading and local
   play for the open tab, visibly explain that reload will need connectivity, and
   disable download/install claims. Optional-storage failures must not break the
   ordinary online app or weaken authentication and CSP.

## Required acceptance evidence

All rows remain pending. Unit/DOM success alone does not establish installation,
browser eviction, mobile behavior or encrypted-vault isolation.

| Journey | Required observable result |
| --- | --- |
| Approved content only | Sentinel private fields in state/journal/auth/ballot payloads never enter cache; unapproved, redirected, no-store and oversized responses are rejected. |
| Offline reload/install | Download on HTTPS, close/reopen offline, follow a previously viewed proposal and required lazy explainer; cold offline visit and uncached route show an honest fallback. Repeat after worker/build update interruption. |
| Reconnect | Stale evidence, expired source, withdrawn approval, changed revision and incompatible model each have distinct visible states; no network refresh until deliberate action; failed refresh does not renew timestamps. |
| Mutation isolation | Capture requests, worker caches, IndexedDB and background-sync registrations while voting/posting offline and losing a submission response. Reconnect, reload and restart browser: zero queued/retried votes/posts and zero fabricated success. Fresh deliberate review is required to submit. |
| Local work | Annotate and play offline without network calls. Explicit draft save binds the original source revision; changed source preserves earlier work and asks for review. Playback is labeled recorded and never changes ballots or synthesis. |
| Quota/eviction | Hit both limits, inject quota errors and browser eviction, corrupt records and unsupported versions; bounded memory, honest unavailable states, preserved valid previous snapshot and no vault/follow/amendment deletion. |
| Clear and isolation | Clear only public downloads, restart with worker active and verify they do not reappear without deliberate download. Private sentinel vault records/keys remain untouched. Verify deletion across tabs. |
| Fallback/mobile | No-worker, denied storage, denied persistence, private browsing, network failure while browser reports online, narrow mobile, keyboard and screen reader journeys remain usable with clear capability limits. |
