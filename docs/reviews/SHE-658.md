## Audit and implementation

Read repository AGENTS.md, readme.md, bill-catalog documentation, accessibility
acceptance documentation and launch merge policy before changes. The existing
catalog is read-only; workflow advisory participation and repository ballots are
separate. No existing procurement game was found. GitHub PR search scoped to
adnanwahab/dear_congress for procurement returned no matches (November 15, 2026).
The supplied live reference could not be read by the web reader; no live parity
claim is made.

ProcurementGame is an explicit opt-in experience in BillCatalog, WorkflowScreen
and DemoTour. Starting from the tour pauses its timer; tour shortcut interception
excludes game controls so radio arrows, Space and Enter retain native behavior.
The underlying tour remains read-only. Three fictional library equipment bids
show budget, durability and deadline conflicts against public fictional criteria.
A separate scorecard explains each criterion and never infers fairness from a
vendor choice. Equal access, conflict disclosure and consistent review are
process obligations. There is no ideological reward, aggregate winner, actual
award or real vendor endorsement.

All scenes retain the hypothetical notice. Skip reaches an explanation without
selection or penalty; Restart clears selection; Exit unmounts the playable scene
and returns focus to Play. A native details disclosure exposes the complete brief,
bids, scores and explanations before playing. Native buttons, radio group and
shared theme/chip styles provide keyboard/touch controls and wrapping layout.
State lives only in component memory. There are no fetch calls, storage writes,
identity transfers, participation changes, server changes or data migrations.
