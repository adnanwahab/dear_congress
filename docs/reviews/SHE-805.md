# SHE-805 deployment identity review and handoff

Refs: https://linear.app/shel-bernstein/issue/SHE-805/cs-l100015-emit-deployment-sha-and-buildrelease-identity-in-version

Audited repository instructions, README build diagnostics, source recovery,
release parity, launch merge policy, manifest loader/writer, Docker build,
/version route and release workflow before changes. GitHub search found no
SHE-805 PR. Related open PRs include #307 (release telemetry) and #333 (asset
caching); neither is acceptance evidence for this issue. Existing main already
implements image-generated commit and builtAt, runtime environment, optional
flyRelease, no-store GET/HEAD, and SHA-bound release parity.

This change extends that manifest with an optional public release tag (`release`),
allowlisted to a bounded v-prefixed identifier. The human-published release
workflow supplies BUILD_RELEASE alongside its validated full SHA and requires
that same tag in its HTTP smoke check. Missing/wrong tags fail that workflow
check. Runtime BUILD_COMMIT/BUILD_RELEASE cannot relabel an image. Fly's optional
runtime release number remains separate. Unknown local identity stays null.
Only fixed/allowlisted fields are returned; no environment dump is introduced.
Tests generate an isolated manifest and load it with conflicting runtime values,
and verify malformed tags, stale/missing release identity and secret exclusion.

Identity is traceability, not signed attestation. Keep Linear open until human
verification. No deploy, merge, release, external message or production-data
write occurred.

tag trigger unchanged; disabled/dry-run governance, quorum 10, 24-hour exposure,
current-head approval, fail-closed allowlists and active kill switch untouched.
Required main checks remain bun test, bun run typecheck and route smoke test;
at least one human approval is required. Live protection/environment settings
were not changed or claimed verified. Existing votes, source identities, PR
revision isolation, records and receipts are untouched.
