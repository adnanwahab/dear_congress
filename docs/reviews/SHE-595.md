## Behavior and data

The existing `/needs` chapter contains a disclosure with inclusive UTC date
filters, previous/next buttons, native timestamp selection, a bump chart, exact
rank/score table, and every sample's denominators in a text alternative. Chart
positions use actual timestamps. Lines join samples without estimating intermediate
rankings. Stable per-need snapshot names animate selected dots with the typed
`priority-history` transition. Native chapter anchors remain unchanged.
Superseded callbacks and unmounted requests cannot overwrite the latest selection.
The shared helper handles unsupported APIs, reduced motion, off and slow modes.

Normal database saves prospectively append changed model ranks/counts, including
a startup baseline at the actual recording time; unchanged results do not append.
The latest 365 changes are retained. There is no reconstruction of older dates.
Missing/empty windows show unavailable; one record explicitly cannot show change.
`GET /api/priority-history` only reads stored aggregates and disables caching.
The viewer sends GET requests only and contains no public submission action.

These are recordings of the existing shared-needs model, not verified population
preferences or GitHub issue ballots. Existing model scoring is unchanged, including
simulated priority priors, sample journals and optional measured outcomes. Each
sample records its source/method version, timestamp, public non-synthetic journal
count with real/sample breakdown, allocation-ballot denominator, simulated prior
population and outcome mode. Text, authors, voter IDs and individual ballots are
not exported. Need IDs and public labels are retained; source repository identities,
repository/item-kind voting, PR head/base bindings and records/receipts are untouched.
