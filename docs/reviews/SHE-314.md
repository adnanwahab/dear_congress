## Proposed bounded spike

Spend 2–3 days validating an offline federal adapter and provenance contract
before committing to the estimated 2–4 week implementation. Use recorded official
responses in a disposable store; no public refresh job or production writes.
Demonstrate one introduced bill, one enacted measure, two text revisions, one
amendment, related House/Senate measures, and a deliberate refresh outage.
Record missing fields, request counts, storage size, mapping exceptions and
licensing findings. Stop for scope review if evidence cannot support reliable
status classification or reproducible text comparisons.

Proposed storage/API boundaries (not existing contracts):

| Record | Required identity and evidence |
| --- | --- |
| Measure | source adapter + jurisdiction + session/Congress + measure type + number; official URL, title, sponsor IDs/names and originating chamber |
| Observation | measure ID, source publication/update time, fetchedAt, checkedAt, last successful complete check, attempt/error state, parser version and raw metadata hash |
| Action | original action text/code/date and acting chamber, official citation and observation hash; preserve unknown actions |
| Document | original/final URL, format, official revision code/date, exact raw bytes, SHA-256, retrieval time and immutable archive locator |
| Revision | measure ID + official version + raw hash, amendment/related-measure links, extracted text hash and extraction version |
| Legal assertion | classification, supporting action/document citation and hash, checkedAt, mapping version; unknown/conflicted is explicit |
| Effective provision | date or condition, section/page citation and revision hash, review state; unknown is valid |

Never key by title, bill number alone, or URL alone. Reintroduction in a new
Congress is a new measure, optionally related to its predecessor. Companion bills
retain distinct IDs and actions. Law identity links back to the enacting measure
without replacing it. Use null with a reason for missing sponsors/text/dates;
do not invent values. Enactment date is not automatically every provision's
effective date. Effective-date extraction needs explicit cited review.

Append metadata observations as well as documents. If a source changes bytes at
the same URL/version label, retain both hashes and flag a source correction.
Store original bytes before parsing; normalized or extracted text is a derivative.
A hash proves retained content consistency, not official authenticity. Retain the
official URL, retrieval evidence and any available signature verification result
without describing unsigned artifacts as authenticated.

Compare explicit revision pairs within the same measure. Offer original downloads
and a readable text diff naming both dates, hashes and extraction method; preserve
amendments as separate records, never silently splice proposed amendments into bill
text. Missing or unextractable text yields “comparison unavailable,” not “no change.”

## Status, refresh and user contract

Keep a persistent sample lane and separate citizen and official lanes. Use textual
badges “Citizen idea,” “Draft,” “Introduced bill,” and “Enacted law.” Draft is an
app lifecycle state; official status is an independently evidenced field. Publishing,
advisory votes, simulated tracker changes and suggested sponsors never promote a
proposal into an official bill. Related citizen ideas can link to official measures
without transferring votes, comments or endorsement claims.

In `/published`, show bill identifier, jurisdiction, originating chamber, official
sponsor, cited last action, status-as-of check and cache age. In `/feed`, maintain
the lane and badge on list and detail views. In `/outcomes`, show official action
history separately from simulated outreach and measured social outcomes; enactment
alone proves neither implementation nor policy impact.

Map only reviewed official action patterns to status. Retain chamber-specific
events and disagreements; one chamber's passage is not enactment. Unknown,
withdrawn and ended-session measures need explicit lifecycle qualifiers. Withdrawal
requires a supported official event, not absence from a list or sponsor withdrawal.
Conflicting sources show a conflict and the underlying evidence, not a guessed
legal conclusion. Exclude unsupported measure types from the initial adapter.

Propose a configurable 24-hour freshness window for the spike, subject to source
update latency review. Display “last checked,” age, and upstream update time as
different values. Even within that window, say “official status as checked at …”
rather than promising real-time currency. A failed attempted refresh immediately
marks retained results “refresh failed; last verified …”; expired results are
“stale”; no prior success is “unavailable.” Never advance checkedAt on an error,
partial pagination, parse failure or metadata-only check when text is required.
Compute expiration at read time so a stopped worker cannot leave a current badge.

Use bounded concurrency, retry with jitter/Retry-After, server-only credentials,
request budgets and resumable pagination. Publish a new per-measure snapshot
atomically only after its required collections validate; incomplete coverage is
explicit at catalog level. Preserve last-good records and errors. A 404 or missing
page does not delete a measure or prove withdrawal. Do not advance a global cursor
past incomplete work; use overlapping update windows and periodic reconciliation.
Revalidate allowed official hosts after redirects, bound bytes/time and disable
external XML entities. Escape imported markup; never execute document HTML.
Redact API keys from persisted URLs/logs while retaining unmodified response bytes
in protected storage where needed for provenance. Do not attach reader identities,
journals or votes to upstream fetches.

## Required verification before implementation acceptance

All below are planned tests, not passing importer tests:

| Fixture/check | Positive result | Negative result |
| --- | --- | --- |
| Reintroduction | distinct Congress/session IDs, explicit relation | no inherited votes, revisions or law status |
| Withdrawal | cited supported event and timestamp | missing list entry or withdrawn sponsor cannot withdraw bill |
| Multi-chamber | separate chamber history and companion identities | single-chamber passage cannot become enacted law |
| Enactment/effective dates | cited law record; per-provision evidence | no effective date inferred solely from enactment |
| Revision/amendment | stable replay and readable two-version diff | same URL with new bytes cannot overwrite archive; proposed amendment cannot become enacted text |
| Failure/freshness | last-good visible with failed/stale badge and age | 429/timeout/invalid JSON/partial page never resets freshness |
| Source trust | approved URL, matching identity and retained hash | spoofed host, redirect, malformed document or hash mismatch quarantined |
| Replay/isolation | restart and duplicate ingestion preserve records | no mutation of citizen/demo IDs, ballots, PR head/base bindings or receipts |

missing timestamps), incomplete pagination recovery and out-of-order responses.
