## Behavior

The builder lives within the lazy catalog screen at `/bills?exhibit=builder`.
Educators select one catalog source for each of five panel roles. Search reuses
searchBills and category identifiers. Empty searches explain recovery. Selected
sources remain visible through filters. Native selects support keyboard selection;
there is no animation, canvas, drag interaction or high-power alternative requiring
a separate accessible implementation.

Consent, accessibility and hypothetical labeling checks gate local preview creation.
Changing any source clears all checks. These are curator attestations, not automated
accessibility certification or verified consent. There is no server publishing API.
Preview URLs serialize five role/ID/revision bindings, with strict role coverage,
known-source and revision validation. Invalid, unknown or stale inputs fail closed
rather than substituting newer content. Read-only preview contains no editing
controls; URL input is untrusted and never creates civic authority or records.
Browser history restores query/category/mode/preview through popstate. Draft panel
selection stays in page memory, is lost on reload, and is not a history snapshot.

Every panel is labeled hypothetical. Evidence explicitly says unassessed; results
show proposed metrics and explicitly deny measured outcomes. Catalog source links
and revision IDs remain visible. No external source accessibility is inferred from
a URL or check date. This path makes no externally verified significant claims.

Downloaded HTML freezes selected text and sources in one read-only, script-free
file with no remote dependencies. Native browser Find, Tab, focusable panels and
anchor navigation remain available offline. Source destinations need connectivity;
the frozen text remains readable. Host that file in a sandboxed iframe for an
embed; embedding the app itself is not required or enabled. No data migration,
API write, voting change or persistent draft store is introduced.
