## Acceptance gaps and bounded spike

All five issue criteria remain unaccepted: voluntary household/reset is absent;
cohort winners/losers beside totals are absent; deterministic household results
are unproven; no new household privacy boundary has been tested; and the required
modeled/observed/unavailable classification is absent for household metrics.

Before committing the estimated 2–4 week build, run a small disposable-data spike
after SHE-311's comparison contract is verified. Prove two hypothetical cohorts,
one supported metric and one unavailable metric with a frozen package and paired
baseline. Validate a versioned, distribution-sensitive model with its responsible
owner before displaying numerical effects. A successful UI demonstration alone
does not satisfy this gate. If the model or dependency is unavailable, retain an
explicit unavailable result rather than fabricating coefficients or effects.

The following are proposed Dear Congress boundary and validation requirements,
not a specification or authorization to change the external HBL application:

1. Offer explicitly hypothetical, optional preset choices with no preselection
   inferred from journals, cookies, geography, IP, account or browsing history.
   State that a selection describes an experiment, not the visitor. Reset returns
   to the unselected aggregate view and clears selection/results. Use transient
   state by default; any later persistence/share path needs explicit design review.
2. Keep the experiment independent of journal entryId, linked needs, coordinates,
   voter identity, account identity and protected-status inference. Do not extend
   current living-city location forwarding to this path. An opaque snapshot ID
   alone does not establish anonymity: review the fetched payload too. Use public
   package provenance and synthetic preset IDs only; do not rewrite existing
   snapshots, records, votes or receipts to achieve the new boundary.
3. Pin frozen package content/version, model version, assumption version,
   archetype definition/version, seed, horizon and run count. Reuse paired random
   streams for baseline and intervention; cohort selection must not reshuffle
   futures. Record these public experiment inputs for reproducible comparisons.
4. Report total and cohort distributions in explicit units and time horizons,
   paired changes, better/worse/unchanged counts and denominator. Define favorable
   direction per metric; taxes and service benefits need separate treatment.
   Avoid an unsupported overall winner label that silently combines trade-offs.
5. Display simulated cohort size, valid paired-run count, missing-run count and
   weighting assumptions separately from any observed source sample size. Neither
   600 preference voters nor 100 futures is an observed household sample. Empty
   cohorts and unsupported metrics are unavailable, never zero-impact estimates.
6. Label every metric modeled, observed or unavailable. Modeled results disclose
   assumptions and interval method/coverage; variability across synthetic futures
   is not automatically a calibrated confidence interval. Observed values require
   dated source/geography/units and cannot imply policy causation. Unavailable
   results explain the missing model/data and do not borrow aggregate values.

## Provenance review and verification plan

The README calls costs/support illustrative and outcomes.json a starter fixture.
Its FEMA/Census source URLs, timestamps and caveats do not independently validate
the checked-in numbers, causal effects, cohort sample sizes or model calibration.
This review inspected local provenance fields and transformation code only; it
did not refresh public sources, verify upstream publications or inspect HBL's
models. Do not relabel fixture or synthetic results as observed. Model review
must establish coverage, limitations, calibration and evidence for each of rent,
travel time, flooding, taxes and services, with unavailable fallbacks elsewhere.

Required future positive and negative checks, using isolated fixtures:

- Opt-in and keyboard selection work; reset clears selection/results, pending
  requests cannot repopulate cleared results, and unselected use stays functional.
- Identical pinned inputs reproduce all cohort values and intervals across
  reruns/restarts; reordered cohorts preserve paired streams; changed seed/model
  version is identified rather than silently compared as the same experiment.
- A supported example shows a worse-off cohort beside a favorable aggregate;
  weights/denominators reconcile, missing values stay missing, and empty cohorts
  avoid division by zero. No unsupported interval or benefit is fabricated.
- Unknown presets, invalid seeds/horizons/counts and identity/address fields are
  rejected or excluded before storage/handoff. Inspect requests, URLs, fetched
  snapshots, logs, analytics and browser storage for private-data leakage. Verify
  no selection changes journals, synthesis incumbents, votes or merge eligibility.
- Source fixtures, stale/missing provenance and unsupported metrics exercise all
  three labels. Observed history must never substitute for modeled treatment
  effects. Document source review and model-owner approval separately from tests.
- At a narrow mobile viewport and 200% zoom, verify readable labels, scrollable
  comparison tables and no lost controls. Check labeled inputs, keyboard/focus,
  reset announcement, accessible table headers and text equivalents to charts;
  better/worse must not depend on color. Run on the identified recovered
  production-equivalent source with disposable data before human acceptance.
