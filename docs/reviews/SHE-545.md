# SHE-545 provenance implementation and remaining acceptance

Refs: https://linear.app/shel-bernstein/issue/SHE-545/joytrust-unified-provenance-badge-and-validation-schema

Inspected the repository README, WorkflowScreen, existing provenance disclosure,
demo payload, official metadata lane, policy measurement prototype and motion and
launch policy documentation. GitHub PR search found #101 (compact source chip),
#120 and #123 (native model provenance boundaries). Their process descriptions
are not acceptance evidence; this work extends the existing disclosure.

## Implemented

Shared typed origin statuses cover official source, observed measurement,
user-submitted, synthetic model and demo fiction. Required metadata includes
date (explicit unknown allowed), jurisdiction, confidence, limitations and link
(explicit unavailable allowed). Runtime validation rejects malformed dates,
unsafe links and missing fields. PublicNumericClaim requires provenance at the
type boundary and suppresses numeric content when validation fails.

Existing workflow sample disclosures, feed response totals, official bill cards,
synthetic measurement cards and sample draft text exports use this foundation.
Background identities, unknown editorial check dates and detailed metadata
citations remain intact. Fictional measurement fixtures remain fiction rather
than being upgraded to observed measurements or executed models.

## Validation and outstanding scope

Focused provenance tests: 7 passed, including the existing DOM retry/disclosure
and advisory-vote isolation journey. Typecheck passed. Full bun test: 478 passed,
26 failed; HTTP server startup fails with EADDRINUSE on port 0 in this environment.
Route smoke also fails at that server bind. No checks or assertions were weakened.
The badge adds no animation or custom interaction; native disclosures retain the
existing touch/click behavior. Actual browser keyboard, touch and reduced-motion
acceptance has not been established by these DOM tests.

This is a partial migration, not full acceptance: legacy numeric claims in
synthesis, dashboard, repository voting, comparisons, live rounds and other
exports still need audited adapters and adoption. TypeScript cannot prohibit raw
JSX numbers; the required component boundary applies only to migrated callers.
Observed measurements, resident submissions and executed model receipts must get
metadata from their own typed source records, never from sample background links.
Loading/empty/error coverage must be checked for each remaining migrated view.
Keep the issue open for this work and human acceptance.

## Preserved merge policy

No governance configuration changed. Source defaults remain disabled/dry-run,
quorum 10, 24-hour exposure, current-head approval, fail-closed base/check
allowlists and active kill switch. Advisory browser choices confer no merge
authority. Required main checks are bun test, bun run typecheck and route smoke
test, with human review/approval and a human-published tagged production release.
Live branch protections and production environment configuration were not
verified or modified. No deployment, merge, release, external message or
production-data change was performed.
