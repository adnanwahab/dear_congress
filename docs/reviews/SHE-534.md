## Proposed implementation contract

Start with an in-app digest on `/outcomes`, adjacent to the watchlist, explicitly
opt-in and off by default. State the channel before enrollment: browser-local
in-app preferences cannot promise email delivery or background monitoring.
Weekly is the suggested enabled frequency; offer monthly and off/unsubscribe.
Changing frequency must retain topic choices; unsubscribe stops future generation
without casting a vote or deleting unrelated saved work. Do not silently migrate
existing proposal follows into digest consent. Account/email delivery needs a
separate consent, privacy, retention and delivery design before enabling it.

Use a new typed, read-only event projection, with runtime validation at its source
boundary. Each event needs a stable source namespace and policy identity, kind
(`revision`, `evidence`, `sponsor`, `implementation-result`), immutable before/after
revision references, source URLs and hashes, a dated source event, separate
retrieval time, reviewed topic IDs and review provenance. Display source dates
with their precision/time zone; do not invent midnight timestamps for date-only
records. Revision links must address the exact pair, never a mutable latest view.
Expose a readable text/field comparison with removed and added text labels and
source citations. The initial observation is a baseline, not a change; missing
before data means unavailable comparison, not an empty prior policy.

For metadata history, reuse the existing identity parser, hashes and archived
attempts. Reject cross-bill comparisons, invalid hashes and ambiguous ordering;
do not guess chronology from random attempt filenames. Preserve raw observations
and corrections. Exclude failed attempts, identical normalized content and changes
only to retrieval time/upstream update time from digest events. A new hash alone
does not prove a meaningful change. Sponsor identity/removal and source corrections
need explicit semantics; absence in a partial response is not withdrawal.

New evidence needs a reviewed association to the policy and the actual cited
material. Implementation results additionally need verified implementation
evidence, baseline/current periods, comparable units/populations, source versions
and uncertainty. Before/after association alone must not assert policy causality.
Keep unsupported kinds unavailable until their reviewed adapter exists. The digest
may be honestly empty while coverage is incomplete.

Keep real sourced events, unverified citizen text, seeded fiction and model
simulations in distinct discriminated types. The real digest accepts only reviewed
source events. Do not combine their totals, use demo dates as source dates or
route simulated sponsor milestones into official sponsorship. Preserve all source
repository identities, repository/item-kind isolation and PR head/base binding;
digest subscriptions must not read or mutate ballots, private journals or receipts.

Generate deterministic batches using a frozen preference version and explicit
half-open UTC window. Deduplicate by source identity, event kind and revision pair,
not title. Record an observation cursor separately from the source event date so
late-discovered corrections are not silently lost. Define overlap/retry behavior
before adding delivery: a failed read/send must not advance a successful-delivery
cursor, retries must not duplicate deliveries, and unsubscribe/frequency changes
must be checked again before any queued send. Empty windows must say there are
no qualifying changes within available coverage; never manufacture streaks,
urgency or participation counts.
