# SHE-527 community annotation layers — bounded implementation candidate

Refs: https://linear.app/shel-bernstein/issue/SHE-527/joytogether-topic-level-community-annotation-layers

This change extends TopicHubs with a read-only beta foundation, not a completed
community annotation rollout. Leave the issue open for human acceptance.

## Audit and behavior

Read repository AGENTS.md, readme.md, privacy/security requirements,
launch-merge-policy, citizen-proposals documentation and SHE-357 review.
Inspected TopicHubs, shared topic projection, existing moderation and provenance
boundaries. Read-only GitHub searches for topic annotation and SHE-527 returned
no matching PRs; this is not proof that no overlapping work exists.

Four native checkbox layers cover research questions, lived experience,
corrections and implementation notes. All annotations default off, with no
browser persistence. Origin filtering keeps reviewed references and individual
accounts in separate sections. Each origin displays at most five items to bound
reading load; layer filters can narrow that list. No voting, sorting by popularity,
location inference, animations or automatic scrolling is added.

The existing typed /api/topics/:id response now includes annotations. Its active
registry is intentionally empty: no reviewed, consented annotation sources were
found or invented. Existing journals, comments, sample references and simulations
are not imported. A pure projection contract for future reviewed records requires
explicit public-topic consent, approved moderation, location review and public
provenance; withdrawn, hidden, pending, seeded and simulated records are excluded.
It projects only explicit fields, retaining IDs/topic bindings and removing
internal review metadata. Reviewed references require HTTPS and a review date;
individual accounts cannot carry reference metadata into the public projection.
This contract is not an authenticated verification workflow or a PII detector.

Contributions remain closed. Copy explicitly identifies missing separate consent,
withdrawal, private reporting and moderator operations, warns against submitting
personal details through another comment form, and links current privacy/removal
information. There is no pretend Report action, no write endpoint or public
annotation submission. Turning on the display cannot enable publication.
The hub also clears old data during retry so its loading state is visible.

## Validation and remaining acceptance

- Focused projection and Happy DOM interaction tests: 8 passed, 0 failed.
  Cover topic isolation, pending/hidden/withdrawn/missing consent, fictional and
  simulated provenance, location review, source URLs/review dates, field stripping,
  default-off display, layer toggles, origin filtering and bounded results.
- `bun run typecheck`: passed.
- `bun test`: 477 passed, 26 failed; HTTP server integrations could not bind a
  local port (Bun EADDRINUSE). Full output was captured in /tmp/SHE-527-tests.log.
- `bun run test:routes`: blocked by the same Bun server bind failure.
- `git diff --check`: passed.

Rerun required checks in a server-capable environment. Native keyboard traversal,
screen-reader, touch, narrow viewport and reduced-motion browser validation remain
outstanding. Controls use native labels, fieldsets and at least 44px control rows;
there is no new motion. Happy DOM does not establish native accessibility.

Before real rollout, implement and review authenticated author consent/withdrawal,
durable annotation storage, private abuse reports with rate limits, authenticated
moderation and appeals, source-review identity/audit trails, and location-safe
excerpt review. Test those HTTP and persistence lifecycles, privacy boundaries,
loading/error recovery and current-record removal. The present empty registry
cannot demonstrate real annotation discovery or moderation operations. No source
has been independently verified by this work. Do not infer full acceptance from
this UI or from a draft PR.

## Preserved merge policy

No governance or production data changed. Existing defaults remain disabled,
dry-run, quorum 10, 24-hour exposure, one current-head approval, strict yes
majority, empty fail-closed base/check allowlists and active kill switch. Existing
repository/item isolation, source identities, PR head/base binding, records,
receipts, votes and authentication remain untouched. Required main checks remain
`bun test`, `bun run typecheck` and `route smoke test`; human approval and a human
merge decision remain required. Production requires a human-published tagged
release. Hosted branch protection and runtime overrides were not verified or
changed. No deployment, release, external message, merge or issue transition was
performed. Pre-existing .mini-symphony-evidence files were left untouched.
