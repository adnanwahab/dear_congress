## Reversible staged execution

This opt-in suite does not change application behavior, default tests, CI, data,
or deployments. Roll back by removing the new command and two test files.

1. Install the pinned browser dependency: `cd tests/performance && npm install && npx playwright install chromium`.
2. From root, run `MEMORY_SOAK_SECONDS=120 bun run test:memory` as a harness pilot.
   A pilot is never 30-minute acceptance. Fewer than seven full loops fails the
   sample requirement; increase pilot duration on slower machines.
3. On an idle reference machine, run `bun run test:memory` (1800 seconds minimum,
   finishing the final route loop). Keep the machine awake and foregrounded.
4. Repeat on base main with the same added harness, browser version and hardware,
   then on the candidate. Preserve both JSON artifacts and compare matching-route
   first/last medians for heap, listeners, detached roots, nodes, workers, FPS
   and route-to-main-visible latency. Repeat three times before release review;
   >10% candidate median latency increase or >15% FPS decline versus base blocks
   review pending investigation. Never refresh baselines merely to pass.

The dedicated config starts only the existing disposable local server, refuses
server reuse, strips inherited service credentials and uses disabled/dry-run
merge governance. Context interception permits only GET/HEAD on the exact local
origin; external embeds and mutations are blocked and recorded. No public-site
load test is authorized. A public test would require a separate operator-approved
safe plan with traffic budget, scope, monitoring and stop conditions.

## Metrics and regression ceilings

One Chromium context/page repeatedly explores `/`, `/feed`, `/votes`, `/needs`,
`/synth`, `/outcomes`, using visible native route links where available and direct
navigation otherwise. First visible native disclosure opens/closes; visible More
opens and Escape dismisses it. Each route settles for one second and samples rAF
for one second. CDP forces GC and records heap bytes, DOM nodes, JS listeners and
actual detached DOM roots. Dedicated page-worker count and canvas count are
recorded. Missing CDP metrics fail; no fake zero values substitute for support.

After discarding each route's first visit, compare median of first three and last
three visits (at least six required). Gates allow retained heap growth at most
max(10 MiB,20%), nodes max(100,10%), listeners max(20,10%), detached roots +5,
workers +0, and FPS decline at most 15%. These provisional diagnostic budgets
must be calibrated with preserved base evidence; they are not proof of no leak.
Use raw time series to investigate monotonic growth even below ceilings.

Evidence is attached as `memory-soak.json` under `artifacts/memory/test-results`,
including timestamps, browser/platform, blocked requests, page errors and duration.
A `finally` detaches CDP and closes the context (including its pages/workers);
Playwright owns browser shutdown and the QA server owns disposable DB cleanup.
No persistent production telemetry or participant identity tracing is introduced.

Limitations: rAF measures scheduling rather than GPU presentation; detached roots
are not retained subtree size. Page workers exclude shared workers; service workers
are disabled. Canvas count does not establish WebGL context disposal. Local maps
are unconfigured and external worlds are blocked: real WebGL/embedded-world
coverage remains outstanding, requiring reviewed local fixtures and explicit
open/close interactions. Full-document route loops do not replace repeated
same-document mount/unmount tests. Current suite is a review candidate, not full
acceptance of all resource teardown paths.
