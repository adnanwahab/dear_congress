# SHE-942: county evaluation worker candidate

Refs: https://linear.app/shel-bernstein/issue/SHE-942/cs-l100073-move-bulk-county-evaluation-off-the-ui-thread

## Evidence and scope

Inspected this repository's README, AGENTS.md, county simulation, map, event log,
browser build and launch merge policy. GitHub searches for open county PRs and
all SHE-942 PRs returned no matches. No public-site requests or load tests were run.
The pre-change map synchronously ran countyVote across all 3,144 bundled counties
in React render. Each revision also reconstructed event history on the UI thread.
The current map has automatic and manual plan improvement, rather than weight
sliders. This change addresses those existing controls without inventing a new
scoring model. Existing unrelated before screenshots cover / and /votes; they
are not map performance evidence.

## Candidate implementation and reversible rollout

- `/map?countyWorker=on` explicitly selects the same-origin module worker.
  `/map` and `countyWorker=off` use bounded, yielding main-thread batches.
  Removing the query parameter rolls back worker selection without data changes.
- Both paths use the same deterministic FIPS model, county ordering and plan
  improvement rule. Only IDs and four plan values cross the worker boundary.
- The standalone worker is bundled and served with the existing browser assets;
  it needs no new CSP permissions or external service.
- Progress announces synthetic scenarios evaluated. Results and plan revision
  publish together only after completion. Partial results never redefine counts.
- Cancel, pause, restart and unmount terminate/abandon pending work; late worker
  messages cannot overwrite completed or reset state. Errors, unavailable Worker,
  message errors and a five-second stalled-worker watchdog select the fallback.
- Completed transitions accumulate once per revision and feed the heatmap instead
  of recomputing all historical evaluations in render. Restart clears this log.
- Search, filters, selection and zoom remain enabled during evaluation. This is
  structural availability, not a measured native-browser responsiveness claim.

## Local measurements

Reproduce with `bun scripts/benchmark-county-batch.ts`. Raw five-run results are
in `docs/evidence/SHE-942-batch.json` (Bun 1.4.2, 3,144 synthetic counties).

| Compute mode | Total elapsed range | Event-loop heartbeats while pending |
| --- | --- | --- |
| Before synchronous | 0.93–1.96 ms | 0 |
| After yielding fallback | 56.35–59.66 ms | 50 |
| After bundled worker | 68.24–99.08 ms | 59–85 |

These are local compute measurements, excluding React commits, DOM/layout and
browser input latency. They demonstrate event-loop opportunities and additional
batch/startup overhead, not a faster computation. This small native-runtime
baseline does not reproduce a freeze. Native browser 3,144-path rendering may
still dominate; no scroll/filter latency improvement or long-task budget is
claimed. Progress updates are limited to 1,024-county milestones and completion.

## Validation and remaining acceptance

- `bun run typecheck`: passed.
- Focused tests: 13 passed, 0 failed, covering nine deterministic revisions,
  fallback yielding/cancellation, built worker parity and progress, error fallback,
  stale replies, map counts, event history, motion and production asset budgets.
- `bun test`: 663 passed, 26 failed. Server-dependent tests could not bind a
  local listener (`EADDRINUSE`, port 0). No protections or test requirements were
  relaxed to work around the environment.
- `bun run test:routes`: attempted; blocked by the same local listener failure.

Before enabling worker mode by default, a human should rerun all required checks
in an environment permitting local listeners and measure desktop/mobile native
browser input, filter and scroll latency while running, cancelling, restarting,
pausing and rapidly repeating revisions. Include Worker-disabled and blocked
worker-asset cases. Verify the same-origin worker asset MIME and execution through
the production router. Compare long tasks and interaction latency against main
with the same device and dataset. This candidate does not establish acceptance;
leave SHE-942 open until those checks and human review pass.
