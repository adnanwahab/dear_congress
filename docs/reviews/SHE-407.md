# SHE-407 · Optional haptic feedback

Refs: https://linear.app/shel-bernstein/issue/SHE-407/joytouch-haptic-feedback-for-supported-mobile-interactions

Implementation candidate; human acceptance remains pending. No deployment,
merge, external message, Linear state change or production-data write performed.

## Audit and scope

Read repository instructions, README, motion and accessibility docs and launch
merge policy. GitHub PR search for `haptic OR SHE-407` in this repository returned
no matches. Navigation supplies shared Page actions and the mobile More sheet.
Existing typed View Transitions remain unchanged.

Disabled-by-default Optional haptics stores only an on/off browser preference.
Blocked storage retains it for the page. The two navigation controls synchronize.
The helper detects `navigator.vibrate`, requests a single 8 ms pulse at most once
per 120 ms, catches exceptions/denials and requires a trusted intentional event,
a visible page and no reduced-motion preference. No timer or polling is added.
API presence cannot establish hardware support; browsers may ignore requests.
See the [Vibration API specification](https://www.w3.org/TR/vibration/).

Feedback marks a successful browser-local demo card move (pointer or stage
selection), successful private amendment version save, or manually changed
recorded-model playback tick. Failed saves, unchanged stages, canceled drags,
automated playback, loading and empty states have no feedback path. Vote choices,
political sliders, synthesis scores and progress milestones have none. There is
no publication, server-write, source identity, ballot or PR revision change.

Helper tests cover default off, blocked storage, trusted/untrusted input,
throttling, reduced motion, hidden document, unsupported API and exceptions.
Existing component tests exercise canceled pointer drags, stage selection,
reduced motion, model loading/empty states and private save behavior. Synthetic
DOM tests do not establish actual mobile feedback or trusted keyboard events.

Before acceptance, on supported mobile hardware enable haptics in More; drag and
cancel a demo card, change a stage by keyboard, scrub recorded time manually,
play automatically, and save/fail a private amendment. Verify pulses occur only
for successful intentional actions, are discreet and direction-neutral, and stop
when disabled or reduced motion is enabled. Repeat with an unsupported browser,
blocked storage, empty data and slow loading. Re-run all required checks in an
environment that can bind the isolated test server. No hardware/browser review
was performed here; this candidate is not acceptance evidence.
