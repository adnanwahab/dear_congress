- `main.tsx` mounts App; App dispatches `/needs` and `/synth` into the engine
  workspace and lazy-loads `MapScreen` at `/map`. The stylesheet regression
  exercises actual workspace CSS in light/dark settings at 390/1280px. It passes
  4.5:1 assertions for need, package and policy controls. These are DOM/style
  checks, not native browser paint measurements.
- Current `/map` is a bundled Census county SVG model, not the old twelve-point
  deck.gl view described in the initial walkthrough. `MapScreen` renders county
  paths with a viewBox, search/list fallback and explicit synthetic provenance;
  its integrated DOM tests cover revision denominators and interrupted transitions.
  It explicitly reads no participation API and records no votes. Do not claim
  that a journal submission appears as a point on this map. That original core-loop
  expectation remains unverified/unmet by this model view; redesigning the child
  or adding a new map feature is outside this parent audit.
- `/api/demo` uses `demoPayload`: immutable fictional fixture totals and separately
  calculated `browserCounts`, with only the requesting browser's choices exposed.
  `WorkflowScreen` `/votes` renders distinct unverified/advisory and synthetic
  sections. `journalOrigin` preserves seeded/synthetic flags, IDs, records and
  sources; the shared journal feed selects real submissions separately and only
  collapses simulated display repetitions. No tally reset or migration was run.
- Public write aliases pass through `publicHandler`, bounded input validation,
  signed-cookie identity, origin protection and rate limits in `public-security.ts`.
  Defaults are 60 requests/IP, 30/identity and 3 journal submissions/identity per
  600 seconds. Production requires a persistent cookie secret; client IDs do not
  establish verified identity. Journal UI includes public-post consent. Limits
  are process-local; source inspection does not verify production configuration.
- `Dashboard` mounts `DailyQuestion`, reading `/api/demo` and linking to `/feed`
  and `/votes?proposal=…#advisory-choice`. Date selection uses America/Chicago,
  refreshes at boundaries and reflects saved choices without issuing a write.
  Optional streak/incentives were not added; returning tomorrow remains advisory.
- `pages.ts` supplies social metadata, canonical links and server 404 content;
  the shared navigation includes Documentation. Security headers remain in the
  server response boundary. The production route smoke includes the ordinary
  launch routes, assets, API reads, direct pilot routes and 404s, but could not
  start here. Old-domain redirects, previews through Fly and live headers remain
  release QA, not verified outcomes of this review.
- Direct repository pilot routes retain explicit advisory labels, blocked reasons
  and no automatic merge schedule. The API/worker and GitHub mutation boundary
  use the code-level `PR_AUTO_MERGE_ENABLED=false` lock. Focused tests verify
