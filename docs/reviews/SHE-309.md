## Arithmetic contract to document in the implementation

Current engine uses `round(x, d) = Math.round(x * 10**d) / 10**d`, default
three decimals. For each proposal:

1. Support is `stats.support`; welfare is `round(demand * effectiveness)`;
   fairness is `round(clamp(1 - 2.5 * strongOppose))`; feasibility is
   `round(1 - changeLevel / 6)`; reversibility is the catalog value; evidence is
   `round(clamp(max(catalogEvidence, measuredImpact)))`.
2. Let `W = sum(weights) || 1`. Contributions are `raw[k] * weight[k] / W`.
   Change penalty is `round(lambda * changeLevel / 6)`. Base score is
   `round(sum(contributions) - penalty)`.
3. Eligible incumbents may receive `0.04` stability bonus. Rank is rounded again.
   Selection then applies gates, budget, history and churn policy. Package B uses
   `lambda * 3 + 0.3`; C uses support-only weights and zero penalty.

Currently `scoreExplanation` puts the base-score rounding residual into the
evidence contribution. Thus its contribution sum reproduces the rank to numeric
tolerance, but evidence contribution is not always exactly its published
raw-times-normalized-weight value. The inspector should expose an explicit
rounding adjustment instead of silently attributing it to evidence. Show full
machine-readable inputs, three-decimal displayed scores, and document the
calculation order. Assert exported reconstruction within `1e-9`; summing six
individually rounded display contributions can differ, so explain that display
rounding is applied last. Existing arithmetic tests cover selected items only.

All-zero weights yield zero weighted base with divisor 1; penalties and selection
gates still apply. Zero evidence is distinct from unavailable evidence. Do not
silently convert missing source evidence into a verified score of zero or fabricate
confidence intervals. Any future missing-data convention must be versioned and
preserve the current engine's behavior until explicitly reviewed.

## Proposed small pilot

After prerequisite verification, build a pilot inspector behind an explicit
pilot entry point on `/synth`, using the same pure engine logic as the server.
Do not change official defaults or any governance configuration.

- Publish a privacy-reviewed immutable aggregate snapshot: model/schema version,
  public catalog/evidence provenance, demand and opinion aggregates, effective
  time, outcomes mode, package policy, previous public provision IDs and stability
  state. Exclude journals, quotes, authors, locations, voter IDs, cookies and
  private moderation details. If an aggregate cannot safely be published, mark
  it unavailable and decline exact replay rather than expose private records.
- “Why this plan?” opens a keyboard-operable inspector listing every proposal's
  status, normalized terms, rounding residual, applicable gates and evidence
  limitations. Budget explanations show spend, remaining budget, candidate cost
  and shortfall at the selection step; label budget as binding only when it is.
  Rights exclusions cannot be overridden by sliders.
- Preview from one frozen snapshot; changing controls never updates persistence,
  ballots, metrics for real participation, incumbent history or challenger runs.
  Show added/removed/retained provision IDs, cost changes and changed reasons
  against that same baseline. Return to original assumptions reproduces it.
- For pilot sensitivity, define “first change” as the nearest tested change in
  one control in either direction, keeping other controls and snapshot fixed.
  Use the current 0.05 weight step on [0,1], and an explicitly documented budget
  grid including zero. Recompute every grid point: selection is discontinuous and
  need not be monotonic. Report the direction, delta, normalized effective weights
  and provision diff. Label this “first tested flip at this resolution,” not a
  continuous mathematical minimum. Show “no flip in tested range” when appropriate.
  Rank sensitivity drivers by nearest flip, then provision-change count with a
  stable control-name tie break; distinguish these from largest score contributions.
- Show baseline and rerun package totals and fairness-proxy changes side by side.
  Alternative packages must actually be recomputed under their stated constraint
  changes; do not claim enumeration of all possible packages or global optimality.
  Missing evidence and illustrative scenarios remain explicitly labeled. Model
  confidence never means a verified prediction; this is an advisory demo, not an
  official governmental voting system.
- Proposed share form: `/synth?inspector=1&model=<version>&snapshot=<public-id>`
  plus canonical numeric weights, lambda, budget and package ID. Snapshot ID must
  identify only an approved public aggregate. Allowlist keys, validate finite
  ranges and length, omit arbitrary text, and reject unsupported versions or
  expired snapshots with a clear non-replayable state. Do not fall back silently
  to today's mutable data. URLs encode assumptions and model version, never
  personal inputs; versioned snapshots are required for exact replay.

Pilot walkthrough: a visitor opens a baseline package, reconstructs one selected
and one excluded score from published inputs, identifies the actual exclusion
gate, changes the nearest reported sensitivity control, explains the provision
diff, resets, and opens the share URL in a fresh browser. Observe whether they can
distinguish illustrative assumptions from measured evidence and advisory choices
from binding votes. Recruit a small pilot before scaling; no participant study or
successful real-user flow is claimed in this review.

## Implementation follow-up — bounded arithmetic inspector (2026-11-13)

This section supersedes the analysis-only status for the delivered slice. Reviewed
recovered source at `0268a4c` and existing PR #31 (the merged analysis history;
connector state fields unavailable). No duplicate implementation was found.
The user explicitly authorized implementation after recovery; live release
alignment remains unverified and is not claimed as a prerequisite completed here.

Implemented a native disclosure, “Why this plan?”, inside each `/synth` package.
It reads the existing response without making requests or updating stored history.
`scoreAudit` version `score-arithmetic-v1` exposes every candidate’s base score,
exact normalized terms, divisor, penalty and explicit rounding residual. Selected
rank and its bonus are separate from base arithmetic. Excluded options show
rights/uncosted/deferred/waiting status from the package computation. This is
an arithmetic inspector, not a full selection trace: it does not label a final
budget shortfall as the binding constraint at the earlier selection step.

The arithmetic contract above now applies with one correction: evidence is
exactly raw × weight / divisor. The residual is `roundingAdjustment` and must be
added explicitly. Selected item explanations use the same revised contract.
Selection scores, defaults and rules are unchanged. Raw score inputs remain
support; rounded demand × effectiveness; rounded opposition fairness proxy;
rounded (1 − changeLevel/6); reversibility; rounded clamped maximum of catalog
and measured evidence. Penalty is rounded lambda × changeLevel/6. Base rounding
is applied after subtracting penalty. Package B and C retain their existing
transforms. The audit is versioned arithmetic, not an immutable replay snapshot.
No journal text, author, identity, cookie, location or objection quote is added
to the audit schema. Proposal IDs/titles and aggregate score inputs already
belong to the synthesis response; no share URL is created by this slice.

Walkthrough: open `/synth`, select a package, expand “Why this plan?”, expand
one included and one excluded proposal, and use the exact JSON inputs to sum
contributions minus penalty plus residual. For a selected proposal, add its
selected stability bonus to reproduce selected rank. Read the evidence warning
and compare missing measured impact with an explicit zero. Opening disclosures
never invokes synthesis. Existing Synthesize actions retain existing behavior.
