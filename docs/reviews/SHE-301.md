## Bounded implementation handoff after the gate

Use a shared, allowlisted manual selector with All jurisdictions (clear), United
States, Texas, Harris County and Houston. Prefer exact decision-body filtering
for this first version; explicitly say which scope is shown rather than implying
that selecting Houston establishes residence or includes every overlapping body.
Describe it as a browsing preference, never residency or voting eligibility.

Persist only the optional choice in a new browser-local key, catching storage
read/write failures and retaining a usable in-memory choice. Validate saved and
URL-supplied values if URL support is added. Unsupported values must visibly fall
back to All jurisdictions; do not silently guess a nearby locality. Clear removes
the stored preference. Never request device GPS or require signup.

Share the preference behavior across the three workflow routes and Needs. Use
native labeled selects, a keyboard-operable clear button, readable mobile layout
and a polite live scope/result-count note. Show proposal scope and possible office
as illustrative responsibility, not implemented authority or confirmed sponsorship.
Keep API payloads, source IDs and vote submission keys unchanged. Reset hidden
selection and stale office state when scope changes; preserve saved ballots.

## Authorized implementation follow-up — November 13, 2026

Implemented a bounded browsing slice against recovered main `0268a4c` following
explicit user authorization. PR #39 is merged, changed only this review document,
and is historical analysis, not behavioral acceptance. A connected GitHub search
for open jurisdiction PRs returned no results. No previous PR was imported.

`JurisdictionPicker` provides an optional native labeled select shared by Feed,
Published, Votes and Needs (and the downstream sample stages). Choices are All
jurisdictions, United States, Texas, Harris County and Houston. The new browser
storage key stores only the preference. Invalid saved values visibly fall back
to All; clearing removes the key. Blocked storage retains a working in-memory
choice and warns that an older stored preference may return after reload.
There is no GPS access, signup requirement or residency/eligibility assertion.
The picker wraps controls on narrow screens, uses 44px minimum control heights,
and announces scope and applicable proposal count in a polite status region.

Sample scope is an explicit allowlist by existing proposal ID, not inferred from
City/County labels. Houston has four scenarios, Harris County three, Texas two
and United States two. The regional METRO transit scenario remains available in
All jurisdictions only; its background reference is not a Houston city bill.
Future/unmapped scenarios likewise remain available in All. This mapping is an
illustrative browsing classification, not new evidence of government authority.
Existing agency/publisher scope caveats remain visible through provenance.

Workflow selection and the proposal dropdown now use the filtered set. A hidden
proposal cannot remain the voting target, and no-result states have no vote
buttons. Scope/selection changes reset transient office and success state, without
changing saved ballots. Needs filters policy options and jurisdiction priority
groups using existing exact jurisdiction fields; shared need ranking, journal map,
measured outcomes, allocations and engine/synthesis inputs stay unchanged and the
UI explains that distinction. Citizen proposals and repository PR voting retain
their separate contracts; this slice does not add locality to those records.
