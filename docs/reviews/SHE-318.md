## Proposed bounded prototype and review workflow

Start after SHE-292's actionable vote semantics and SHE-296's source provenance
contract are agreed; recovery is present locally, but production equivalence
still needs maintainer evidence under SHE-281. Suggested 2–4 week sequence:

1. Inventory every public route and shared UI message, including labels, accessible
   names, validation/API error mappings, loading/failure states, consent, privacy,
   deletion, non-binding status, simulated data and election-status wording.
   Include `/`, `/journal`, `/journals`, `/needs`, `/vote`, `/votes`, `/feed`,
   `/proposals/new`, `/proposals/:id`, `/synth`, `/map`, `/published`, `/draft`,
   `/sponsors`, `/outcomes`, `/documentation`, `/docs`, `/api-docs`, `/embed`,
   `/privacy`, repository list/detail routes and 404s. Derive the final matrix from
   the current renderer/router; aliases need coverage too.
2. Prototype typed English/Spanish message catalogs and independent original/plain
   reading controls on isolated fixture-backed proposal, consent and privacy
   flows. Keep route/form components mounted across switches. Do not expose a
   partial Spanish critical journey as complete localization.
3. Have a named human Spanish translator review all critical vote, consent,
   privacy, legal and election-status copy, followed by a civic/legal-domain
   reviewer for meaning. Record message ID, English revision/hash, Spanish
   revision/hash, reviewer, date and disposition in a review manifest. Source
   changes invalidate approval. Agent-generated drafts never count as review.
4. Test with English/Spanish readers, including assistive-technology users; compare
   comprehension of advisory status, publication visibility, withdrawal and source
   meaning. Record misunderstandings and revise before broader route rollout.
   Choose measurable comprehension targets with reviewers before recruiting;
   no invented participant results or approval thresholds are asserted here.

Use stable internal choice values (`support`, `oppose`, `unsure`, `yes`, `no`),
IDs and API payloads; translate display text only. Locale updates must preserve
proposal, selected/recorded choice, unsent text, confirmation state, pending
request and idempotency keys. They must never submit, retry a write, grant consent
or cast a ballot. Preserve existing stale-revision handling: changing language
cannot migrate a ballot to a new head/base. Avoid locale-based component keys,
navigation reloads and automatic translation of user-authored text.

## Plain language, glossary and exact originals

Keep original text available beside a separately labeled explanatory summary.
Use one coherent plain-language level in the first prototype, with Original /
Plain language selection; validate additional levels before adding them. No
reading level changes policy content, counts, eligibility or source status.

Coordinate an additive source-reference model with SHE-296: stable source ID,
publisher/jurisdiction, original URL, exact edition/revision or content hash,
retrieval date, clause/section locator and exact excerpt. Each summary sentence
maps to one or more clause references and a reviewed summary revision. For a
citizen proposal, identify its immutable text sections as citizen-authored;
do not label them enacted law. Keep original source language and distinguish
official translations from community-reviewed translations.

Every summary must offer an actionable link to its exact clause in the recorded
source version, with the original excerpt available for comparison. If a source
changes, approval becomes stale; show the original and mark the summary unavailable
pending review. Missing/ambiguous clauses or unsafe links must not silently fall
back to a generic homepage or a generated citation. No live paraphrase generation
in consent or legal/election-status copy. Original bytes, source identities and
existing proposal records remain intact; derived annotations do not rewrite them.

Create reviewed glossary entries for advisory vote, proposal, jurisdiction,
quorum, consent, revision, simulated support and source freshness. Definitions
must distinguish civic participation from official elections and repository
governance. Provide inline keyboard-operable disclosure, semantic labels,
Escape-to-close and focus return; essential warnings remain visible without it.

## Private preference and optional speech

Default to English without citizenship/location inference. Store an explicitly
chosen locale and reading mode only on-device under dedicated preference keys,
with in-memory fallback when storage is unavailable and a reset control. Keep
them out of URLs, ballot/journal records, analytics, public profiles and request
payloads. Browser-local storage is accessible to same-origin scripts; document
that boundary rather than promising encryption. Coordinate with SHE-319 so a
future private journal does not accidentally sync or publish these preferences.

Speech is optional and user-initiated. Feature-detect browser synthesis and offer
play/pause/resume/stop with proper names and status. Set utterance language to the
displayed text, cancel on navigation/content/locale change, and never auto-read
drafts or public text. Browser/OS voices may use network services: do not promise
offline privacy for all voices. Prefer explicitly local voices and explain any
network processing before opt-in; remain fully usable when no suitable voice is
available. Never substitute speech for semantic screen-reader support.

## Required positive and negative verification

Use a disposable production-build server and synthetic data, with external write
and merge switches disabled. No live votes, publications or production edits.

| Area | Positive evidence required | Negative evidence required |
| --- | --- | --- |
| Catalog/review | All route-critical English/Spanish messages approved against current source; visible text and accessible names agree | Missing keys, stale hashes and unreviewed critical translations cannot be represented as approved |
| Switching | Toggle both directions on the same proposal with a choice, form text, confirmation and pending request; history/reload stay coherent | Network interception records zero extra POST/PUT/PATCH/DELETE; no duplicated retries, changed identity or lost draft |
| Scope/revision | Same item number in different repositories/kinds stays isolated; current revision choice remains bound | Stale PR head/base remains rejected; language change cannot copy a ballot between items or count community votes as verified |
| Sources | Every plain summary opens its recorded clause/version; original remains readable | Missing, changed, ambiguous or unsafe source disables the affected summary; no fabricated official label or citation |
| Privacy | Preferences persist locally, reset, and work with blocked storage | No locale in outgoing bodies/URLs/metrics/public records; no citizenship inference or speech network use without informed opt-in |
| Accessibility | Manual screen-reader checks in English/Spanish, keyboard-only completion, 200% browser zoom and 390px viewport; record browser/AT versions and screenshots | No hidden/truncated consent, horizontal page overflow, focus trap/loss, wrong document language or reliance on hover/color/audio |
| Speech | Start/stop and language change work with a suitable voice | Unsupported synthesis, absent Spanish voice, denied/network voice and navigation fail safely without auto-play |

Run keyboard and visual checks on every public route and state (including errors,
privacy, 404, glossary and long Spanish labels), with focused end-to-end checks
for voting, consent and deletion. Test 390px and 200% zoom separately and together.
Use automated accessibility scans as supplemental evidence, plus manual VoiceOver
and NVDA coverage where available. Neither screenshots nor a passing unit test
alone establish screen-reader or human translation acceptance.
