# SHE-977: demo fixture isolation

Refs: https://linear.app/shel-bernstein/issue/SHE-977/cs-l100088-isolate-demo-fixtures-from-real-anonymous-ballot-datasets

## Audit and change

Read repository instructions, README, launch merge policy, demo catalog/payload,
JSON loading/legacy migration, civic vote writes, privacy projection and existing
integration tests. GitHub PR searches for fixture work and SHE-977 found source
recovery PR #18 and repository voting PR #1, with no SHE-977-specific PR returned.

Fictional response totals live only in `src/engine/demo.ts`, not in a persisted
voter dataset. `/api/demo` now explicitly identifies that catalog as
`civic-demo-fixtures.v1`. Its existing `items`, `browserCounts` and requesting
browser's `votes` remain separate. Counts are illustrative and vary by scenario;
the headline 1,800 is not an ingestion target or verified participation count.
Legacy loading migrates stored legacy choices only; it does not ingest catalog
totals. No migration or relabeling of historical ballots is introduced.

Previously admin reset replaced the database with seed data and selectively
restored proposal sources and moderation records. It could discard uncited
journals, civic ballots, answers, allocations and simulation records. Reset now
only invalidates the code-only fixture cache. It does not save or replace the
database. Initial empty-database seeding remains unchanged. This intentionally
retires destructive sample-synthesis reset semantics.

Regression assertions cover the explicit namespace, fixture/count separation,
absence of stored browser IDs in another anonymous reader's demo response, exact
database bytes surviving authenticated reset, and retained votes after restart.
There is no raw database export added; public demo JSON is the export surface
checked here. Existing journal/public projection rules are unchanged.

24-hour exposure and current-head approval/check requirements. Advisory browser

bindings, ballots, receipts and existing records are unchanged. Required main
