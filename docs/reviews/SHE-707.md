## Proposed implementation contract

1. Establish server-authorized principals and additive durable storage for
   profiles, consent, invitations, connections, blocks, reports and restricted
   audit events. Do not silently claim old browser identities or migrate existing
   journals, votes or drafts. Define account recovery and moderator authority
   before enabling real-person connections.
2. Profiles default undiscoverable. Opt-in exposes only a selected display label,
   selected skills (budget reading, code, laws, source-document reading) and
   coarse availability. Avoid precise schedules, contact information and free-form
   biography in the initial projection. Matching uses explicit skill overlap and
   availability only, with a readable reason and deterministic tie handling.
   Do not query political choices, votes, party labels, journal text/history or
   inferred ideology. Self-described skill is not a verified qualification.
3. Use a connection lifecycle: requested, accepted by both parties, declined,
   cancelled, expired, ended or blocked. Requesting contact never shares an
   artifact. Limit unsolicited requests, expire invitations, prevent duplicate
   pending requests and explain that declining does not require a reason.
   Do not expose direct contact details or add external messaging implicitly.
4. Display Personal, Invite-only and Public as text at every relevant boundary.
   Personal artifacts are owner-only; invite-only requires an explicit named
   recipient grant; public requires separate explicit publication consent.
   A connection is not blanket permission to read artifacts. Preview exact content,
   source revision and audience before each grant. Changing content, recipient,
   scope or revision invalidates consent. Existing public records retain their
   current semantics; no bulk relabelling or destructive migration.
5. Bind each artifact grant to source repository, item kind, stable ID and exact
   revision; include PR head/base when relevant. Authorize every list, detail,
   search, export and stream delivery server-side. Preserve original provenance
   and immutable proposal text; grants never confer ballot, reviewer or merge
   authority. Do not upload browser drafts without deliberate artifact selection.
6. Provide Leave connection, Revoke artifact access, Block and Report. Leaving
   ends future connection access; revocation invalidates future retrieval,
   queued work and streams. Blocking prevents requests in both directions without
   revealing the reporter or block reason. A former participant must retain an
   authorized path to manage their own grants and reports. Explain that copies
   already downloaded cannot be recalled. Ending a connection does not erase
   independent published proposals, source IDs, votes or audit receipts.
7. Reports enter a private queue covering profiles, invitations, connections and
   selected artifacts. Report submission must not itself grant artifact access;
   any evidence attachment requires a separate preview and consent. Define
   scoped moderator access, hide/suspend/restore decisions, reasons, appeal path
   and retention. Existing journal moderation remains isolated.
8. Persist authorized state changes and minimal audit records atomically with
   rollback on save failure and idempotent retry. Record actor, action, target,
   exact revision, permission generation, server timestamp and outcome; avoid
   private document text, politics and journal content in audit/telemetry.
   Expected-version conflicts must not widen access. Recheck consent/session
   generation at commit, reconnect and fanout, including concurrent revoke/share.
9. Retain structured demo/synthetic provenance through every projection. Keep
   fixtures in a visibly separate demo lane with no real contact actions and no
   real-contributor counts. Never manufacture mentors, attendance or messages
   from sample proposals or anonymous round voters.

Coordinate artifact permissions with SHE-709 and restricted event history with
SHE-711 after reviewing their eventual implementation. Neither current draft is
a dependency that already satisfies authorization. These foundations can be
built within this repository; their absence is a delivery gap, not a requirement
for the user to weaken security or authorize an external service.

## Integration plan

- CitizenProposals.tsx: offer skills-based reading help for the exact loaded
  artifact, then a separate scoped sharing review. Do not attach journal source
  text, browser drafts or advisory responses automatically.
- LiveRound.tsx: keep advisory votes intact. Add a mentor entry only through an
  explicit authorized connection; round-code possession never authorizes private
  documents. Do not derive an attendee roster from votes.
- TopicHubs.tsx: expose only opted-in directory fields and separately consented
  public artifacts. Preserve exclusion of human stories lacking curation consent.
  Avoid topic counts or error wording that disclose private connections.

Use a shared labelled connection panel with explicit consent, scope text,
pending/error states and keyboard-operable leave/revoke/block/report controls.
On session or artifact switch clear protected content, cancel pending requests
and ignore late responses. On denial show a useful recovery action without
revealing whether another person's private artifact exists. Reconnect must not
resubmit invitations, messages or sharing actions automatically.
