## Implemented slice

On `/votes?proposal=demo-transit` and the sample transit card on `/published`,
expand **Try a private evidence card**. Access and funding questions correspond
to the two existing unresolved claims. Each optional template asks for an explicit
measure, baseline, minimum threshold, time period and affected riders. Participants
may edit or discard cards independently. No position, party, identity or ideological
category is collected. Cards are separate from all vote handlers and stores.

A participant can manually tie each condition to a later published evidence update
by adding its title, HTTP(S) URL and date/passage/table locator, then choosing
**Link published update privately**. Missing metadata or unsafe URLs announce an
error and retain edits. Credentials, relative URLs and executable schemes are
rejected. Citation edits invalidate the displayed link until explicitly linked
again. Links open with `noopener noreferrer`; nothing is fetched or monitored.
Linking does not verify the source or decide whether the threshold is met.

Private means page memory only: no network submission, browser storage, public
profile, subscription or account persistence. Leaving/reloading loses the cards;
the UI explains this before editing. Anyone viewing the same screen can see them.
This is intentionally a fictional sandbox, not verified civic participation.
No new API or database schema exists. The real comparison API is unchanged.

Only the exact `adnanwahab/dear_congress:fictional-demo:demo-transit:v1` clause
can display these prompts. Changed text, other IDs or other namespaces fail closed.
Removing that editor discards its private state. Comparison tables continue to
reuse the read-only argument map without embedding an editor or extra live regions.
Real citizen proposals and repository PRs/issues have no new condition behavior;
no PR head/base binding, existing ballot, source identity, receipt or record changes.

## Remaining limits and policy

This delivers editable demo templates and manual evidence links only. Persistent
private drafts across visits, authenticated privacy, real proposal integration,
reviewed evidence ingestion, automatic matching/notifications and real participant
usability evaluation are not implemented. A future PR integration must bind exact
repository, item kind, proposal revision and PR head/base; this sandbox supplies
no verified authority. Leave SHE-452 open for human acceptance and scope review.

Preserved configured policy: disabled/dry-run governance defaults, quorum 10,
24-hour exposure, current-head approvals/checks, protected-base requirements and
active-by-default kill switch; advisory browser ballots stay separate from verified
membership/merge ballots. Required main checks remain `bun test`,
`bun run typecheck`, and `route smoke test`, plus at least one human approval.
Remote settings were not verified or changed. No deployment, merge, release,
auto-merge, external message, production write, or voting/auth/check weakening
occurred. Production deployment still requires a human-published tagged release.
