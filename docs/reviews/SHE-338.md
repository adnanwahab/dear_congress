# SHE-338 — Needs ranking motion

Refs: https://linear.app/shel-bernstein/issue/SHE-338/demomotion-animate-the-needs-ranking-when-switching-real-simulated

Implemented the Real voices / Simulated residents / Both ranking switch in
LegacyApp. Audit found the old switch only changed the map: rows always used
real ordering and default demand, with static real/blended rank comparisons.
Rows now sort and display demand for the selected view. A new read-only
`demandSimulated` state summary uses the existing engine with only synthetic
journals and no real priority allocations; real and blended summaries and
persisted data are unchanged. Measured-outcomes policy is preserved.

Switches use the SHE-329 updatePlan helper (View Transitions plus flushSync).
Collision-free encoded need identities give rows and bars separate snapshot
names. Rows glide for 700ms; transformed bar snapshots interpolate their bounds.
Browsers without View Transitions use the existing FLIP row fallback and CSS
scaleX bar transitions. Rank movement compares the immediately previous view,
shows ↑/↓ plus magnitude with a brief emphasis, and remains as text until the
next switch. Selection is retained by need ID and its row scrolls into view
instantly during the committed update. Reduced motion bypasses View Transitions,
FLIP and CSS motion while preserving markers and final values.
