# SHE-968 — launch SLO implementation and remaining acceptance

Refs: https://linear.app/shel-bernstein/issue/SHE-968/cs-l100082-publish-launch-error-latency-and-availability-slos

## Audit

Reviewed repository instructions, readme.md, launch-alerts.md,
launch-merge-policy.md, launch statistics/HTTP, public-security and App API helper.
Baseline: dd8aae5. The existing dashboard counted participation but had no p95,
error-rate or client-save indicator. Paused submissions intentionally returned
503; blindly classifying every 5xx would report false outages.

Connected GitHub searches for repository PRs containing SLO, monitoring, and all
open PRs returned no results during this run. This is search evidence only, not
proof that no overlapping work exists. The public `/version` fetch failed in the
web tool; deployed revision and production monitoring were not verified.

## Delivered scope

See [published definitions and operating limits](../service-slos.md).
Added a separate bounded process-local operational collector and authenticated
admin panel, route-template response observation, explicit paused-write
classification, and content-free best-effort reports from the main civic save
helper. Counts and blocked writes remain visible with thresholds, owner,
10-minute window and explicit unknown/incomplete states. This adds no participation
counts and rewrites no votes, records, receipts, PR head/base or source identities.

Existing configured governance defaults remain disabled/dry-run, quorum 10,
24-hour exposure, current-head approval, fail-closed base/check allowlists and
active kill switch. No live merge policy, protection, release or deployment changed.
Human approval and the three required checks remain necessary; production values
and enforcement were not queried or changed.

## Validation

- Focused SLO, telemetry, admin HTTP and public security tests: 21 passed,
  including window expiry, nearest-rank p95, overflow, intentional vs genuine
  503s, report validation, exception propagation and save preservation.
- `bun run typecheck`: passed after installing locked dependencies.
- `bun test`: 658 passed, 26 failed (684 tests). Listener-dependent tests
  failed at Bun startup with `EADDRINUSE` on port 0.
- `bun run test:routes`: failed at the same socket bind before route assertions.
- A standalone `Bun.serve` on `127.0.0.1:0` reproduced `EADDRINUSE` without
  repository code, establishing an environment restriction. Rerun both required
  checks in a listener-capable environment before review acceptance.
- `git diff --check`: passed. No live browser/layout verification was possible
  against a locally listening server.

## Remaining acceptance

This is a review candidate, not proof of operational readiness. Keep SHE-968 open
until a human verifies acceptance. Live rollout, full-browser verification, owner
and backup shift acceptance, deployed source alignment, external alert delivery
and external availability evidence remain required. The client indicator's
explicit coverage and delivery limitations must be accepted or extended before
claiming universal save monitoring. No external messages or production writes
were sent.
