## Bounded prototype before the 2–3 week build

Propose a 2–3 working-day disposable-data spike, then reassess scope. First prove
one local policy/jurisdiction match and one deliberately unsupported geography,
an editable draft, cancellation, mail-client handoff, private evidence upload,
correction and complete export. Use synthetic correspondence and a local fake
transport only; do not contact an office to test the feature. No sending service
is selected or authorized by this document.

Resolve SHE-282's real/sample decision, SHE-284's private-data contract and operator
authorization before enabling real outreach. Browser cookies for public advisory
participation do not establish an authenticated private mailbox or cross-device
account. Select and review ownership, recovery, retention, encryption, backups
and deletion before accepting personal correspondence. Public journal APIs,
public feeds, SSE, extraction providers and public GitHub comments must never
be reused for private correspondence persistence.

### Matching and source provenance

Separate office identity from incumbent person, recipient endpoint and policy
competence. Store stable jurisdiction/office IDs, geography coverage, policy-type
mapping and rationale, official directory/contact URL, endpoint type, observed
recipient, source revision/hash where available, checkedAt, reviewer, expiry and
last failed check. Review jurisdiction and agency competence independently: a
nearby representative is not necessarily the implementing agency or a sponsor.
Ambiguous matches show choices and uncertainty; unsupported geography has no
recommended recipient. Obtain only the location precision needed for matching;
keep addresses private and out of URLs, logs and public summaries.

Before implementation acceptance, independently review representative source
records against the actual official directories, documenting reviewer/date and
coverage limitations. An official-looking domain alone is insufficient; verify
the agency's own directory and redirect destination. Reject unsafe URL schemes,
lookalike hosts and unreviewed redirects. Do not invent email addresses. Offer
an official contact-form link when no published mailbox exists, and explain that
it is a separate external submission.

Choose a freshness interval with the operator during the spike; do not present
an arbitrary interval as an official guarantee. Missing/expired verification,
changed recipient, failed refresh or contradictory sources visibly flags the
contact for review and blocks a verified Send action until reverified. A failed
check retains last-good evidence without advancing checkedAt. Recheck at final
handoff; directory changes invalidate the reviewed recipient confirmation.

### Human-controlled handoff

Show the exact recipient, official source/check date, subject, editable body,
attachments, sender identity and proposal revision before a deliberate final
confirmation. State that this is an individual citizen request, not a mandate,
verified electorate result or endorsement. Never insert sample tallies as real
support. Edits to any reviewed field invalidate confirmation. Cancel, navigation,
background refresh, retry and scheduled jobs must never send.

Initial scope should favor an explicit “Open reviewed draft in mail app” action.
Use correct URI encoding, bounds and a copy/download fallback; mail-client launch
is a handoff, not proof of sending. The user's mail client supplies the final Send
step. Returning to the site must not mark the message sent. Contact-form handoff
has the same evidence limit. Record an optional user-attested send separately
from independently verifiable receipts.

Any later authenticated service requires separate operator approval and user
consent, minimal provider scopes and server-side authorization. Bind a one-use,
short-lived confirmation to owner, exact recipient, proposal revision, message
hash and attachments; reject changes/replays. Use idempotency and an explicit
unknown-delivery state after ambiguous failures. Reconcile provider evidence
before retry; never automatically resend or schedule follow-ups. A provider's
accepted message is not delivery, readership or office agreement.

### Evidence and status contract

Keep an append-only interaction event history, deriving displayed status from
supported events rather than a free-form stage selector. Each event needs owner,
interaction ID, proposal identity/revision, office/contact snapshot, occurredAt,
recordedAt, evidence reference/hash, evidence type, verification level and actor.
Distinguish user assertions, provider receipts, imported correspondence and
reviewed official public records. Hashes establish content consistency, not truth
or sender authenticity. Treat uploaded mail headers and screenshots as untrusted
claims until reviewed; automatic acknowledgments must remain distinguishable.

| Display state | Minimum supporting evidence | Must not imply |
| --- | --- | --- |
| Drafted | Saved reviewed-text revision | Contact occurred |
| Handoff pending | Explicit mail/form handoff event | Sent or delivered |
| Sent | Dated user attestation labeled as such, or authenticated provider receipt | Read, endorsed or replied |
| Acknowledged | Linked receipt/acknowledgment with date and provenance | Substantive reply or support |
| Replied | Linked substantive reply, source/date and review classification | Sponsorship, agreement or introduction |
| Introduced | Reviewed official measure/action citation linked to the relevant proposal revision | Outreach caused introduction or policy succeeded |
| Stalled | Dated explicit reason or elapsed follow-up window and last evidenced event | Office rejection or proof a message was read |

Retain last evidenced milestone when showing stalled; this is a follow-up
condition, not a replacement for history. Corrections append a reason, author,
time and superseded-event link; invalidate unsupported derived states while
retaining the correction trail. Duplicate, late and out-of-order evidence must
not fabricate progress. A reply can arrive without a known sending receipt;
show the gap instead of inventing a sent event. Keep outreach milestones distinct
from SHE-314 legislative provenance and SHE-315 policy-effect measurements.

### Privacy, publication and export

Default all bodies, headers, addresses, attachments, receipts and interaction
history to private. Enforce owner checks server-side on read, write, download,
export and evidence URLs. Signed anonymous IDs or knowledge of an interaction ID
alone must not bypass the selected private ownership contract. Use protected
attachments, bounded file types/sizes and safe rendering; never execute imported
HTML. Exclude correspondence from analytics, error bodies and public caches.

Public summary publication is a separate, explicit opt-in action previewing the
exact redacted text and evidence excerpt. Publication consent is bound to that
revision; a new reply or correction is private until separately reviewed. Warn
about third-party personal details; public-office correspondence may still
contain private information. Public summaries do not expose raw private evidence
links. Revocation removes the active public projection without promising recall
of outside copies. Define owner deletion and backup expiry with the operator;
retain only justified minimal audit metadata and explain any retention limits.

Offer versioned JSON and readable history/CSV plus authorized evidence files,
including timestamps/timezones, status provenance, source snapshots, consent and
correction log. Warn that private exports contain personal data. Ensure CSV
formula escaping, safe filenames and attachment manifests. Round-trip/reconcile
export against stored events; do not silently omit withdrawn or corrected events.
Do not export unrelated voters, journals, credentials or provider tokens.
