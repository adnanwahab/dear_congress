## Audit and implementation

Read repository instructions, readme.md, bill-catalog documentation, accessibility
acceptance guidance and launch merge policy before changing the client. The
baseline has read-only catalog drafts, simulated workflow proposals and a timed
demo tour; no budget shock exercise existed. GitHub PR search on November 14,
2026 found no SHE-663 PR. Related separate candidates include SHE-620 (#231),
SHE-665 (#276) and SHE-668 (#274); these are not acceptance evidence for this task.
The reference live URL could not be retrieved with the web tool; no visual parity
is claimed and no live service was modified.

BudgetShock is a shared opt-in component in BillCatalog, WorkflowScreen and the
active DemoTour. Starting from the tour pauses its timer; tour shortcuts ignore
keyboard events inside the exercise so native selects and buttons work normally.
All scenes retain the fictional/hypothetical notice and source chip. The fixture
uses invented tokens rather than catalog costs, proposal identities or live data.
It offers editable allocations, protected service minimums, a deliberate invalid
example and two workable responses: split deferrals or a one-time reserve. The
receipt shows baseline/current amounts, delayed repairs/expansion, reserve use
and constraint violations. Completion has no points, preferred ideology or reward.

Skip/Exit discard state and return focus to the launcher. Restart restores the
baseline. Complete text is available even before opting in. State stays in the
mounted React component; there are no storage calls, network requests or changes
to advisory choices, revision identities, server records, votes or receipts.
Theme variables and the existing chip class are reused. Reverting the new
component/styles/tests and its three integration points requires no data migration.
