# SHE-563 — experience-quality implementation review

Refs: https://linear.app/shel-bernstein/issue/SHE-563/joyquality-privacy-safe-delight-metrics-for-interactive-civic-journeys

## Audit and implementation

Read this repository's AGENTS.md, readme.md, motion and launch governance docs.
Audited LaunchStats, the protected stats HTTP layer, main browser entrypoint,
cross-document/in-page motion, guided demo, synthesis comparison and law behavior
model paths. GitHub search found merged launch instrumentation PR
[#12](https://github.com/adnanwahab/dear_congress/pull/12), inspected with exact
main/head metadata. No SHE-563 PR was found; the open-PR listing also contains
parallel Joy work, which was not imported as another product's requirements.
The supplied live reference could not be retrieved by the web reader; no live
instrumentation or source parity is claimed.

Implementation extends the existing separate launch SQLite store and ADMIN_TOKEN
protected `/admin/stats`. It does not create a second product analytics system.
The old page-view sender is not wired in the main entrypoint and stays inactive.
The new fixed vocabulary covers route readiness/failure/abandonment, demo
start/completion/explicit exit, comparison opening, model completion/failure/recovery
and actual motion fallback use. No raw content, identities, opinion, geographic
location, error messages, receipt fields, source IDs or revision IDs are accepted.

The shared shell supplies opt-in and opt-out, with blocked storage failing closed
and DNT/GPC taking priority. No new requests occur before affirmative consent.
Only daily counts by coarse capability and latency bucket persist, for 30 UTC
dates, with automatic cleanup. The dashboard presents failure points and task
outcomes, with explicit bounce-proxy and inference limits. Full details and backup
retention requirements are in [experience-quality.md](../experience-quality.md).

## Acceptance and preserved policy

This is an implementation review candidate, not verified launch acceptance.
Human review must rerun the full suite, typecheck and route smoke test, verify
consent behavior and capability fallbacks in real browsers, inspect the protected
dashboard with synthetic fixtures, and confirm backup aging before exposure.
Unlinked aggregate counts cannot prove understanding or supply an exact unique
visitor bounce/conversion rate; explicit demo exits and pre-readiness abandonment
are reported as limited bounce proxies. User research is still needed to establish
whether the interactions improve understanding.

No deployments, merges, releases, external messages, live fixture submissions,
production data writes or Linear state changes were performed. Existing source
identities, repository/item kinds, vote/PR revision binding, civic records and
receipts remain unchanged. Governance defaults remain disabled/dry-run, quorum 10,
24-hour exposure, current-head approval/checks, fail-closed allowlists and active
kill switch. Advisory browser votes remain separate from verified merge authority.
Live branch protection/environment settings were not changed or verified. Required
main checks remain `bun test`, `bun run typecheck`, `route smoke test` and at least
one human approval, with production gated by a human-published tagged release.
See [launch-merge-policy.md](../launch-merge-policy.md). Keep this Linear issue
open until a human verifies acceptance.
