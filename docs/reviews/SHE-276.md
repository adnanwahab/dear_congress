## Findings and resulting changes

All API handlers now receive a server-issued signed cookie identity through one
boundary; client `x-voter-id` cannot select it. Production requires a persistent
32-character-or-longer secret. Cookies are HttpOnly, Secure, SameSite=Lax. The
existing handlers' header interface is an internal adapter only. API responses are
no-store, and the debug response no longer reflects cookies or arbitrary headers.
Browser clients no longer generate/send IDs. Test API clients use cookie jars.

The vote API, all three journal aliases, answer API, citizen proposal writes and
label editing use shared per-IP/per-ID attempt budgets. Journal aliases also share
a three-attempt/ten-minute cooldown. Invalid attempts consume budget; cookie
rotation does not bypass the IP limit, and changing IP does not bypass an existing
signed ID's limit. Fixed-window limits are configurable positive integers. 429
includes Retry-After seconds and retry guidance. A bounded bucket map fails closed
at capacity. IP keys are HMACs, not plaintext addresses.

Trusted Fly mode reads only Fly-Client-IP. Other modes use Bun's socket peer.
X-Forwarded-For and X-Real-IP never select a key. The listener binds IPv4 to avoid
private IPv6 proxy bypass. This assumes the listener is reachable only through
Fly HTTP proxy; deployers must preserve that boundary. Fly proxy trust references:
https://fly.io/docs/networking/services/ and
https://community.fly.io/t/security-guidance-verifying-fly-proxy-socket-peers-and-forwarded-headers/28891.

Validation precedes writes/extraction: JSON objects only, 64 KiB bodies even without
a Content-Length, nonblank journal text, 10,000 raw characters maximum, bounded
author and label shapes; valid proposal IDs, exact stance enums, importance,
boolean compromise/goal values, bounded free text, valid need IDs and allocations.
All vote fields are checked before any mutation. Existing proposal-keyed upsert
semantics replace an earlier stance. Citizen advisory choice replacement is also
tested through the cookie boundary. Journal HTML remains React text, with an
escaping test on the actual journal view. No raw HTML rendering was added.

Public label edits and PATCH journal corrections return 403 until ownership is
implemented; the unprotected edit helper is unreachable through HTTP. These paths
are throttled too. Journal publication can be paused by setting
PUBLIC_SUBMISSIONS_ENABLED=0 and restarting. The optional website honeypot is
validated; the shared journal cooldown is the active minimum spam control.

Beside Publish publicly, the form explains publication, advises against addresses
and contact details, links to an entry-ID-only removal request, and requires an
unchecked public-consent checkbox (including keyboard submission). Errors such as
429 display in the form and clear the busy state. The journal sends only its
explicit text/author/labels; it never reads private draft or vision-board storage.
No vision-board implementation exists here. Existing proposal drafts remain local
until their separate explicit publication action.

The votes UI footer states: “Anonymous, non-binding advisory participation; one
vote per browser ID, not one verified person.” It does not claim representative
polling or government authority. Publishing logs no longer include journal results,
text previews, IPs or referring URLs. Extraction logs contain counts/provider only;
server error logs omit messages/stacks that could contain user input.

## Operational limits and rollout requirements

- Existing data/source IDs are retained. Old client-selected IDs are not adopted
  into signed cookies: automatic adoption would preserve impersonation. A browser
  may initially lose access to its previous choice. Legacy rows remain stored;
  coordinate any reconciliation with SHE-271 to avoid silently double-counting
  legacy/new identities. No sample/real tally migration or deletion was performed.
- The limiter is in memory and resets on restart. This JSON-file app needs a single
  process/writer/machine. Multiple Fly machines require shared storage-backed
  atomic counters (e.g. Redis script/transaction with expiry) and transactional
  application storage before rollout. Machine count was not verified or changed.
- HSTS, nosniff, no-referrer and CSP are on API responses. The matching Fly header
  configuration covers HTML/assets in production. Local direct Bun HTML does not
  receive Fly response headers. CSP source/configuration tests cover CARTO root
  and subdomains, MapLibre blob workers, Bugsnag reporting, and same-origin framing;
  actual browser network/worker/report delivery has not been tested here. Arbitrary
  custom map hosts need explicit policy review. Wildcard embedding is removed.
- Secure cookie API clients must preserve cookies over HTTPS. Cross-origin browser
  journal publishers must use a same-origin publication flow. Development secrets
  are ephemeral; production must configure a persistent secret before startup.
- Other prototype mutation endpoints (reset/synthesis/design) are outside this
  write-hardening scope and still require a broader launch authorization review.

## Merge policy preserved

votes do not authorize merges. Read-only evidence from PR #1's branch policy:
quorum 10, minimum exposure 24 hours, at least one current-head approval,
America/Chicago 9 a.m. batches, maximum recovery six hours, enabled=false,
dryRun=true, empty allowedBases/requiredChecks fail closed. Eligibility additionally
requires strict yes majority, known protected base, clean mergeability, successful
current-head checks, no blocking/requested reviews and maintainer approval for
sensitive changes. Issues cannot merge; non-HBL merge scopes stay disabled.
No one-vote quorum or relaxed checks/auth were introduced. Remote branch protection
could not be verified (`gh api` network access failed). Existing main/master push
Fly deployment workflow is unchanged; fly.toml still targets dear-congress. Its
only changes are candidate proxy/header configuration; nothing was deployed.
