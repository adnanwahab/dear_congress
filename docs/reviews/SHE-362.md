# SHE-362 — accessibility evidence gate

Refs: https://linear.app/shel-bernstein/issue/SHE-362/qualityaccessibility-gate-civic-journeys-on-automated-and-manual

Implementation candidate on 2026-11-13; acceptance remains pending. Keep Linear
open. A draft PR or successful process is not acceptance evidence.

## Audit and scope

Read repository AGENTS.md, readme.md, source-recovery.md, launch-merge-policy.md,
and the SHE-318 and SHE-340 reviews. Inspected route dispatch, shared shell,
loading/error states, workflow search and advisory mutation feedback, county map
and CI. Initial GitHub repository PR search for accessibility returned no matches.
The open inventory then returned #108 (SHE-354 optional maps) and #109 (SHE-353
production parity). Inspected #108's full diff: it independently improves embedded
map failure handling and jurisdiction alternatives. It is a draft against main,
not an accepted dependency, and its changes were not copied into this work.

Public screens already had native mains, search names/count statuses, a native
phone dialog, advisory mutation statuses and searchable county text alternatives.
Missing shared skip navigation and stable main targets were concrete shell gaps.
This change adds the first-tab skip control, focusable stable main on the thirteen
requested routes and their loading states, a main/error heading for legacy load
failure, legacy top headings and focus after legacy history navigation. Global
focus-visible styling includes forced colors. County commitment progress bars
receive individual names; the filtered county count becomes a polite status.
Existing source identity, proposal selection and advisory save logic are retained.

The separate Playwright/axe tooling runs a production server against disposable
state with credentials stripped, external merge disabled and no existing listener
reuse. Five route profiles and a keyboard advisory journey emit JSON, HTML,
route screenshots and failure traces to a portable CI artifact. Critical/serious
axe violations fail with no exclusions or exception allowlist. Existing three CI
checks remain unchanged; a separate accessibility job is added. Browser tests use
`.pw.ts` so Bun's unit runner does not mistakenly execute Playwright tests.

See [reproduction and manual checklist](../accessibility-acceptance.md). Exact
browser tooling versions are pinned in its separate package, but transitive
resolution is not locked yet. The app lockfile is unchanged. The 720px profile
models 200% desktop reflow; actual browser 200% zoom remains manual verification.

- Browser dependency installation: blocked. Bun add reported tempdir EPERM;
  npm reported ENOTFOUND registry.npmjs.org. No local Playwright run, axe pass,
  route screenshots or native keyboard result is claimed.
- `git diff --check`: passed.

The CI browser gate is unverified until it runs in an environment with registry,
browser and listener access. Fix any reported route/state violations before
acceptance. This work does not claim complete accessible naming of every dense
chart/control, comprehensive heading repair, configured-map fallback coverage,
all form/error states, or native zoom compliance. Extend browser journeys to cover
network failure/retry, dialog focus return and journal validation; the manual
checklist includes those states now. No human exception has been approved.

Manual screen-reader review has not been performed. At least one complete
Feed → evidence → advisory choice → confirmation → return journey must receive
a dated reviewer/browser/AT record against the current revision, along with the
all-route/phone/zoom checks. Automated audits supply evidence, not a guarantee of
full WCAG conformance. Do not treat this implementation candidate as satisfaction
of all SHE-362 acceptance criteria.
