## Proposed implementation contract

This describes future work, not existing endpoints or acceptance evidence.

1. Bind each round to repository, source kind, immutable source ID/revision and
   exact published rules. Retain the sample namespace and all existing choices.
   Any future citizen-proposal adapter must preserve its independent proposal text,
   journal lineage, ballots and objection history. PR head/base and repository
   voting remain entirely outside this advisory round contract.
2. Define host/member/outsider capabilities server-side. Default new private
   artifacts to Personal; Public and Invite-only need deliberate audience review.
   Invitations must expire and be revocable, and must not authorize unrelated
   artifacts. Check scope/grant version on reads, writes, lists, QR access,
   exports, source previews and every SSE emission. Disconnect revoked streams
   and remove private content from client state. Do not retrofit existing public
   rounds into a private scope or rewrite historical choices implicitly.
3. Give queue entries, questions and pinned sources separate artifact IDs and
   sharing decisions. Preview exact content, scope, audience and retention before
   sharing; edits invalidate consent. Hosts cannot publish another participant's
   private text merely by pinning/approving it. Reuse #215's moderation contract
   after its current head is reviewed, preserving held-question privacy.
4. Publish queue ordering/pass rules, moderation/appeal path, allowed choices,
   change/withdrawal behavior, pause behavior, closing/expiry and cookie limits
   before participation. Keep all advisory ballot options and aggregate counts
   visible; moderation cannot secretly discard a disfavored ballot. Never convert
   question upvotes, queue entries or connected browsers into verified turnout.
5. Use expected round/artifact/grant versions for mutations; reject stale or
   denied operations before write/fanout. Make retries idempotent and reconcile
   uncertain outcomes using the same operation ID. No automatic privileged
   replay after reconnect. End is terminal; pause blocks new contributions while
   retaining safe leave, revoke and report paths. Closing does not erase ballots.
6. Commit successful changes with minimal audit events: actor role/opaque ID,
   action, artifact/source revision, scope transition, time, operation ID and
   outcome. Failed persistence cannot publish a success or partial state. Keep
   pending text, reporter identity, invitations and credentials out of public
   audit projections and logs. Explain audit retention separately from content
   withdrawal and that revocation cannot recall downloaded copies.
7. In LiveRound, show scope, current rules, host capability, freshness, queue,
   approved question wall, pinned source, pause/close and participant exit/report
   controls. CitizenProposals and TopicHubs supply explicit source-bound entry
   links and per-artifact sharing, without automatic secondary publication.
   Keep native labeled controls, stable focus and text status announcements;
   avoid announcing every heartbeat/tally as an intrusive live-region update.

## Required verification before acceptance

Use disposable data and at least host, invited member and outsider sessions.

| Area | Required positive and negative evidence |
| --- | --- |
| Permissions/privacy | Every scope and role; guessed codes/artifact IDs; copied presenter URLs; expired invitations; lost cookies; denied reads/writes/exports; sentinels absent from public payloads, URLs, logs and SSE; anonymous author linkage never disclosed. |
| Leaving/revocation | Voluntary queue withdrawal, leaving a room and withdrawing an artifact are distinct; revoke invalidates open streams and future reads; already-downloaded-copy limits are visible; no unrelated record/ballot deletion. |
| Stale sessions | Revoke/change scope/pause/close between preview and mutation; delayed fetch/mutation after round switch; network loss, reconnect and restart; no silent replay or success on conflict; immutable source revision mismatch fails closed. |
| Moderation and audit | Pending/rejected question invisible to outsiders; report private and idempotent; host-only decisions with reasons; no hidden ballot changes; persistence failure rollback; concurrent transitions and retry produce one consistent event history. |
| Isolation/provenance | Same source ID across kinds/repositories cannot alias; seeded/synthetic content stays labeled; zero initial real responses; existing votes, proposal text, journal links, PR head/base bindings, records and receipts remain unchanged. |
| Accessibility/mobile | Native keyboard and screen reader through join, queue, question review, pin, pause, close, leave/revoke/report; denied/error focus recovery; 390px width, long content, 200% zoom, reduced motion and forced colors; scope discernible without color. |
