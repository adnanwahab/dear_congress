## Safe local experiment and before/after measurements

The appendix is the exact final probe. It intercepts `Bun.serve` and invokes the
real wrapped route handlers without opening a listener or making HTTP requests.
It removes inherited service configuration, uses fresh temporary JSON and SQLite
paths, disables governance merges, and deletes temporary stores in `finally`.
The contact hold path and explicit `inference: none` avoid LLM calls. No public URL
is a load target. Local-only rate limits are raised to 10,000 to isolate backlog
behavior; these numbers are not recommended production settings.

Each of three fresh-process runs submitted 500 contact-like synthetic excerpts in
20 batches of 25, then one publishable synthetic excerpt, then 100 reports in four
batches of 25 against that excerpt. Requests have no cookie, so each receives a
fresh server-issued anonymous test identity; this deliberately models multiple
reporters, not repeat-report deduplication. Finally an authenticated same-origin
hide removes public visibility. Every run passed 611 assertions: 500 holds, 100
accepted report requests, publication/report/takedown checks, retained source and
record counts, and file equality after module reload. Reload is not a crash test.

Times include handler completion through awaited save; percentiles use sorted
per-request durations (p95 indices 474/94 for 500/100 samples). These are local
request latency and queue-drain proxies, not human review latency or isolated disk
queue-wait instrumentation. Other repository checks ran during some samples;
variation must not be interpreted as a performance regression or improvement.

In all runs admin HTML grew from **433 bytes** to **348,323 bytes** after holds,
then **358,247 bytes** after reports. Compact persisted JSON was 246,516 bytes.
Public visibility was true before and after the report burst and false after hide.
All 501 originals, 100 reports and one hide decision survived module reload;
500 records remained pending. Hide is a retained removal from public projections,
not destructive deletion. The request succeeded only after the save completed.

This establishes local reliability for the exercised workload, and reproduces the
unsafe-publication gap. It does not establish a safe maximum throughput, sustained
capacity, operator review time, browser rendering speed, fleet behavior, crash or
write-failure recovery, or deployed source parity. The empty-to-loaded comparison
is before/after load, not before/after an implementation fix. No such fix exists
in this analysis candidate.

## Proposed policy and reversible stages — not activated

1. **Local implementation first.** Add explicit report state (`open`/`resolved`),
   immutable report IDs and risk classification with reasoned human resolution.
   Migrate existing reports conservatively to open/unreviewed without losing
   originals. Treat untriaged potential high-risk reports as a publication hold;
   never infer safety from report volume, elapsed time or absence of more reports.
   Bind approval to the current report set/revision and recheck inside the same
   serialized mutation as publication; a newly arriving unresolved risk must win.
   Store report and hold atomically before acknowledging. Preserve original
   source/ownership and do not convert moderation actions into ballots or proposals.
2. **Bound work, retain evidence.** Proposed pilot limits: 500 unresolved journal
   items, 100 in-flight durable mutations, admin pages of at most 50 items and
   bounded per-entry report pages. These are initial test limits, not measured
   safe capacities. Reject new publication admission before mutation with an
   actionable 503/Retry-After when full; do not discard acknowledged records.
   Reserve capacity for reports and authenticated takedown. At report-storage
   saturation, fail closed on affected publication and pause intake rather than
   silently losing safety reports. A bounded page alone does not bound backlog.
   Index/group reports once per view; separate pending/urgent work from retained
   history. Expose oldest unresolved age and queue depth privately.
3. **Isolated staging.** Use disposable synthetic data and outbound-network denial;
   replay 25/100/500/1,000-item bursts at concurrency 1/10/25 with default rate
   limits separately from the backlog experiment. Measure p50/p95/p99 for ingest,
   report, hide, queue wait, page size and oldest-review age. Inject slow/full disk,
   save failure, restart and concurrent approve/report races. Proposed gates:
   zero public unresolved high-risk excerpts, zero lost acknowledged records,
   no vote/receipt or source-identity changes, bounded configured depths, admin
   page ≤256 KB and takedown request p95 ≤1 second on staging hardware. Require
   measured review staffing before setting a human-review SLA; this audit has none.
4. **Human-controlled pilot only after gates.** A maintainer selects the reviewed
   revision and tagged release, checks source parity and all required checks,
   confirms a staffed urgent queue, then explicitly decides whether to release.
   Start with a limited cohort and unchanged auth/rate limits. Any unresolved
   high-risk public exposure, evidence loss, queue-cap breach or latency gate
   failure stops expansion. This document authorizes no deployment or live load.
5. **Rollback without publication leakage.** Pause new journals using the existing
   switch and restart under operator control; keep reports and takedowns staffed.
   Hide already exposed high-risk excerpts explicitly, since the switch does not
   retract them. Retain holds and audit data during rollback; an older reader must
   understand the hold representation and fail closed. Do not roll back to a build
   that republishes held records. Verify compatibility on disposable restores;
   never reset production or delete reports to make a queue appear healthy.

Acceptance remains open until the bounded queue and unresolved-risk gate are
implemented, race/failure tested, and human-reviewed. Local hide success alone
cannot satisfy the publication gate. No merge, deployment, external message,
production mutation or Linear status change was performed.
