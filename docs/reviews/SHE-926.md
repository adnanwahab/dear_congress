## Resulting contract

Only exact GET paths `/api/legislation`, `/api/audit-samples` (index), and the new
`/api/sample-proposals` bypass identity issuance into the public-read wrapper.
All three producers ignore request identity, origin and query parameters. No CORS
permission is added. Weak SHA-256 representation ETags support lists, wildcard and
weak/strong `If-None-Match` comparison, returning empty 304s with cache metadata.
`Vary: Accept-Encoding` accounts for HTTP compression; cookie and authorization
are intentionally absent because these projections never read either field.
No credentials or owner data are copied into cache keys or values.

The new sample API returns existing sample IDs and text/background references,
explicit fictional kind and unavailable participation. It omits fictional
support/oppose/unsure tallies and browser choices. It does not replace `/api/demo`
in the current feed UI: this task does not claim to eliminate that personal read.
The existing feed's legislation read benefits when short mode is deliberately
selected. Static editorial catalogs, official metadata, citizen proposals and
repository ballots retain distinct identities and stores.

`PUBLIC_READ_CACHE_MODE=validate` is the default: public/no-cache and content
validation on every request, reducing bytes without hiding source failures.
`short` opts into a hard 15-second process/shared/browser lifetime with
must-revalidate, coalescing concurrent misses, and Age on cached responses.
There are at most three process entries, each at most 1 MiB; oversized bodies
are returned no-store. Errors and Set-Cookie responses are no-store and evict the
entry. Expired data is never served on failure. No stale-while-revalidate or
stale-if-error extension is enabled. Request no-cache forces refresh; request
no-store additionally skips retention. Unknown mode values fail startup.

All other API routes keep their original security/auth/identity boundaries and
no-store behavior. Account HTML now explicitly uses private/no-store, including
trailing slash and HEAD through the existing page handler. Ballots, journal-owner
reads, personalized state/demo, citizen choices and authentication never enter this
cache. No votes, existing journals, receipts, PR head/base bindings or persistence
formats were changed.

## Local before/after measurement

Reproduce with `bun scripts/measure-public-read-cache.ts`. It creates and deletes
a disposable synthetic single-bill archive, mocks the importer fetch locally,
and runs 100 serial in-process reads per mode. No listener, public site, API key
or real records are used. Raw result: `docs/evidence/she-926-cache-measurement.json`.

| Mode | Archive reads | Body bytes | 304s | Failures | Median ms | p95 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Prior no-store wrapper | 100 | 52,300 | 0 | 0 | 0.060 | 0.099 |
| Default validate | 100 | 523 | 99 | 0 | 0.056 | 0.079 |
| Opt-in short | 1 | 523 | 99 | 0 | 0.001 | 0.003 |

The warm filesystem, tiny fixture, single process, fixed mode order and sub-15s
run limit interpretation. Measurements exclude network, TLS, compression, browser
and CDN behavior. They demonstrate local read/byte reduction, not production
speed, capacity, reliability improvement or load-test acceptance. TTL expiry and
error handling are separately covered with a controlled clock.

## Reversible staged rollout

1. Review this revision and pass all required checks in a socket-capable runner.
   Keep default validate; verify public reads return ETag/304 without Set-Cookie
   and sensitive reads still return no-store. No automated production rollout is
   authorized by this document.
2. After a human-published validated tagged release, an operator may explicitly
   select short mode in a controlled rollout. Observe normal request/error and
   latency metrics without new identity tracing or load generation. Verify Age,
   304 metadata, archive update/error visibility within 15 seconds and no private
   route becoming shared-cacheable at the actual proxy. Record deployment-specific
   before/after values before claiming production acceptance.
3. Revert to validate to remove the process TTL, or off plus restart to restore
   the original wrapper. Existing downstream entries can survive for the remaining
   15 seconds; do not promise immediate remote purge. A code revert requires no
   database migration or resident-data reset. Preserve all data during rollback.

Short mode can delay visibility of archive updates/corruption or refresh failure
by up to 15 seconds. Metadata check times/source hashes still mean what they meant
before; cached delivery is not fresh source verification or current legal status.
No offline retention policy, browser persistent cache feature, fictional turnout,
verified voter claim, identity tracing or consent change is introduced.
