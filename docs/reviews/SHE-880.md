## Acceptance gaps and completion path

| Requirement | Evidence / remaining work |
| --- | --- |
| Three actual official records | Unmet. Select three specific measures and successfully fetch their original detail responses using an authorized key in a network-enabled environment. Do not publish synthetic test fixtures as official records. |
| Government ID and jurisdiction | Existing identity binds Congress, bill type and number; source URL binds the same measure. UI jurisdiction is US. Validate each selected identity against its primary source. |
| Action date, retrievedAt and source URL | Parser requires an action date and builds a Congress.gov bill URL. Existing `checkedAt` is metadata-fetch attempt start time, displayed as metadata retrieved time; successful attempts alone supply that timestamp. There is no explicit `retrievedAt` field. Decide and document the schema mapping before claiming exact field acceptance. |
| Read-only metadata, no inferred enacted/effective status | Existing lane quotes the latest reported action and says current legal status is unverified. No legal-status or effective-date mapping exists. Preserve that boundary even if action text mentions a public law. |
| Failed fetch produces unavailable state | With no prior success, failed attempts yield no records and the UI shows the empty lane. After success, retained metadata is marked refresh failed without advancing last-good time. Corrupt archives produce HTTP 503 and an unavailable alert. A first-fetch failure is not distinguished from never imported in the API; review whether explicit per-record unavailable entries are required. |

Use a new disposable local `LEGISLATION_PATH`, run the existing importer for each
reviewed identity, then read back through `readBills` and the read-only API.
Verify identity, original URL, action date, retrieval time, immutable raw hash,
and jurisdiction for each. Exercise an unavailable fetch in that disposable
archive and inspect both first-failure and retained-record UI. Keep original
responses and retrieval provenance; do not transcribe web summaries into fake API
responses. Complete source, safety and editorial review before any release.
Full text, current legal status, effective dates, measurements and modeled futures
remain distinct and unverified by this metadata-only lane. Participation remains
non-binding and advisory.

## November 17 implementation follow-up

Audited the existing source and related GitHub PRs again before editing. Search
returned importer PRs #26 and #68, provenance PR #44, and the adjacent data-lane
switch PR [#430](https://github.com/adnanwahab/dear_congress/pull/430). No SHE-880
PR was returned. The switch remains outside this change. Existing untracked
before-page evidence was preserved; no new browser verification is claimed.

Added explicit `jurisdiction: "US"` and `retrievedAt` to the successful metadata
projection. `retrievedAt` is the start timestamp of the last successful retrieval
attempt, derived from the existing immutable `checkedAt` field; it is not an
upstream event or response-completion timestamp. A subsequent failure retains
that time and hash. No original archive files or records are rewritten.

Added `readLegislation` and an additive read-only API `unavailable` array for
identities with failed attempts and no successful response. The UI renders these
as requested identities with attempt time and an explicit unavailable message,
without inventing a title, official action, retrieval time or evidence badge.
`readBills` and the API’s `bills` array preserve their existing contracts.
Recovery removes only the unavailable projection, retaining original attempts.

**Remaining blocker:** the importer still has no configured Congress.gov key;
a direct API request again failed host resolution. Web access could read the
[H.R. 1 source page](https://www.congress.gov/bill/119th-congress/house-bill/1),
but that result was a rendered/cached page, not original API response bytes.
It was not imported or treated as a fresh official observation. Three actual
records, source selection/validation and source, safety/editorial review remain
unmet. Run the documented importer for three explicitly reviewed identities in a
network-enabled environment with an authorized key and disposable archive, then
validate original bytes, identities, action dates, source URLs and timestamps.
There is no national ingest, status inference or effective-date assertion.

Focused importer/lane tests: **7 passed, 0 failed**, 70 assertions, covering
initial failure, successful recovery, retained retrieval time, identity validation,
raw-hash integrity, escaping and conservative legal-status framing. Typecheck
passed. Route smoke was attempted and failed before assertions at sandbox server
bind (`EADDRINUSE`, port 0). Full-suite results are recorded below.

No deployment, merge, external message, production data change or issue transition
was performed. Configured governance and release policy described above is
unchanged. Leave SHE-880 open for the actual pilot and human acceptance.

Full `bun test`: **746 passed, 26 failed** across 772 tests. The failures were
server-start fixtures blocked by `EADDRINUSE` on port 0; required checks are not
all green. Re-run the full suite and route smoke on a runner permitting local
