# SHE-624 — PR review queue discovery

Refs: https://linear.app/shel-bernstein/issue/SHE-624/civicplaypatch-arcade-pr-review-queue-search-by-readiness-and

## Audit and implementation

Read repository instructions, readme.md, repository-voting, pr-previews and
launch-merge-policy docs. Inspected GamePatches, LiveRound, GitHub evidence
collection, eligibility and API caching. LiveRound is the civic live-vote
surface, not a PR queue; it remains unchanged to preserve that isolation.
GitHub read-only search found no PR matching “review queue”. Inspected the eight
recent open results (including draft PRs #228, #227, #226); these concern other
features. This was a bounded audit, not proof that every historical PR is unrelated.

GamePatches retains governance status and adds independent checks, review,
exact blocked-reason, affected-feature label and last-GitHub-update age filters.
Filters compose with text search and reset pagination. Feature labels are
contributor metadata, not verified impact analysis; absent labels remain unknown.
Age means time since the original updatedAt, not PR creation or first observation.
Unknown/invalid/future timestamps have their own filter. Exact source timestamps,
GitHub links, repository ID, version, head SHA, base and available base SHA remain
visible. No new provider requests, write paths or database changes were added.

The typed discovery status never supplies merge authority. Unfetched or inaccessible
protection evidence stays unknown. Missing/old-head checks never pass. Review
approval must match the displayed head; outstanding review requests and changes
requested remain distinct. The approval filter means one current-head approval
is present, not that configured approval count or all merge gates pass. Evidence
receipt time is explicitly unknown because the existing contract does not expose
it. Source sync time is not represented as an evidence fetch time. Lists can
only filter fetched/cached evidence; opening details fetches it through the existing
API. No eager per-PR fan-out or fabricated receipts were introduced.

Existing loading, source error/stale, source permission errors and viewer roster
states remain visible. Native labeled selects, visible select focus, responsive
grid and 44px controls support keyboard and narrow screens. No animation was
added, so reduced motion uses the same static interaction. Filter/clear actions
only update React state; source/preview links remain ordinary links. Voting still
requires its separate existing explicit controls. Repository/item route remounts
retain their existing isolation.

## Preserved merge policy

No policy configuration changed. PR_AUTO_MERGE_ENABLED remains false; disabled,
dry-run defaults, quorum 10, 24-hour exposure, current-head review and check gates,
protected-base evidence, strict majority, sensitive-change approval and kill switch
remain intact. Non-HBL PR scopes remain disabled/dry-run and issues never merge.
See ../launch-merge-policy.md for human review and tagged-release controls.
No production/environment settings, votes, records, receipts, auth, CSRF or roster
were changed. No deployment, merge, release, external message or issue-state change.

  focus, clear/reset and immutable input receipts.

- Desktop/mobile browser layout, actual keyboard navigation and reduced-motion
  browser checks were not executed in this sandbox. Static CSS and DOM tests

  review and successful full checks remain required; leave the Linear issue open.
