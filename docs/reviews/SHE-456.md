# SHE-456 — synthetic stakeholder lenses

Refs: https://linear.app/shel-bernstein/issue/SHE-456/joydeliberation-stakeholder-lenses-for-policy-tradeoffs

Implemented a bounded qualitative deliberation tool in HouseholdImpacts. Four
opt-in lenses describe invented assumptions, metrics with units, possible opposing
effects and uncertainty. Every selected card explicitly distinguishes direct
household evidence (unavailable), conditional unvalidated extrapolation and fictional
narrative. These are discussion prompts, not package-specific calculated effects.
No validated household response model is available; existing Unavailable cells,
missing-model disclosures and no-run/no-forecast caveats remain intact.

The component remains inside the existing real-voice synthesis package and stage
navigation. Proposal descriptions and evidence retain their sources below the
lens; no source is relabeled as household evidence. No new APIs, dependencies,
simulation handoffs or data migrations were introduced. Assumptions are local
version-1 authored examples, not empirical source claims. Selection is local,
unselected by default, resettable and cleared by the existing package remount.
No identity inference, fetch, storage or URL mutation is added. No lens interaction
counts as verified participation. The public guide explains these boundaries.

## Validation and remaining acceptance

- Focused component/public-guide checks: 4 pass, 0 fail, 80 assertions.
  DOM journey exercises all four selections, per-card evidence labels, reset,
  unknown input, remount and zero network/storage/URL changes.
- `bun run typecheck`: passes.
- `bun test`: 475 pass, 26 fail across 135 files. Server startup failures report
  EADDRINUSE on port 0; the full required suite is not green.
- `bun run test:routes`: fails at Bun.serve startup, EADDRINUSE on port 0.
- `git diff --check`: passes.

Loading/failure: these cards are synchronous bundled copy with no remote load or
request lifecycle. Missing household evidence is explicitly unavailable on every
card and in the table, never zero or an invented successful result. Existing
package loading/failure behavior is unchanged.

Keyboard/touch support uses a native labeled select and reset button, described
privacy help, live status, semantic article heading and table, focusable overflow
region and minimum 44px control heights. Text wraps without fixed card widths.
No animation is introduced, so the lens has no motion to suppress.

Browser acceptance remains pending: at 390px and actual 200% zoom select each
lens by touch; verify no page overflow or gesture-driven navigation; use
Tab/Shift-Tab, arrows and Enter/Space to select/reset with visible focus; verify
screen-reader status and table context; repeat under reduced motion and offline.
DOM checks are not proof of native keyboard, touch or screen-reader behavior.
Human acceptance and a passing required suite in a server-capable environment
remain necessary. Keep the issue open; a draft PR is only a review candidate.
