## Implemented local rehearsal

The Draft stage now includes an explicitly simulated expert office-hours panel.
Typed contracts bind each queue to repository, sample item identity and exact
draft text. The caller remounts on source/revision changes; transition validation
also rejects a mismatched source. No PR, issue, official bill or citizen proposal
identity is inferred from a sample ID.

A consent checkbox gates adding a question. Questions begin pending; simulated
moderation must supply a reason to approve or decline. Only approved questions
can receive an answer. The fixed fictional expert profile displays simulated
verification, scope, checker, time, basis and conflicts. The transition refuses
unverified or undisclosed profiles. This is a rehearsal gate, not real auth.

Answer revisions append timestamps, text and unverified evidence notes.
Corrections and withdrawals require reasons; withdrawn answers cannot be revived.
Earlier history remains inspectable. Opinion, source notes and official decisions
are separately labeled. React renders all submitted content as text; citation
notes never become user-supplied links or executable markup.

Everything stays in page memory. No API, storage, message or vote writes occur.
Reload, navigation or changing the proposal/revision discards the rehearsal,
including its history; this limit is visible before entering text. It is not a
publication audit log or a durable expert answer record.

The panel mounts only after proposal loading succeeds. Existing loading and retry
UI remains authoritative. Local validation errors retain entered text and use an
alert; updates use a status region. Native forms, labels, fieldsets, details and
buttons support keyboard interaction. Flexible full-width textareas, wrapping and
44px buttons support small screens. The panel introduces no animation, timers or
motion dependency. Public guide copy describes these boundaries.

## Remaining acceptance work

This delivers an interactive local rehearsal, not live verified expert office
hours. Keep SHE-505 open for human review and remaining implementation. Real
participation needs authenticated moderator/expert roles with server-side
permissions, independent verification and expiration/revocation procedures,
expert consent and conflict disclosure review, durable revision-bound question
and answer storage, publication/removal/retention policy, and authenticated
correction/withdrawal endpoints. Implement and test those before enabling public
questions or representing any real expert as verified. Run all required checks
in an environment where local server listeners work, and review mobile/keyboard
and reduced-motion behavior in a native browser.
