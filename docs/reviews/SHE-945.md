# SHE-945 — request and client log audit

Refs: https://linear.app/shel-bernstein/issue/SHE-945/cs-l100076-audit-request-and-client-logs-for-journal-text-or-anonymous

Status: local hardening candidate; external hosting logs and deployed browser
traces remain unverified. Leave the issue open for human acceptance.

## Evidence before changes

Read AGENTS.md, readme.md, docs/citizen-proposals.md, docs/launch-alerts.md and
launch-merge-policy.md. Audited runtime console calls and route wrappers.
GitHub privacy PR search found #14 (privacy), #21/#73 (private journal), #226
(metrics), #307 (release failure telemetry) and #125 (privacy navigation).
Inspected #307's diff: it proposes additional server/client telemetry on another
revision. It is not acceptance evidence for this checkout. Reconcile its reporting
sink with this request context before integrating; do not add raw browser exception
payloads, incoming request IDs or identity fields.

Confirmed risks in the checked-out source:

- Debug request logging copied Referer, User-Agent, origin and other headers.
  Referer can contain URL secrets; headers can contain arbitrary personal text.
- Publication label events copied IPs, entry IDs, submitted/ignored IDs, headers
  and JSON parser exception messages. Malformed JSON can echo body fragments.
- Citizen proposal unexpected errors logged the complete exception. The Bun
  fallback logged `error.name`, which is also arbitrary text.
- The client has one explicit console sink: optional-map warnings. It already
  discarded MapLibre error objects, but interpolated a type-restricted reason
  without runtime validation. No global exception-reporting SDK is installed in
  this checkout. Native browser/React/dependency diagnostics are outside that sink.
- Other runtime messages include fixed stats failures, startup/configuration,
  duplicate-need migration and authenticated purge summaries. Offline clustering
  CLI intentionally prints its report; it is not a request trace. Do not run it on
  personal production data as part of this audit. No production data was read.

## Local change and corpus

`private-logs.ts` discards publication payloads entirely and accepts only fixed
event names. Debug events no longer retain headers, paths or response metadata.
Unexpected exceptions emit a fixed category and random server-issued request ID;
no exception field is inspected. AsyncLocalStorage isolates concurrent requests.
The outer route/fallback wrapper returns the same ID in `X-Request-ID`, including
handled proposal persistence failures. IDs are per request, never browser/voter
identities or trusted incoming headers. Existing security/auth wrappers, responses,
streams, embed CSP, votes, source references and persistence remain in place.
The map warning validates its reason against three fixed values at runtime.

Canaries cover private journal/draft text, anonymous browser vote token, URL path,
query and fragment secrets, malicious exception name/message, headers, malformed
label JSON and submitted IDs. Tests capture actual console calls from debug and
preflight route adapters, publication label handlers, proposal persistence failure,
concurrent thrown handlers and client map failures. They verify no canary appears
and server exception traces match response request IDs. Redirect/stream/header
preservation is also checked. These tests do not claim to intercept every native
browser diagnostic, proxy log or future third-party SDK.

## Before/after measurements (local only)

Reliability baseline reproduces the old debug Referer/User-Agent serialization:
the synthetic canary appears three times across two header fields. Captured logs
from the same header corpus after hardening contain zero occurrences. Exception
and publication corpora likewise have zero canary occurrences after hardening.

A local Bun microbenchmark (10,000 sequential in-memory `Response('ok')` calls,
1,000 wrapper warmups) measured 2.376 ms before versus 14.862 ms with the request
wrapper: about 0.238 versus 1.486 microseconds/call, 0/10,000 non-200 responses in
both cases. It measures allocation/context overhead only, not HTTP latency or
production capacity. No public requests or load tests were made.

Validation:

- Focused canary/ownership tests: 8 passed, 0 failed, 103 assertions.
- `bun run typecheck`: passed.
- `bun test`: 659 passed, 27 failed on the final run. 26 failures require listening
  sockets rejected here with EADDRINUSE on port 0. One browser bundle budget test
  reports 250,244 gzip bytes against 250,000. Repeating that test with the original
  client map module reports 250,218 bytes: baseline already exceeds the limit;
  this candidate adds 26 bytes. No budget was weakened.
- `bun run test:routes`: attempted, blocked by the same listen restriction.

Required checks are not all green. Re-run all three in a socket-capable environment
and resolve the bundle budget before human acceptance.

## Reversible stages and remaining acceptance

1. Review and run the canary corpus locally using disposable data. This is the
   only stage performed. No data migration, production write or telemetry endpoint.
2. Human release owner reconciles #307, resolves checks, then exercises an isolated
   staging deployment with synthetic drafts/tokens/URLs and forced persistence and
   client failures. Inspect stdout, browser console, network reports and hosting
   access/error logs. Check request-ID response correlation, no secrets, error rate
   and before/after p50/p95 latency at a small fixed sequential request count.
   Do not inject deliberate errors into the public site.
3. Hosting operator inspects actual proxy/provider request-log fields and retention,
   including full URL/query, Referer, IP and cookie capture; remove sensitive fields
   at each configured sink. Repository redaction cannot control upstream logs.
   Native browser diagnostics and dependency failures need a real-browser staging
   capture; any added reporter must project only reviewed fixed fields.
4. Human maintainer reviews the current SHA and checks, and a human release owner
   publishes a tagged release through existing gates. Monitor staged reliability
   before considering broader rollout. Roll back to a validated compatible image
   if IDs/security/streams regress; do not restore raw payload logging or alter data.
   No rollout or rollback is executed by this task.
