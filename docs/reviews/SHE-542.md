# SHE-542 — cinematic regression harness

Refs: https://linear.app/shel-bernstein/issue/SHE-542/joyquality-visual-regression-harness-for-the-ten-cinematic-journeys

## Implementation candidate and limits

Inspected readme.md, docs/motion.md, docs/launch-merge-policy.md, motion.ts,
proposal-motion.ts, PatchChange, WorkflowScreen, MapScreen, shared civic stages,
and the existing accessibility Playwright suite and isolated server. GitHub PR
search found related open drafts including #140 (cinematic recap), #177 (keyboard
parity), and #176 (non-coercion). None is acceptance evidence or a foundation to
silently transplant. No matching visual regression PR was found in the search.

The beta defines six civic stages and a seven-stop demo, not a canonical list of
ten cinematic journeys. This implementation maps ten tests to existing behavior:
six stage-to-next-stage/back journeys, redline playback, county zoom/revision,
loading/error/retry/empty, and proposal selection/external world handoff. Each
runs at desktop 1440×1000 and touch mobile 390×844, both normal and reduced motion
(40 cases). Maintainers must confirm that mapping against the intended ten journeys.

Fixtures reuse the typed fictional demo catalog with a fixed date, empty browser
counts and unavailable verified status. Browser API mutations are intercepted,
aborted and asserted absent, including vote submissions. Normal desktop controls
use Tab/Enter; mobile uses tap. Proposal IDs must survive navigation/history;
redline source text must remain mounted, normal playback must enter and exit its
state, and reduced motion must skip decorative playback. The actual CSS animation
is paused at a 900ms timeline position for a midpoint screenshot; the cleanup
clock is controlled independently. The county test uses deterministic single
revisions rather than an uncontrolled interval simulation.

The beta's /map is a local SVG county simulation, not a camera fly-through.
The HBL world destination belongs to another repository. Tests assert its safe
external handoff and the local selection change only. They do not establish a
proposal→world morph or camera animation that is absent from this checkout.
Navigation endpoint screenshots also cannot establish every intermediate
cross-document transition frame. Those remain acceptance gaps.

## Run and review baselines

```
bun install --frozen-lockfile
npm install --prefix tests/visual --ignore-scripts --package-lock=false
(cd tests/visual && npx playwright install --with-deps chromium)
bun run typecheck:visual
bun run test:visual
```

The harness reuses scripts/accessibility-server.ts: credentials are removed,
storage is disposable, governance remains disabled/dry-run with kill switch active,
and no production origin is used. Do not run accessibility and visual suites
concurrently because both intentionally use the isolated server's port 3107.

Screenshots compare with zero differing pixels against platform/project-specific
reviewed files in tests/visual/baselines. Missing baselines fail; ordinary CI never
updates them. Traces, screenshots and the HTML report upload under
cinematic-journey-evidence. To create an initial candidate in Ubuntu 24.04 with the
pinned Playwright Chromium, run:

```
(cd tests/visual && npx playwright test --update-snapshots)
```

Review every candidate image, including loading/error/empty and redline midpoint,
then commit the Linux baselines and rerun without update mode. A passing snapshot
update is not regression or acceptance evidence. Do not copy macOS images into
Linux baseline paths. No baseline images have been generated or reviewed here;
the new CI check will remain red until that work is completed.
