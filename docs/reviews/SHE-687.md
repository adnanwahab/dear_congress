## Implemented scope

Sample source panels now offer a proposal-specific JSON packet with exact current
and proposed text, repository and fictional-demo kind, editorial summary version,
author/review gaps, source citation identity/scope, recorded check date,
assumptions, limitations and an explicit material-update provenance entry.
Unknown publication dates and human review remain unknown. Export timestamp is
not a source date. Evidence version 1 is the export contract's version; it is
not an invented upstream revision. No historical summary revisions are available.

The projector explicitly allowlists public fields. It never reads journals,
ballots, browser storage or full source bodies. A closed contract check before
serialization rejects extra fields, changed fixed statuses, unsafe citation URLs,
invalid dates and malformed proposal fields. The companion JSON Schema is
`docs/schemas/evidence-packet-v1.json`. Export is read-only, without persistence,
network requests, claim submission, human approval or voting authority.

Links receive HTTPS/credential syntax checks only. No network reachability or
content verification is claimed. A failed/missing citation remains a gap; the
packet is useful offline without pretending the link has been verified.

Native details/buttons and a labelled read-only textarea provide an offline
copy fallback after load. Download errors retain the packet. Print errors retain
selectable JSON. Source changes remount the export control so an earlier
packet does not remain attached to a new proposal. Guide copy explains these limits.

## Acceptance still open

This is a bounded sample export, not the complete issue. Keep SHE-687 open.
A fully sourced case and a conflicting case cannot be truthfully demonstrated
from these background-only fixtures. The missing-source case is covered. Remaining
implementation needs an agreed claim-provenance contract, reviewed and dated
primary sources, editorial inference/user claim/synthetic estimate records with
per-claim limitations, append-only material evidence revisions and human review
state, plus citizen/official proposal integration with revision and kind isolation.

Reachability verification needs a bounded trusted-source service or reviewed
source checker (no arbitrary server-side URL fetching), dated results and explicit
offline/timeout/redirect states. Current syntax validation does not satisfy that
requirement. Run all required checks in an environment permitting local server
binds and perform native keyboard/touch/loading/error/print accessibility QA.
No fixtures are labelled fully sourced or human approved without supporting data.
