## Proposed bounded delivery contract

Start with a small text-only, human-moderated circle. No audio/video recording,
location collection, provider inference or automatic publishing. The guided
sequence is: read privacy limits → choose audience → inspect participants and
moderator → explicitly join → optionally tell a first-person problem → listen
without rebuttal → optionally offer a reflection → review any proposed excerpt.
Passing a turn and leaving must always be available. Avoid likes, popularity
ranking, inferred consensus and converting stories into votes.

Show audience in text at the heading, composer, review and each artifact:

| Scope | Read/share contract |
| --- | --- |
| Personal | Author only. If a report needs human review, separately confirm the exact report excerpt and reviewer access. No implicit moderator access to personal drafts. |
| Invite-only | Active admitted members and assigned moderator only. Expiring single-use invitations establish membership; a URL alone never grants ongoing read access. No search, hub, feed or public API projection. |
| Public | Only a separately reviewed, moderated artifact revision with explicit author permission. Joining or posting to a circle never supplies that permission. |

Default to personal preparation. Display warnings before entry: omit names,
contact details, exact addresses, workplaces, schedules and sensitive third-party
details; participants may copy what they see; anonymity cannot be guaranteed.
Do not prefill public journal text or private drafts into another audience.
Exclude exact location fields from the contract and reject unexpected location
metadata. Privacy review must also cover identifying free text: detection is a
hold signal, never proof that an artifact is safe. Potentially identifying text
must remain unpublished until revised and reviewed. Declining consent does not
write text, join a circle or create a participant count.

Treat a summary as a new artifact with its own text, source revision bindings,
audience and permission. Make summaries optional and initially human-authored.
Require each contributing author to approve the exact excerpt of their story
and the resulting summary revision before wider sharing; revisions invalidate
prior approval. Omit nonconsenting sources entirely. Never describe pseudonyms
or removed names as guaranteed anonymization. Do not fetch source URLs or send
stories to an AI provider as an incidental implementation choice.

Add separate typed circle, membership, invitation, story, summary, consent and
moderation records. Bind permissions to repository/source kind, circle, artifact
ID, revision and audience; do not reuse proposal ballots or PR revision records.
Server-side checks apply to every read, write, export and stream delivery.
Use existing same-origin protection, signed identity, bounded input, rate limits
and server-only moderation authorization. Add idempotency and expected-version
checks, atomic persistence/rollback and restart tests without destructive migration.
Never trust client-supplied owner, moderator, audience approval or origin labels.

Leave removes future membership access and closes streams. Separately offer
revoke sharing and delete my story; leaving alone must not silently delete or
retain publication contrary to the stated choice. Revocation immediately removes
served excerpts and dependent summaries from all relevant projections and streams;
re-sharing requires fresh permission. Deletion removes raw story content and
derived copies under app control, retaining only minimal authorized event metadata.
Specify report retention and backup expiry before pilot enrollment; do not promise
recall of screenshots or independently published copies. Audit records must omit
raw text, invitation secrets, reporter identity from public responses and precise
location. Preserve unrelated journals, votes, source IDs, frozen plans and receipts.

Reports need typed artifact/revision targets, a private receipt, human triage,
reasoned decisions and an appeal path. Reporting must not itself publish a private
story or automatically count as a vote to hide it. Restrict moderator access to
assigned circles and authorized report excerpts; retain a minimal action history.
Retired moderators immediately lose access. A stale tab must clear inaccessible
content and announce the denial; SSE must reauthorize before delivery, not only
when connecting. Do not cache private text in URLs, public state, logs or storage.

## Integration and acceptance evidence still required

`CitizenProposals.tsx` should offer a separate listening entry point with explicit
audience and no inherited public-comment permission. `LiveRound.tsx` can link to
a separate circle flow, but its voting endpoint/code/participant count must retain
their current meaning. `TopicHubs.tsx` may show only an explicitly released,
current public summary; existing human-journal exclusion remains. Synthetic
walkthroughs must visibly say fictional at entry, per message and attendance
count, and must never be counted as real contributors or appear in real circles.

Before acceptance, implement and record these checks against disposable data:

1. Author, invited member, stranger and moderator sessions exercise all three
   scopes. A stranger with known IDs, an expired/reused invitation, forged role,
   wrong repository/item kind or revoked membership cannot read or write text,
   summaries, reports or SSE. Moderator access never crosses assignment scope.
2. Decline joining/sharing, pass a turn, leave, revoke, delete, report and appeal.
   Assert exact per-revision permission, fresh consent after edits, and no text
   submission when consent is denied. Verify denied storage/network permissions
   preserve in-memory input without claiming it was saved or published.
3. Race revocation/deletion against summary approval, two saves, reconnect and
   stale tabs. After permission loss, no further event contains restricted text;
   stale updates fail without restoring it. Verify server restart, disk failure,
   retry conflicts and deletion of dependent served summaries.
4. Seed private-text, location and hidden-story sentinels. Assert absence from
   public APIs, topic hubs, search, exports, logs, analytics and summary inputs.
   Exercise identifying prose, unsafe markup, third-party details and reports.
   Snapshot unrelated ballots, PR head/base bindings, records and receipts to
   prove no mutation. Never run write walkthroughs against the live app.
5. Test truthful fictional labels, zero fabricated attendance and complete
   separation from advisory vote totals and verified repository electorate.
6. Perform keyboard and screen-reader journeys with labelled audience controls,
   understandable warnings, focus recovery and announced permission errors.
   Check 390px, long text, 200% zoom, forced colors and reduced motion. Follow
   `docs/accessibility-acceptance.md`; simulated DOM success alone is insufficient.
7. Run `bun test`, `bun run typecheck`, `bun run test:routes`, focused permission,
   privacy, stale-session and UI tests. Record actual browser evidence for the
   changed states. Human review must verify the current revision before acceptance.
