# SHE-941 — deferred map loading audit

Refs: https://linear.app/shel-bernstein/issue/SHE-941/cs-l100072-lazy-load-county-geometry-and-map-modules-only-when

## Result and evidence

Audited baseline `ac5212b` and existing repository PRs before changes. Source recovery PR #18 retained deferred MapLibre loading; county trust PR #117 and map continuity PR #244 address related presentation. The GitHub search also returned dependency-monitoring PR #312. No SHE-941 implementation PR was identified in that search. These PRs are context, not acceptance evidence.

The requested loading boundary already exists: App uses React.lazy for MapScreen and renders it only for `/map`; its existing Suspense fallback is PageSkeleton. MapScreen statically imports the Census county shapes and local simulation/heatmap behind that boundary. `maplibre.ts` dynamically imports MapLibre only for configured maps. There are no deck.gl imports in client source, despite installed plotting dependencies. No runtime change is needed based on this source audit.

This change extends the real production-bundle regression test to require county shapes to remain outside the initial static import graph and reachable through deferred imports. It also rejects map-screen labels, plotting package markers and preload/prefetch hints in the initial shell. Existing MapLibre JS/CSS and 250,000 gzip-byte budget checks remain.

Two production builds, before and after the test/tool additions, produced identical assets:

| --- | ---: | ---: |
| Initial static JS | 745,787 / 240,859 | 745,787 / 240,859 |
| Deferred county screen + geometry | 1,745,683 / 569,950 | 1,745,683 / 569,950 |

Raw reports: [before](../evidence/SHE-941/build-before.json), [after](../evidence/SHE-941/build-after.json). Gzip values are locally compressed artifact sizes, not measured HTTP transfers. No payload or latency improvement is claimed. The shared initial graph applies to Home and Votes; this alone cannot prove their runtime waterfall.

## Waterfall and latency measurement status

Added `scripts/measure-map-loading.ts`: runs the actual production server with disposable databases, disabled merge automation and no inherited service credentials. Uses fresh Chromium contexts for Home, Votes and Map at 1440px and 390px; blocks all external-origin requests; captures navigation and resource timing, JS raw/gzip totals, and verifies county payload appears only for Map. No public site is contacted. Observation continues 1.5 seconds after the first main heading. Reports include resource start/duration and navigation DOM timings; they are unthrottled local diagnostics, not a user latency benchmark. Plotting classification uses package-name markers; source inspection complements it.

Run with an installed Playwright module:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs bun scripts/measure-map-loading.ts > /tmp/SHE-941-waterfall.json
bun scripts/measure-map-loading.ts --build-only
```

Attempted the browser measurement here, but the sandbox rejected Bun.serve's listening socket (`EADDRINUSE`, port 0). Therefore no browser waterfall or before/after latency was collected. Existing task screenshots contain no network or byte measurements. Browser acceptance remains outstanding; do not close the issue based on static evidence.
