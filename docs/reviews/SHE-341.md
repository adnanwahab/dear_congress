## Changes

Shared lightweight skeleton primitives provide card, list, line and vote shapes.
All six bottom-navigation civic stages use their existing responsive grid classes
while initial demo data is pending. Draft and Sponsors now reserve panels instead
of omitting them. Overview uses feed, vote and draft placeholders; Journal keeps
the composer available and shows placeholders for its shared feed. Accessible
status labels replace visible loading sentences. Placeholder shapes are hidden
from accessibility APIs and have no interactive vote controls. Empty and failure
states, retry controls and proposal selection remain separate from loading.

App's lazy-code fallback selects a layout from the route. Map gets a lightweight,
approximate national silhouette, including inset hints, independently of the
county JSON/module download. A normalized path draws via stroke-dashoffset; county
paths fade via fill-opacity on arrival without changing their existing status
opacity or revision ripple transitions. CSS reduced-motion rules remove shimmer,
outline drawing and county arrival animations, including preference changes.

Skeleton and content share the existing responsive grids; feed and two-column
panels reserve minimum heights. These measures reduce jumps but are not a measured
CLS guarantee. The code fallback's simplified header/heading and Map silhouette
are approximations, and variable-length content can exceed reserved sizes.
Browser measurement must establish CLS < 0.05 before acceptance; further size
alignment may be needed, especially on narrow screens and cold code loads.

## Verification

Locked dependencies installed without changing the lockfile. Typecheck and
`git diff --check` pass. Four focused tests pass (41 assertions): all six initial
stage states, route fallback selection, outline presence, motion CSS, and the
existing isolated DOM journey for delayed/empty responses, errors/retries,
unavailable proposal IDs and restored proposal context. That journey now checks
accessible skeletons instead of the retired loading sentence.

Full `bun test` after the regression update: 282 passed, 22 failed. The failures
are HTTP tests whose Bun server cannot listen in this sandbox (`EADDRINUSE`,
port 0). `bun run test:routes` is blocked by the same server startup error.
No rendering-browser, screen-reader or throttled-network CLS measurement was
performed. DOM tests do not establish pixel layout or animation quality. Human
review should check desktop/mobile cold loads for each bottom destination,
reduced motion, long proposals, layout stability and the outline/county handoff.
