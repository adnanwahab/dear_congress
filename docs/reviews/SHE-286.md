## Implemented behavior

- `/admin/stats` uses the existing `ADMIN_TOKEN` through Bearer authorization or
  browser Basic authentication (`admin` / token). Missing/unconfigured/wrong
  credentials fail closed with 401; no login cookie is created. GET and HEAD only,
  no-store, noindex and existing security headers. Plain server HTML includes all
  required counts, empty states, source breakdown, collection start and caveats.
- `LaunchStats` uses separate additive SQLite tables, defaulting to
  `${DB_PATH}.stats.sqlite`; configurable through `STATS_DB_PATH`. It survives
  restart and demo reset without migrating, deleting or rewriting existing data.
- Today/yesterday use Chicago calendar dates, including DST and year boundaries.
  Votes deduplicate by date, hashed identity, source scope and target/revision.
  Unique voters and yesterday/today intersection count identities. Existing civic
  cookie identities, repository community identities and approved GitHub identities
  stay distinct; there is no attempted cross-system identity linking.
- Civic stance/goal/allocation, immutable citizen proposals, and all six existing
  repository/kind scopes are observed only after successful saves/validation.
  Repository targets retain number and exact version, including PR head/base
  binding. Rejected/stale ballots and withdrawn-only choices do not add votes.
  Replacements/retries count once per day; a later withdrawal does not erase
  evidence that the identity participated that day. No tally or electorate is
  calculated from the metrics store.
- Journal aliases `/api/journal`, `/api/entries`, and journal-mode
  `/api/publish_draft` record the accepted entry's ID and server flags, keeping
  sample/simulated/real separate. Answer mode, simulations/what-if runs and seed()
  never create real journal metrics. Unknown legacy rows are not backfilled.
- `/api/page-view` records browser loads and pathname transitions using only
  aggregate day/normalized route counters. It is outside the public identity
  wrapper, issues no cookie, rejects non-POST/cross-origin/private/unknown/query
  routes and oversized JSON, and has independent IP limits using the existing
  trusted-proxy rules. Detail IDs are collapsed. No visitor identifiers, query,
  fragment, referrer, IP or user agent is persisted in view data. Client calls use
  `credentials: omit`, keepalive, and ignore collection errors. History wrappers
  retain normal navigation behavior. The stats page itself loads no scripts.

New collection starts at the stored `startedAt`, not midnight retroactively.
Existing votes lack reliable timestamps/origin; no safe migration can manufacture
returning voters or separate unidentified historical QA. New accepted public
submissions are operational activity, not proof of human/resident identity.
Automation using the public APIs cannot be distinguished from a human. No seeded
or modeled population contributes vote events. These definitions are explicit on
the page and in the readme rather than silently presenting legacy tallies as live.

Metrics are best-effort after application persistence. The separate stores are
not atomic together: a crash/disk failure can undercount. Runtime observation
failure preserves the successful application response and marks the dashboard
incomplete for that process. Page-view delivery may fail or be blocked/rate-limited;
request spoofing may inflate it. Startup requires writable metrics storage. No
claim of representative turnout or exact audited traffic is made.

## Existing configured merge policy preserved

No policy, quorum, roster, auth, origin/CSRF, revision validation, checks, worker,
GitHub merge adapter, workflows or production settings were changed. API edits
only observe successful saves through a server callback.

Defaults remain quorum **10**, strict yes majority, **24-hour** exposure, at least
**one current-head approval**, empty allowed bases/checks (fail closed),
`enabled=false`, `dryRun=true`, **09:00 America/Chicago**, maximum **six-hour**
recovery. Production bases require explicit authorization; the kill switch is
active unless disabled. Known protected-base evidence, clean mergeability,
successful current-head checks, no blocking/outstanding reviews and maintainer
approval for sensitive changes remain required. Nonlegacy PR scopes are forcibly
disabled/dry-run and issues never merge. Community votes remain outside verified
merge ballots; the shared approved roster remains capped at 100. Repository,
kind, source and PR head/base identities remain intact.

Fly config has no merge-enabling override. Daily integration still requires its
existing variable/signed credentials; Fly deploy still triggers on main/master
pushes in this baseline. Remote protections and production environment overrides
were not verified. No one-vote quorum or live automatic merge was enabled.
