# SHE-536 implementation review

Refs: https://linear.app/shel-bernstein/issue/SHE-536/joydiscover-embeddable-civic-proposal-explorer-for-community-websites

Implemented a versioned static learning card at `/embed/v1`, with a sample index
and proposal-specific URLs. The existing WorkflowScreen feed offers a copyable
iframe snippet and preview. The renderer consumes the existing typed DemoItem
catalog without reading database records, votes, browser identity or simulations.
Summary, jurisdiction, source publisher/name/scope/review date and read-more links
preserve the sample's identity. Catalog sources currently have no review dates;
these are explicitly “Not checked,” not reviewed evidence. No real proposal card
is claimed by this implementation. v1 versions the rendering contract, not content.

## Audit and security boundary

Read readme.md, AGENTS.md, launch policy, WorkflowScreen, DemoItem catalog,
ProposalProvenance, public security headers, server router and route smoke tests.
GitHub PR search scoped to adnanwahab/dear_congress for “embed” returned source
recovery PR #18 and separate simulation viewer PR #120, with no matching civic
proposal-card implementation. Local baseline is 1305bc0. Existing `/embed` remains
unchanged; the new route never boots that full application.

Only the dedicated static route allows HTTP/HTTPS ancestors. Its CSP disables
scripts, connections, forms, base URLs and objects, and applies an opaque-origin
sandbox without allow-scripts or allow-same-origin. Only user-activated new-tab
links escape the sandbox; they use noopener/noreferrer. The copied iframe repeats
the sandbox, has an accessible title, lazy loading and no-referrer. Host websites
must explicitly permit the Civic origin in frame-src. No CORS or write/auth policy
was changed. No cookies are issued. Hosting still receives ordinary HTTP requests.
All metadata is HTML-escaped; source URLs require HTTPS without credentials.

The document is server-rendered with no asynchronous card state or animation.
Native browser navigation supplies loading; empty catalogs and unknown IDs have
explicit messages, with 404 for unavailable samples. Native links, visible focus,
viewport sizing, wrapping and scrolling support keyboard/touch and static
reduced-motion presentation. Actual cross-origin browser behavior, keyboard/touch,
high contrast and small-screen visual verification remain required before acceptance.
