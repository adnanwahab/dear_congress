## Consented study procedure

A human study owner must arrange ten voluntary first-session participants through
an already consented channel. Do not initiate outreach from this task. Recruit by
experience and access needs, never political stance. Offer desktop/mobile and
keyboard/assistive-technology participation without requiring medical disclosure.
This is a small formative sample, not representative civic participation.

Use an isolated local instance with disposable synthetic data, no production
credentials and merge disabled/dry-run/kill switch active, following the existing
accessibility runner guidance. Record exact commit, fixture version, route,
browser/version, broad device class, viewport, zoom and input/assistive technology
only where voluntarily provided. Start each session in a fresh browser profile.
Do not submit test votes, journals, comments or proposals to the deployed site.
The supplied civic-synthesis.fly.dev URL is context, not permission for writes.

Read before starting: “We are testing this independent advisory beta, not you.
It is not an official government or election service. Participation is voluntary;
you may skip a task or stop at any time. Use only the supplied fictional text.
We will retain anonymous task outcomes, elapsed times and paraphrased interface
observations, without names or private content. May we proceed with those notes?”
Record only consent yes/no and a session code. Do not run or count a session
without affirmative consent. Use notes by default; make no audio/video recording.
Any later recording requires separate explicit consent and an approved storage,
redaction and deletion arrangement before capture.

Avoid leading hints or explaining navigation before tasks. Start the timer after
reading each prompt; stop on the defined outcome, participant stop or five-minute
cap. Count unassisted success, assisted completion, failure or skipped separately.
Log elapsed seconds and assistance; never convert a timeout into success. Pause
timing for equipment interruptions and record the interruption. Allow rest/stop
without penalty. Run all eligible sessions on the same baseline revision.

| Task prompt | Observable success |
| --- | --- |
| From home, find a sample proposal about transport and explain the proposed change | Reaches a matching proposal, explains it without help; merely browsing creates no vote |
| On this disposable copy, express a choice, find whether it saved, then change it | Recognizes server confirmation and revised choice; report each substep separately |
| Find where you could describe an experience; use the supplied fictional bus-delay sentence and stop before publishing | Locates journal/editor and identifies public-sharing boundary without publication |
| Find what happens after a proposal and whether a public office has received anything | Reaches follow-up information and correctly identifies simulated/no-message state |
| Find participation/privacy guidance and explain what to avoid sharing | Finds guidance, identifies public journal visibility and private-content warning |

After each relevant task, ask without suggesting answers: Who operates this?
Is this an official ballot? Are the displayed counts real participant totals?
Did viewing a proposal cast a vote? Where would published journal text appear?
Was anything sent to an office? Record correct/partial/incorrect/unknown against
the applicable screen's actual claims; retain only a brief anonymous paraphrase.
Do not ask for policy preferences or personal experiences.

Record interface accessibility observations for every session: focus visibility
and order, keyboard reachability, modal escape/focus return, labels and announced
save/error states, clipping/reflow at the participant's chosen zoom, non-color
meaning, motion preference and touch targets. Mark untested conditions explicitly.
Use docs/accessibility-acceptance.md for separate manual screen-reader and actual
200% zoom checks; automated accessibility output is not participant evidence.

## Ranking and before/after acceptance

After ten sessions, group repeated observations by friction ID, keeping affected
session codes and task denominators. Rank safety/comprehension failures and
task-preventing accessibility barriers first, then other task failures, then
assistance/time burden. Within a tier use affected-session frequency, then median
task time; document human judgment and ties. Report n/N, unassisted and assisted
completion separately, median and range for completed tasks, and timeouts/skips
separately. Small samples do not establish statistical or population claims.

For each of the actual top three, add the observed baseline, affected tasks and
session codes, severity/rank rationale, exact proposed fix, source/proposal IDs,
before/after commit SHAs, sanitized before note, comparable after note, and human
reviewer decision. Notes satisfy the issue's recording-or-notes option without
retaining recordings. Currently all three ranking slots are **unestablished**.

accessibility regresses. Human acceptance requires ten consented baseline records,
an evidence-ranked top three, comparable after evidence for each fix, privacy
review and required checks on the final revision. A merged document meets none
