# SHE-878 — Human editorial gate for 100 draft concepts

Refs: https://linear.app/shel-bernstein/issue/SHE-878/cs-l100041-set-a-human-editorial-review-gate-on-all-100-draft-bills

## Scope and audit

Read repository instructions, README, catalog module documentation and launch
merge policy. Audited the strict deterministic importer, generated catalog,
shared search, detail UI, citizen proposal input allowlist and publish-draft modes.
Catalog records have no ballot publishing endpoint; citizen inputs do not import
catalog identity. GitHub PR search found original catalog PR #119 and separate
daily-question queue PR #298, with no SHE-878 result. This is a local implementation
candidate, not verification of deployed source or acceptance.

## Implementation

All 100 stable IDs now have a checked-in ledger recording exact catalog digest,
proposed jurisdiction, author/editor assignments, legal/evidence/fiscal decisions
and publication decision. No actual author/editor or reviewer identity was
verified, so assignments remain explicitly null and decisions pending/blocked.
The shared gate rejects missing/duplicate records, stale revision/jurisdiction,
missing assignments or approvals without human identity and review evidence.
Every detail page exposes these gaps; every catalog card shows publication blocked.
A complete editorial record still cannot open an advisory ballot. No publication
API, migration, catalog digest rewrite, vote transfer or production write was added.

The module documentation describes human assignment, independent review, evidence
records, revision reset, explicit editor publication decision and required human
PR review. HFL-051 supplement remains outside the catalog digest and needs a
separate reviewed immutable snapshot before future publication. This ledger is
repository review evidence, not authenticated reviewer identity infrastructure.

## Acceptance limits

Human maintainers still need to identify actual authors and editors and perform
all 100 legal, evidence, fiscal and editorial reviews. No concept is introduced
legislation or a verified cost/impact claim. Future ballot publication requires a
separate authorized server implementation bound to immutable source kind and
revision. Human browser/accessibility review remains pending; DOM tests verify
visible disclosure and absence of catalog API writes only.

Existing governance defaults remain disabled/dry-run, quorum 10, 24-hour exposure,
one current-head approval, fail-closed base/check allowlists and active kill switch.
No voting, auth, merge or production configuration changed. These are documented
source defaults, not verified live configuration. Required main checks remain
`bun test`, `bun run typecheck`, `route smoke test`, with actual GitHub protection
requiring human approval. No external messages, issue transitions, merge, auto-merge,
release or deploy performed. Leave the issue open for human acceptance.
