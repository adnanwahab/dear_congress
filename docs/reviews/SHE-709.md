## Proposed implementation contract

This is a design proposal, not a description of existing endpoints.

1. Define a versioned artifact envelope keyed by repository identity, artifact
   kind, source ID and immutable content revision. Keep ownership, visibility,
   grant version, moderation state and retention policy separate from text and
   civic/repository votes. New artifacts default to personal. Preserve all legacy
   records and their existing public semantics; do not bulk relabel them private.
2. Establish server-verified principals and explicit artifact grants. Every read,
   list, export, search, prefill, notification and stream must apply the same ACL.
   Team membership grants access only to explicitly selected team artifacts.
   Invite acceptance and share-link navigation cannot change visibility, publish
   content or grant access to other personal artifacts. Public data projections
   must allowlist fields and omit grants, private metadata and owner credentials.
3. Add a shared review component in CitizenProposals, LiveRound and TopicHubs,
   with adapters for each actual contribution type. Show exact text/attachments,
   source and revision, Public / Invite-only / Personal as text, named audience,
   processors, retention and deletion limits. List omitted private material
   without copying that material into a public payload. Require separate consent
   per artifact; invalidate it on text, attachment, audience, retention or revision
   changes. Membership or a share link never supplies publish consent.
4. Bind consent server-side to owner, exact reviewed content revision, audience,
   policy version and idempotency key. A stale revision, expired/revoked session
   or changed grant must fail closed before persistence and fanout. Lost-response
   reconciliation uses the same operation identity; never silently retries a
   different payload or queues public publication after reconnect.
5. Separate publish request, moderation pending, approved publication, rejected,
   withdrawn and retention deletion. Personal saves must not enter public journal
   extraction, topic indexes, SSE, synthesis, telemetry or preview endpoints.
   Moderator authority is scoped and does not silently authorize secondary use.
   Reports work for each supported artifact kind without publishing report text
   or reporter identity to its audience.
6. Implement leave and owner revoke with grant-version checks, invalidation of
   existing links/streams and future retrieval, plus clear limits for downloaded
   copies. Do not delete an independent published proposal, mutate its votes or
   lose source IDs when revoking a related draft. Define retention of minimal
   audit metadata separately from artifact text; do not retain private text in
   ostensibly content-free audit records. Audit actor, operation, revision,
   scope transition and result atomically with successful changes; denied actions
   must not leak content into logs.
7. Preserve synthetic provenance as structured data through save, preview, share,
   moderation and projection. Label fixture material at every visible boundary;
   never present sample messages as participant messages or synthetic records as
   authenticated collaborators. Existing live-round browser totals must remain
   separate from synthetic policy examples and verified repository ballots.

Durable personal storage/encryption and account recovery need explicit engineering
and security design; SHE-319 documents the existing limitations. Avoid silently
migrating plaintext drafts into a shared service. Coordinate any artifact timeline
with SHE-711 after its current revision is reviewed; private permission events
cannot be copied wholesale into a public retrospective.

## Required acceptance evidence

| Area | Required cases on disposable data |
| --- | --- |
| Scope and payload | Each supported kind in each scope; exact allowlisted preview; edit-after-consent; omitted private sentinel absent from requests, URLs, logs, streams and public projections; no implicit publication on invite or link. |
| Authorization | Owner, explicit recipient, unrelated team member, outsider and lost-cookie browser; guessed IDs and copied links; expired/revoked grants and sessions; membership changes between preview and commit; denied reads never return private text. |
| Concurrency and durability | Stale revision/grant returns conflict without mutation; concurrent share/revoke; failed persistence rolls back; same-key retry reconciles exactly once; offline/reconnect sends nothing without fresh consent. |
| Moderation and retention | Held content absent from public APIs/topics/SSE; rejection and withdrawal distinguished; report authorization and privacy; expiry enforced on reads and streams; deletion jobs, backup limits and minimal audit policy demonstrated. |
| Isolation and provenance | Same ID in different kinds/repositories stays isolated; existing proposal/source IDs, PR head/base binding, ballots and receipts unchanged; fixtures remain labelled after every transition; no invented contributors. |
| Accessibility and mobile | Keyboard-only review, cancel, leave, revoke and report; focus recovery; associated labels and announced errors; scopes discernible without color; screen-reader review; narrow phone widths, long names/URLs and 200% zoom without lost controls. |

Existing journal request-capture, topic exclusion, live-round isolation and
proposal tests are useful regression coverage, not tests of an unbuilt vault.
Native mobile, screen-reader and stale-session vault acceptance remain unverified.
