## Audit findings

- `server.ts` `/api/votes` resolves browser identity, replaces votes by proposal ID, deletes `withdrawVotes` entries and persists the shared database. `dashboardState` reads that same map. `src/engine/demo.ts` `demoPayload` counts browser choices separately from illustrative responses, but includes every matching persisted browser choice. Synthetic test votes would affect those public browser totals.
- `src/server/launch-stats.ts` records successful stance submissions as daily participation. Its published contract explicitly says withdrawals do not erase participation and automated submissions cannot be distinguished from human submissions. A create/change/withdraw sequence could contaminate metrics even after current counts return to baseline.
- README public-write guidance and `src/server/public-security.ts` require signed anonymous cookies, exact origin checks and rate limits. Production uses Secure, HttpOnly, SameSite=Lax cookies; Fly proxy trust matters. Handler mocks and local HTTP tests cannot establish real browser HTTPS cookie behavior.
- `src/client/WorkflowScreen.tsx` submits through `src/client/advisory-mutation.ts`. That helper sends explicit stance upserts, not `withdrawVotes`; clicking the selected stance cannot establish withdrawal through this helper. The server withdrawal API alone does not establish the requested `/votes` UI lifecycle.
- The helper retains a viewed text revision in a browser receipt, but its POST contains proposal ID and stance without that revision. This is not evidence of server-enforced advisory wording revision binding. Existing repository PR head/base voting is a separate system and must remain isolated.
- Existing `scripts/proposal-selection.test.tsx` checks selection without writes, pending acknowledgement, failed submission/retry and restored selection using injected requests and Happy DOM. `src/client/advisory-mutation.test.ts` checks receipt/retry behavior; `src/server/public-security.test.ts` checks cookies, origin and validation, including replacement through the separate citizen-proposal handler. These are useful component checks, not production end-to-end acceptance.
