## Reproducible lab

Install root dependencies with `bun install --frozen-lockfile`, then
`npm install --prefix tests/performance --ignore-scripts --package-lock=false` and
`cd tests/performance && npx playwright install --with-deps chromium`.
Run `bun run test:vitals` at root. Playwright is pinned by the existing performance
package to 1.56.1. CI uses Ubuntu 24.04, Node 22 and Bun 1.4.2.

Each of `/`, `/feed`, `/votes` gets three serial cold contexts, 390×844 touch/mobile,
4× CPU slowdown, 150 ms network latency, 1.6 Mbps download / 750 kbps upload.
These are a fixed mid-tier mobile approximation, not a calibrated physical phone.
Default motion remains enabled. Cache and service workers are disabled.
Production-minified code runs via the existing disposable QA server. Only GET/HEAD
requests to fixed loopback are allowed; external services and writes are blocked.
No public-site traffic, telemetry, voter inference or production storage is used.

Every individual run has budgets LCP <=2500 ms, CLS <=0.1 and interaction proxy
<=200 ms. Missing LCP or unsupported APIs fail measurement. LCP is observed before
interaction after a fixed five-second load window; late content beyond that window
is not covered. CLS uses maximum session windows (one-second gap, five-second cap),
excluding recent-input shifts. A real touch activates the visible theme control;
Event Timing's maximum qualifying interaction duration is the lab INP proxy.
No events above the 16 ms observation floor means below-floor observation, not zero
latency. This single interaction does not establish full-session or field INP.
Search, vote allocation, heavy map routes and proposal-detail deep links need
separate reviewed scenarios before claiming site-wide coverage.

Artifacts include per-run DevTools timeline JSON, Playwright trace ZIPs, browser
version, source HEAD, profile, raw Event Timing and route metrics in summary.json.
Failures also produce failure.json. CI retains artifacts for 14 days. Download them
for durable review evidence before expiration. Local environment differences must
be recorded; compare only the same runner/browser/profile. The server build occurs
before navigation and is not counted as page latency.

Metric references: [LCP](https://web.dev/articles/lcp),
[CLS session windows](https://web.dev/articles/cls),
[lab interaction diagnosis](https://web.dev/articles/manually-diagnose-slow-interactions-in-the-lab).

## Staged rollout and exceptions

Stage 1 adds a separate report-only CI job. The measurement command exits nonzero
on any budget breach; the CI measurement step explicitly continues on error and
records its outcome. Missing artifacts fail upload. This stage is an exception to
blocking on budgets, not an exception to the thresholds. Owner: human maintainer;
review after five successful comparable CI runs, before promotion/release.
No numeric route exceptions are granted. Never raise thresholds to clear a failure.

Stage 2 requires a human to review traces, resolve breaches and missing-route
coverage, then remove report-only handling and configure the check as required.
Record any future exception with route, metric, observed value, reason, owner,
issue, expiry and removal criteria. Rollback is removal of this new job/harness;
no application changes or data migrations need reversal.
