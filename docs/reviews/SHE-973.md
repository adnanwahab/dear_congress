The browser previously collapsed map resource, initialization and timeout errors
into one fallback. Needs geographic fetch failures silently appeared as empty
cells. /healthz remains process liveness, not dependency readiness.
GamePatches already displays repository-scoped sourceStatus, stale, lastSync,
warning and integration state. LawBehaviorExplorer explicitly cannot verify a
cross-origin world handoff. These observations are different kinds of evidence.

## Local changes

Map status now retains a last successful browser-render timestamp and sanitized
failure category. A resource failure does not establish a provider outage:
connectivity, CSP and provider problems remain possible. Initialization failure
is identified separately. Timestamp scope is the mounted view and map style;
reload discards it. No credential-bearing provider URL or raw error is displayed.

Needs now distinguishes aggregate API failure from an empty successful response,
rejects missing cells arrays, times out after ten seconds and cancels obsolete
requests. Its last-success timestamp means a local aggregate response, not a
successful external source refresh. Geographic data stays separate by existing
real/simulated mode. The panel identifies GitHub as unchecked in this view and
world loading as unverified rather than asserting green status.

## Remaining acceptance work

This is a partial implementation, not an operational monitoring system. Keep
SHE-973 open. Independent provider/source probes, durable per-dependency last
success, scheduled stale detection and delivered dependency alerts are absent.
The browser cannot distinguish provider outage from a blocked network request.
A configured provider probe must use reviewed fixed targets and redact secrets;
style HTTP success alone cannot prove tiles, glyphs, sprites or rendering work.
Source refresh monitoring must preserve each source's identity and distinguish
cached fixture reads from upstream fetch success. GitHub observations must stay
scoped by repository and item kind; a cached 200 is not a successful GitHub sync.
External world health needs explicit evidence from its own service; link clicks
must never count as load or simulation success. Alert routing and delivery need
operator setup and human receipt evidence as described in docs/launch-alerts.md.
No live outage cause or deployed revision was established by this work.
