## Implemented scope

The existing validated paired receipt supplies two exhibits: hypothetical current
rules and edited law. A single receipt binds model version, seed, population,
time horizon and checkpoints. These are law-model branches, not outcomes of the
visitor's package or sample proposal. No cross-run comparison is introduced.
Thumbnail dots use one shared metric scale and recorded checkpoints; missing
values remain unavailable. There is no fabricated image, forecast or preference
ranking. Order and the edited-minus-current metric methodology are declared.

Hover and keyboard focus preview final-checkpoint summaries. Native toggle
buttons also support touch. Selecting both opens existing synchronized time,
metric, actor and chart comparisons; deselection hides them and stops playback.
Rerun/input changes clear the gallery and selection. Receipt source/provider,
model version, parameters and limitations remain visible before comparison.
Loading, cancellation, timeout, failure, retry and stale-response rejection reuse
the existing request lifecycle. No request occurs on hover or selection.

Outcomes in the six-stage UI links to /synth with an explicit separate-model
notice. It deliberately does not transfer sample proposal identity to the law
sandbox. Public-guide copy explains this boundary. Selection stays in memory;
no new cookies, storage, journal inference, publication or model inputs.

Cards stack below 440px and use existing visible keyboard focus treatment.
There is no gallery animation or autoplay, including under reduced motion.
Actual browser mobile/reflow, screen-reader and reduced-motion verification
remains for human review; DOM tests do not establish that acceptance matrix.
