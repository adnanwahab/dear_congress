# SHE-348 — shared topic identity

Refs: https://linear.app/shel-bernstein/issue/SHE-348/demo-give-each-topic-a-color-and-icon-used-on-every-page

Implementation candidate; human acceptance remains outstanding.

Read AGENTS.md, readme.md, docs/source-recovery.md and
docs/launch-merge-policy.md; audited demo fixtures, Needs catalog, workflow,
dashboard, sponsor persistence, search and CSS. Inspected existing PR #77
(SHE-332, shared visual system) and #87 (SHE-324, proposal motion) through GitHub
read-only tools. Both touch these screens; integration must retain their header
and title/detail transition changes alongside these chips. No existing SHE-348
PR appeared in the topic/issue search.

src/shared/topics.ts owns the eight topic IDs, labels, opaque colors and inline
SVG path definitions, explicit need-label mappings and legacy sample-card
mappings. TopicChip renders the same name, icon and color on Feed, Published,
home, Votes, Draft, Sponsors and Outcomes. Needs rows retain their original need
labels with a chip for known mappings; ambiguous labels remain unmapped.
Sponsor/outcome topics resolve from the loaded proposal's exact ID, with explicit
legacy sample fallbacks. Existing saved cards are neither rewritten nor migrated.
Unknown IDs remain untagged rather than being guessed from their titles.

The topic filter retains the native select and adds keyboard-accessible chip
buttons with aria-pressed; both update the same local filter state. Chips expose
`view-transition-class: topic-chip` for motion integration without assigning
colliding transition names to repeated chips. SHE-324's incoming-snapshot and
selected-proposal motion behavior still belongs to its separate change.

The opaque topic colors and white text are independent of surrounding light/dark
surfaces and the SHE-332 blue content accent. All eight pairs exceed WCAG AA
4.5:1. SVGs are decorative; the visible topic names provide accessible identity.
CSS explicitly protects chip text from existing sponsor and metadata selectors.
