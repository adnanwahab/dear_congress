## Implemented bounded prototype

Outcomes displays a separate evidence docket even while proposal data loads or
fails. Public examples bind exact claim ID, revision, source locator, date and
limitations to new evidence, requested correction, decision rationale, material
revision history, human-review state and an appeal path. The fully sourced case
is sourced to the repository's synthetic fixture, not real-world primary evidence.
Conflicting metrics and missing observations remain explicit. All four evidence
categories are explained; no real primary-source case is invented.

Users can prepare a validated local draft, inspect it and export the docket as
plain text. Copy text remains available if download APIs fail. Print CSS exposes
the full text, including draft and history. No network request, local storage,
submitter identity, private note, vote or source mutation occurs. Drafts are lost
on reload. Example acceptance is explicitly demonstration-only. The public guide
links to the docket and states those limits.

## Remaining acceptance

This is not a live formal moderated pathway. Durable authenticated intake,
private contact storage, public/private projection, moderator authorization,
append-only signed decisions, independent appeals and reviewed real primary-source
cases remain to be designed and implemented. Existing source data, repository and
item-kind isolation, PR head/base bindings, votes, records and receipts are untouched.
No claim changes are applied automatically. Reconcile the proposed EvidenceClaim
contract with #175 before shared-schema integration.

Native keyboard-only, touch, screen-reader, narrow-screen and actual browser print
review remain unperformed. DOM tests verify native labeled controls, public text,
validation, no-service draft preparation, export contents and download-error
fallback; they do not establish native accessibility acceptance. Docket records
are bundled synchronously, so there is no separate remote docket loading state.
