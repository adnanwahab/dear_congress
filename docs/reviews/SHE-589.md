# SHE-589 implementation review

Refs: https://linear.app/shel-bernstein/issue/SHE-589/civicplaymotion-civic-house-orbitable-3d-home-for-the-six-civic-stages

## Audit and scope

Read repository README, motion foundation and launch merge policy. Relevant GitHub
PR searches for `repo:adnanwahab/dear_congress "Civic House"` and
`repo:adnanwahab/dear_congress SHE-589` returned no matches during this work.
The existing six-stage registry, WorkflowScreen, Navigation, typed transitions,
native chapter links and `/api/demo` remain the source of navigation and samples.
This is implementation work, not an analysis-only acceptance recommendation.

The optional foyer is `/?house=1`, linked from the existing utility navigation.
Its flat grid is the default. An explicit CSS perspective mode offers a native
range input for touch and keyboard orbit, without a WebGL dependency or continuous
render loop. Both modes expose the same six semantic articles, previews and links.
Reduced motion and motion-off disable the spatial switch; forced colors remove
transforms. Mode switches reuse the typed `filter` transition; chapter links reuse
the existing stage morph helper and native navigation. Navigation does not wait
for a preview request or animation. Unmounted preview requests cannot commit.

Previews use the existing API's fictional proposal fields and synthetic tallies.
Possible offices are not confirmed sponsors; outcomes explicitly state no verified
outcome. No visit/progress tracking, public write, source remapping, vote blending,
tracker update, repository binding change or production data migration is added.

Stage exits save only a validated same-origin stage URL and focused element ID
in sessionStorage. Query/hash context survives; other origins, different stages
and live-round URLs cannot become saved room destinations. Storage failures fall
back to ordinary links. Focus restores existing IDs; elements without IDs fall
back to the stage heading. This is a documented limitation, not restoration of
private draft text or all transient in-page form state.

## Validation

- `bun run typecheck`: passed.
- Focused house/navigation/motion/transition run: 11 passed. The house integration
  test additionally covers saved focus, URL binding, failed preview/retry and
  read-only requests (15 house assertions in the final focused run).
- `bun test`: 476 passed, 26 failed. The failures occur in server-starting tests
  with local socket bind errors (`EADDRINUSE`, including ephemeral port 0).
  The heading contract was updated for the accessible focus target and passes.
- `bun run test:routes`: attempted; blocked at Bun server socket bind with the
  same `EADDRINUSE` error before route assertions could execute.
- Browser success/failure tests added in `tests/accessibility/civic-house.pw.ts`,
  using the existing isolated production browser harness and all configured
  desktop/mobile/reduced-motion/contrast/reflow projects. They check navigation,
  focus, retry, axe findings, overflow and absence of writes. Not executed here:
  Playwright is not installed; a dependency install could not complete in the
  restricted environment. `npm test --prefix tests/accessibility -- --grep house`
  reports `playwright: command not found`.
- `git diff --check`: passed.

Before acceptance, run all required checks and browser tests in an environment
with local sockets and installed browsers, visually review both layouts, and
complete the repository's manual screen-reader/touch journey. Native back,
interrupted navigation, blocked storage and changing reduced-motion preferences
also need actual browser review. No claim of full accessibility acceptance is made.

## Governance preserved

No governance configuration was edited. Existing documented source defaults remain
merge disabled/dry-run, quorum 10, 24-hour exposure, current-head approval/checks,
protected-base evidence and active default kill switch. Advisory browser votes
remain separate from verified authority. Human approval and required `bun test`,
`bun run typecheck`, `route smoke test` checks remain required; production releases
require a human-published tag. Live protections/environment were not verified or
modified. No merge, deployment, release, external message or Linear state change
was performed. This work remains a review candidate; the issue stays open pending
human acceptance.
