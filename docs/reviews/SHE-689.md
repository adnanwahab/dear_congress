## Proposed implementation contract

Implement an additive circle service with server-enforced membership before
adding entry points to the three components. Define the participant credential
and recovery model explicitly: either a properly isolated browser capability
with disclosed loss/recovery limits or an authenticated principal. Do not borrow
repository GitHub membership as civic-circle authority. Persist separate circle,
session, membership, consent, artifact, grant, report and audit records; existing
journal, proposal, voting and governance collections remain intact.

Bind each circle to source repository identity, item kind, item ID and immutable
revision/snapshot where applicable. Never resolve an ID against another source
kind. Keep PR head/base bindings unchanged. A source revision change requires
explicit review rather than rebinding existing minutes silently.

### Scope and permission rules

| Visible scope | Read permission | Sharing behavior |
| --- | --- | --- |
| Personal | Creator only | No discovery or participant roster; explicit reviewed grant needed to share a selected artifact |
| Invite-only | Active, consented members for artifacts expressly granted to the circle | Single-use expiring invitation, bound to circle and intended participant; invite acceptance does not publish anything |
| Public | Anyone for artifacts explicitly published as public | Public circle shell does not make drafts, roster, reports or minutes public automatically |

Always display both circle scope and artifact audience in text. Default new
artifacts to personal. Grant creation must show exact artifact revision, audience,
what will be exposed and a confirmation; changing circle scope must not broaden
artifact grants. Each contributor authorizes publication of their attributed
contribution; a facilitator cannot consent on their behalf. Mixed-consent minutes
must omit unconsented contributions and identify omissions without revealing text.
Keep consent purpose, artifact revision, audience, policy version, principal and
time; no prechecked consent. Explain that revocation blocks future hosted access
but cannot recall downloaded copies.

Enforce authorization on list, detail, mutation, export, source previews and event
streams. Use no-store projections; never return private fields and hide them in
CSS. After leave, removal or consent/grant revocation, deny subsequent reads and
exports, invalidate outstanding invitations and close relevant streams. Omit
unauthorized artifacts from public topic counts, previews and search. Public
metadata must not reveal invite-only circle existence or member identities.

### Sessions and rotating roles

Participants join expressly, then choose whether to accept facilitator,
fact-finder or skeptic assignments for each session. Rotate among eligible,
consenting active participants; support skipping/declining and small groups with
vacant roles. Display responsibilities, current assignment, next proposed
rotation and acceptance status. Facilitating, investigating and questioning grant
no extra voting weight or moderation authority. Keep moderator permissions
separate and server-enforced; departing facilitators leave a visible vacancy.

Use a versioned shared source checklist: claim/question, original source identity,
URL and locator, access date, excerpt/revision, uncertainty, counterevidence and
review state. Preserve originals and label unavailable or unverified sources.
Do not fetch arbitrary user URLs or copy private/held journal content implicitly.
Minutes record session date, agreed wording, unresolved questions, source links
and accepted role assignments. Export JSON plus readable minutes only after an
authorized, deliberate action; include scope, revision and provenance labels,
exclude credentials, private reports and unpublished contributions. Escape text
and avoid executable HTML in exports. No automatic journal or proposal publication.

Use expected record versions for role changes, consent, minutes and grants;
reject stale writes with 409 and require refresh/reconfirmation. Pair bounded
idempotency keys with principal, circle, action and payload to make retries safe.
Check membership again at commit/export time. Persist atomically using the
existing single-writer conventions, roll back failures and survive restart.
Audit successful changes with actor reference, target/revision, action, timestamp
and reason without exposing tokens or private report text in public history.
Define retention and deletion policy before enrollment; revocation must also
suppress derived excerpts and public history that would expose withdrawn text.

Members can leave, revoke their grants/consent and report from the artifact.
Moderators can freeze a session, remove a member or hide an artifact with a
reason and private review receipt; restoration and appeals need an explicit
review path. Extend typed report targets without changing existing journal
reports. Reports alone must not suppress content automatically. Keep reporter
identity and evidence private to authorized reviewers. A removed member must
still have an appropriate way to report abuse without regaining circle access.

Start empty. Any optional walkthrough must be a separate, visibly synthetic
fixture lane: label every attendee/message and exported fixture as synthetic;
exclude it from real member counts, minutes, source claims and participation
metrics. Never imply that a demo character accepted consent or attended.

### Integration sequence

1. Build the durable service, credential model, ACL projections, revocation,
   moderation and audit tests before enabling invitations.
2. Add a circle entry on citizen proposal detail bound to that exact source;
   leave public comments and advisory responses independent.
3. Add an optional circle-session link to LiveRound after authorization; keep
   round expiry and voting independent. A round must not export circle minutes
   or turn role assignment into votes.
4. Topic hubs may list only explicitly published circle artifacts with valid
   source/consent grants. Preserve current human-journal exclusion and sample
   labels. Update public-guide privacy wording with actual shipped behavior.

## Acceptance evidence still required

All circle-specific acceptance criteria remain unmet by this analysis.

| Required test group | Concrete checks |
| --- | --- |
| Permission denial | Stranger, pending/expired invite, removed member and nonmoderator attempt every read/write/export/stream; reject forged role, principal, cross-circle and cross-source IDs; assert no private sentinel leaks |
| Scope and consent | Distinct personal/invite/public UI; no inherited sharing; no preselected consent; one artifact grant cannot expose another revision; leave/revoke blocks future reads and derived excerpts |
| Stale sessions | Expired credential, revoked grant during export, delayed response after navigation, concurrent rotations, stale minutes and restart; fail closed, clear private UI, preserve earlier records and offer deliberate refresh |
| Roles and provenance | Declined/vacant roles, small teams and repeated sessions; synthetic fixtures never count as real; source IDs and unresolved disagreements survive export |
| Moderation and audit | Unauthorized actions denied; hide/freeze/remove/reinstate records reason; reports private; lost-response retry, disk failure and restart preserve receipts and history |
| Voting isolation | Snapshot journal/proposal responses, repository ballots, PR head/base bindings and receipts before/after the complete circle journey; demonstrate no change |
| Accessibility and mobile | Keyboard role selection, labelled consent/scope controls, focus on denial/dialog close, announced errors, screen-reader minutes, 390px reflow, 200% zoom, contrast and reduced motion; record actual browser and human review evidence |

Use disposable local data only. Run full repository checks and targeted HTTP,
persistence and rendered UI tests after implementing behavior. Existing screenshots
of home/votes are not circle-specific evidence. Automated DOM checks alone do not
establish accessibility acceptance; follow docs/accessibility-acceptance.md.
