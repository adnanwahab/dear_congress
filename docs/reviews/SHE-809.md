# SHE-809 — public read-only launch fallback

Refs: https://linear.app/shel-bernstein/issue/SHE-809/cs-l100019-create-a-safe-read-only-launch-fallback-switch

Implementation candidate; human acceptance and staging HTTP drill remain pending.
No issue transition, external message, PR publication, deployment or merge.

Audited repository instructions, readme, launch merge policy, repository voting,
server route wrappers, public security, client mutation handling and public guide.
GitHub searches found no SHE-809 PR and identified related PR #316 (SHE-949).
Inspected its diff: analysis-only proposed degradation specification, not a
working switch. This implementation covers the narrower public HTTP write fence;
it does not claim the whole-system cached/offline L3 mode specified there.

`LAUNCH_READ_ONLY` is owner-only startup configuration, default off and fail-closed
for unknown nonempty values. The outer API wrapper gates object and function
handlers before validation/extraction/moderation/persistence, including journal
aliases, live votes and revision-bound repository ballots. Rejections are 503
with stable `writes_paused`, no-store and Retry-After; nothing is enqueued.
HTML notice stays outside the React root. Existing reads, sample provenance and
source links are retained. Public guide describes rejected/unsent work truthfully.
No data schema, vote identity, source scope, PR head/base binding or receipt is
changed. Existing draft retention behavior is unchanged.

Owner enable/disable, drain, all-instance restart, reconciliation and compatible
image rollback are documented in `docs/launch-read-only.md`. Already admitted
operations must drain before activation; restart is not an instantaneous fleet
fence. Background jobs and GET side effects continue. Do not describe this as
zero storage writes or a background-publication kill switch. Browser controls
remain usable for local exploration; server writes receive the visible pause
error. Previously loaded tabs learn of the pause on their next mutation/reload.

Preserved governance: disabled/dry-run defaults, quorum 10, 24-hour exposure,
current-head review, fail-closed allowlists, active kill switch and advisory lock.
No runtime policy or branch protection configuration changed or verified. Human
approval and all required checks still apply. No production records were touched.

Validation: restored dependencies with `bun install --frozen-lockfile` (no lockfile
change). `bun run typecheck` passed. Focused switch tests: 3 passed, 38 assertions.
`git diff --check` passed. Both `bun run test:routes` and the new isolated
`bun scripts/smoke-read-only.ts` fail at Bun listen on port 0 (`EADDRINUSE`) in this
sandbox, before HTTP assertions. The new smoke covers mutation aliases, repository
ballots, unchanged state/file contents and readable pages with the notice; rerun
in an environment permitting server sockets. Full-suite result recorded below.

Remaining: required checks must pass, staging owner activation/recovery and
