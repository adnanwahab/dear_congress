## Implemented slice

MapScreen retains civic navigation and its county model and adds a separate,
opt-in, clearly fictional neighborhood project explorer. A schematic map and
native numbered selection buttons expose the same project selection without
hover, canvas, external tiles or geolocation. Records carry distinct project and
evidence IDs/revisions, publication and observation dates and demo provenance.
Milestones and implementation intentions cannot imply completion. The selected
project shows observed example work separately from forecasts and distinguishes
explicitly paused work from unknown status. An illustrative 30-day age rule uses
the pinned snapshot date and observation date, never page load or publication.
Old evidence remains visible. No record is represented as verified.

Correction rehearsal validates the selected project/evidence pair and HTTPS source,
appends a pending item bound to both revisions, and never changes the underlying
records. Invalid corrections retain their text. Text and unreviewed URLs are rendered
as escaped text, without executing user markup or linking an endorsed source.
The queue survives project selection and disclosure changes, but is page memory
only and is cleared on reload. The form explicitly requests fictional text and
states that nothing is delivered to a real moderator. No network or browser storage
write, API, production-data change or data migration is introduced. The guide and
README describe these limits.

## Acceptance still open

This is a demo interaction slice, not full delivery of the issue. A human must
verify remaining requirements before closing SHE-467:

- Choose real project sources and jurisdiction coverage with permission to retain
  source revisions; register implementation documents and published milestones.
  Require archived exact-source claims, reviewer identity, reviewed timestamp,
  observation date and corrections history before displaying verified updates.
- Build a durable, authenticated and rate-limited correction intake with typed
  API contracts and tests. A resident submission must stay pending; only a separate
  authorized review can publish a new fact revision, retaining originals and
  earlier correction receipts. Do not repurpose journal votes as verification.
- Supply reviewed real coordinates and a map projection with an equivalent list;
  the fictional schematic conveys no real geography. Review project-specific
  freshness expectations rather than reusing the illustrative demo threshold.
- Add loading, partial-source and failure/retry checks when asynchronous sources
  are introduced. Current fixtures load synchronously with the bundle; no spinner,
  artificial network loading or fake verification service is shown.
- Verify native keyboard, touch, reduced motion, 390px reflow, actual 200% zoom,
  forced colors and screen-reader reading order against this revision. Native
  buttons, form controls and details support keyboard operation; controls have
  44px minimum height and visible focus. The new section adds no motion, timers,
  auto-advance or animation. DOM tests do not prove native input or layout acceptance.
