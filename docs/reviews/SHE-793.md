# SHE-793 advisory receipt review candidate

Refs: https://linear.app/shel-bernstein/issue/SHE-793/cs-l100004-give-every-advisory-choice-an-explicit-savedfailedwithdrawn

## Audit and scope

Read repository AGENTS.md, readme.md, launch merge policy, the SHE-402 receipt
review and vote modules. Inspected current GitHub PRs and patches for #353
(SHE-863 receipt export), #383 (SHE-798 next steps) and #385 (SHE-796 production
smoke analysis). These remain separate open candidates; this change does not
assume their implementation or acceptance. #353 and #383 overlap the receipt,
workflow, guide and test files and require integration review before merging.

The sample-proposal flow at `/votes` already waited for `{ok:true}`. It lacked a
withdraw control and acknowledgement time; a failed replacement could leave the
previous saved receipt showing. This candidate renders the attempted proposal,
option and pending/failed status immediately, and stamps Saved or Withdrawn only
after explicit acknowledgement. Failure says outcome unknown, because a lost
response can follow a successful write. Retrying preserves the exact proposal
and action, including withdrawal, through the existing mutation lock, timeout,
rate-limit and best-effort session recovery path. There is no automatic retry.

Withdrawal uses existing `/api/votes` `withdrawVotes` semantics; no server,
schema, identity, auth, tally or production data change is introduced. Saved
receipts include browser acknowledgement time, explicitly not server commit
time. Older receipts say unknown. Acknowledgement history may be superseded by
later changes; the UI makes that limit explicit. The viewed-text fingerprint
remains local and non-cryptographic, not a server-bound revision. Cookie choices
do not establish unique people, eligibility, turnout or official authority.
Change vote focuses the options; copy failure keeps selectable text available.
README and public guide describe the statuses and trust limits.

This implementation extends the existing sample `/votes` receipt. Dashboard,
live-round, citizen-proposal and repository-community controls are separate
flows and have not been migrated to this receipt component. No claim is made
that every participation surface now satisfies these criteria. Human scope
review is required before closing this issue.

## Validation and remaining gates

- Focused mutation, receipt, proposal-selection and public-guide tests: 16 passed,
  zero failed. Includes all three stances, pending, missing acknowledgement,
  withdrawal request/retry, reload recovery, copy denial, focus, reduced-motion
  rendering and explicit browser caveats.
- `bun run typecheck`: passed.
- `bun test`: 765 passed, 26 failed; failures report local server startup
  `EADDRINUSE` on port 0. This run preceded the final formatter regression test
  and storage-input validation, which passed in the focused run.
- `bun run test:routes`: failed at the same socket startup boundary.
- `git diff --check`: passed.

Required server checks must pass in a socket-capable environment. Native browser
visual, touch, keyboard and screen-reader checks remain outstanding. DOM tests
are not production verification. No production choice, withdrawal, fixture,
message, deployment or merge was performed. Production lifecycle writes would
violate this task's no-production-data-change constraint; no safe excluded smoke
namespace has been established (see #385). Leave Linear open pending human
acceptance; this candidate is not ready to ship on the present evidence.
