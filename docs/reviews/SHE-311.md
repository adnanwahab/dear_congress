## Current Dear Congress flow and gaps

Source walkthrough (not an executed browser walkthrough): `/synth` selects
`SynthView` in `src/client/App.tsx`. Real-voice package cards mount
`SimulateRealities`; settings default to 100 futures, 10 years and seed 42.
Creating a link posts a package identifier to `/api/simulation-snapshots`.
The server recomputes real-only synthesis, freezes one package, stores it, and
returns an HBL `/world?simulation=…&runs=…&years=…&seed=…&autorun=1` URL.
Users can copy that URL or edit its workload settings. The quick summary instead
uses `/world/plan.html` with proposal IDs and costs; it is a distinct contract.

| Requested evidence | Present source | Remaining gap |
| --- | --- | --- |
| Two immutable policy packages | `simulation-snapshot.ts` freezes one package without advancing stored plan history | No atomic A/B comparison manifest. Server recomputation may differ from the package currently displayed after custom weights/budget changes. |
| Same inputs, seed and model version produce same result hash | URL accepts an explicit seed | Snapshot uses random ID/time, has no model version or result hash. `/api/plan` has a package-content `planHash`, but is a live read-only export (`storedSnapshot:false`), not a simulation result hash. |

National illustrative cost units must not become city fiscal estimates without a documented conversion. |

`SimulationSnapshot` schema v1 is a partial policy export, not a complete executable
model input. It has no journal text, but retains an entry ID and derived needs.
Both public snapshot responses force `location:null`; journal deletion also clears
stored linked location. Preserve this privacy behavior. An opaque ID is not an
authorization mechanism and derived needs/source linkage still require review.
Do not add private journals, coordinates, identities, ballots or raw DB exports
to a comparison URL or provenance bundle.

## Bounded post-launch pilot proposal

First agree the integration contract with the receiving model owner; no external
implementation is claimed or authorized by this report. Dear Congress can later
provide a versioned, privacy-reviewed comparison export capturing both selected
packages atomically from one input state, including the actual synthesis settings.
Preserve old snapshot URLs and existing stored records. Do not silently substitute
current packages when an old comparison is unavailable.

The manifest should distinguish content identity from random storage ID/time:
canonical public input bytes, ordered A/B content digests, source repository/revision,
schema/model versions, measured-data source dates/digests, units, assumption set,
100 explicit run seeds and horizons [1,5,10]. Specify canonical serialization,
numeric precision, PRNG and quantile algorithm before promising stable hashes.
Version any change affecting results. Hash canonical results independently from
timestamps, transport IDs and presentation metadata. Keep identical per-run random
draw identities across worlds even when policies alter execution paths.

An assumption edit should create a new comparison revision with exactly one named
assumption changed and retain both original policy inputs. Unsupported metrics,
missing data and failed runs need explicit unknown status and reasons. Show valid
sample counts and paired deltas alongside separate medians/p10/p90; do not imply
a difference of medians is the median paired effect. Separate measured baselines
from modeled outcomes and show “simulation, not forecast” and advisory-only status
on the comparison and share/replay views. Define retention/export and unavailable
model-version behavior before describing a link as durably replayable.

Start with one synthetic, privacy-reviewed A/B fixture and 100 paired runs. A text
table must remain usable without GPU rendering; any CPU execution alternative
must pass the same deterministic vectors or clearly declare a distinct model
version. If computation is unavailable, explain it without fabricating results.
Expand only after a real pilot participant can choose two packages, understand
uncertainty, inspect sources, change one assumption, share and replay the result.

## Validation and acceptance handoff

Existing snapshot fixtures in `server.simulation-snapshots.test.ts` cover no-entry
creation, package IDs/unknown names, missing snapshots, no text/coordinate export,
unchanged plan history, invalid settings, workload caps, seed zero and maximum seed.
They do not test model determinism or A/B results.

Future representative and edge fixtures must cover identical A/B (zero paired
delta), repeated/reordered canonical inputs, seed 0/max, changed seed/model/input,
restart/replay after live policy changes, missing/evicted snapshots, unavailable
model versions, unknown metrics, partial/all run failures, quantile ties and small
valid sample counts. Verify identical seed/draw schedules for all 100 pairs,
single-assumption edit enforcement, concurrent package capture, provenance units,
and privacy redaction after journal deletion. Preserve revision-scoped votes and
repository/item-kind isolation with regression checks.

Product walkthrough still required: keyboard-only selection of A/B, create/run,
inspect all five metric groups at each horizon, distinguish unknown/measured/modeled,
edit one assumption, copy/open a link in a fresh session and verify hashes. Check
labels, focus/error announcements, semantic table headers, non-color uncertainty
cues, readable mobile layout/zoom, screen-reader output and no-WebGPU rendering.
