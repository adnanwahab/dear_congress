## Proposed data and authorization contract

1. Add a versioned community session and immutable decision-artifact store without
   migrating or rekeying existing proposals, ballots, objections or receipts.
   Bind every artifact to a source namespace, item kind, stable source ID and
   exact revision/text hash. Repository references also retain exact repository
   identity and PR head/base; issues cannot acquire PR merge authority. A local
   amendment snapshot is not a published revision.
2. Capture considered options individually, including retained/rejected/deferred
   outcomes and explicit reasons. Record source title, URL, locator, excerpt or
   version, supplied date and verification status. Unverified sources remain
   unverified; never infer factual support from a link. Collect explicit
   objections, open questions and reviewer decisions as separate linked records.
   Each reviewer decision identifies the exact revision, authority basis, reason,
   decision status and unresolved dissent. No response means unknown, not assent.
3. Record contribution origin explicitly at creation: human attributed, human
   anonymous, demo or synthetic. Named contributions require specific attribution
   consent for the chosen artifact/audience; self-described names are labelled
   unverified. Public projections omit private actor identifiers. Keep anonymous
   contributions in a separate section without cross-artifact identity correlation.
   Demo and synthetic content must be visibly separate and excluded from real
   contributor counts and reviewer authority. Do not generate fictional attendees.
4. Default artifacts to personal. Make Personal, Invite-only and Public visible
   as text on the artifact, edit form, sharing preview and export. Session scope
   is an upper bound; joining a session never widens an artifact's audience.
   Require explicit per-artifact consent before sharing or widening scope.
   Invitations need intended-recipient validation, expiry and revocation. Enforce
   read, write, correction, sharing and moderation permissions on the server for
   detail routes, lists, search, exports and streams, including guessed IDs.
5. Separate contributor, reviewer, organizer and moderator capabilities. A
   reviewer may append a reasoned decision, not erase an objection. An organizer
   cannot publish someone else's personal material. Neither browser votes nor
   a session role grants repository voting, code approval or merge rights.
   Preserve existing signed-cookie, same-origin, bounded-input and rate-limit
   controls; shared identity and CSRF requirements need explicit implementation.
6. Persist each action and audit event atomically with stable event ID, server
   sequence/time, private actor reference, source revision, prior version and
   permission version. Require expected-version checks and idempotency keys;
   stale/conflicting writes fail without retargeting or losing input. Serialize
   persistence under the existing single-writer model; failed saves roll back.
   Corrections append superseding events and keep prior decisions available only
   to appropriately authorized reviewers. A restricted audit is not a public feed.

### Corrections, departure and moderation

Provide Request correction beside each contribution/decision. Authors can correct
their own wording with an appended version; other participants can submit a
private correction request. Authorized review records accepted/declined/pending
outcomes and a reason, linking both the corrected artifact and superseded event.
An objection author controls their own withdrawal; reviewer decline must never
silently mark it resolved. An accepted objection requires an exact resulting
published revision before claiming that it changed the proposal. Open questions
remain explicit until an authorized response supplies an answer or records unknown.

Provide Leave session, Revoke sharing, Withdraw attribution and Report controls
with distinct consequences. Leaving removes future invite-only access without
pretending past disagreement disappeared; retained records follow their current
sharing/retention policy. Owners need an authorized management route for their
artifacts after departure. Revocation stops future authorized reads, exports and
stream deliveries, with revalidation clearing displayed private content. Public
copies already downloaded cannot be recalled; explain that before publication.

Reports enter a bounded private moderation queue with restricted actor/reason
records. Moderators append hide/restore decisions and reasons, preserving source
identities and receipts without publicly retaining withdrawn text. Do not expose
reporter identity, private counts, titles or audit payloads to unauthorized viewers.
Submitting a report does not grant access or automatically suppress disagreement.
Define retention/redaction for sensitive content before a real-group pilot; an
append-only ledger must not become indefinite public storage of personal data.

## Integration in the requested surfaces

- `CitizenProposals.tsx`: expose the log only through an authorized source/revision
  binding. Show choice rationale, considered options, sources, open questions and
  unresolved dissent next to the exact chosen revision. Existing public comments,
  objections, proposal text and vote totals retain their current contracts. No
  automatic import of browser drafts or inferred consent from publication.
- `LiveRound.tsx`: link to a log only when an explicit authorized session/artifact
  binding exists. Current demo rounds stay advisory and temporary; do not derive
  attendees or decisions from voter hashes, counts, pulses or round termination.
- `TopicHubs.tsx`: discover only explicitly public artifacts with topic-curation
  consent. Exclude personal/invite-only records from results and counts. Keep
  fictional examples and human contributions visibly distinct; topic similarity
  does not establish provenance or group endorsement.

Render a semantic ordered decision history with headings, readable timestamps,
text scope/status labels and stable authorized source links. Show attributed and
anonymous contributions separately, with an additional clearly labelled demo lane.
Summaries must retain minority objections and unresolved questions; never label
an organizer's selection unanimous or imply governmental adoption.

Use no-store responses for private/session-dependent projections. On permission
denial, logout, expiration or session switch, clear old content, cancel in-flight
loads and reject late responses. Recheck authorization on every stream emission,
reconnect and export; joining once is insufficient. Stale offline edits cannot
widen sharing or be replayed into another revision. Do not put private content in
URLs, public analytics, indexes or service-worker caches.

current-head approval, strict yes majority, fail-closed empty base/check allowlists,
