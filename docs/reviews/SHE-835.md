Refs: https://linear.app/shel-bernstein/issue/SHE-835/cs-l100025-add-privacy-preserving-distribution-attribution-without

Implemented locally; human acceptance and deployed verification remain pending.
No deployment, production writes, external messages, merge or issue-state change.

## Audit and scope

Read repository instructions, README metrics/privacy sections, launch merge policy,
launch metrics HTTP/store and client request paths. GitHub PR searches restricted
to adnanwahab/dear_congress for attribution and SHE-835 returned no matches.
Existing metrics have authenticated admin access, normalized route aggregates and
separate identity-bound vote metrics. Campaign attribution never queries or joins
those identities. Civic records, source repositories, PR head/base revision
binding, votes and receipts remain unchanged.

## Behavior and privacy boundary

Fixed cs_source and cs_campaign query vocabularies select an optional consent
banner. Parameters are stripped with replaceState, preserving unrelated query and
hash navigation. Declining sends no attribution. Allow records a normalized
landing aggregate; page-memory consent expires within 30 minutes and ends on
reload or Stop. No cookies, local storage, contact uploads, third-party tracker,
fingerprints, recipient tokens or cross-device stitching are added.

The shared App request helper attaches the bounded marker; successful real journal
publication or a nonempty civic sandbox vote records an interaction aggregate.
A response acknowledgment suppresses subsequent interaction markers in that page.
Pending moderation, sample and simulated journal publications and rejected actions
are excluded. Repository voting and other request helpers are not instrumented.
No claim of whole-product interaction coverage is made.

Counts persist in a separate new SQLite aggregate table alongside existing stats.
Only day, source category, campaign category, normalized landing route, stage and
count persist. No timestamps, raw query strings, participant identifiers, journal
IDs or ballot targets enter this table. Existing admin authentication, origin
validation, bounded requests, rate limits and metrics-failure behavior remain.

These are approximate first interactions per consenting page session, not unique
people, audited conversions, comprehension, causal impact or representative
participation. Concurrent submissions can count more than once before the first
acknowledgment. Forged same-origin headers and client failures affect coverage.
The server validates vocabulary and expiry but does not authenticate consent or
issue tracking tokens. Hosting may log initial query URLs before client cleanup.
Daily aggregates currently have no automatic expiry. No historic data is backfilled.
