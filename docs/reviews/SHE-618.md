# SHE-618 safety-gate explainers

Refs: https://linear.app/shel-bernstein/issue/SHE-618/civicplaypatch-arcade-interactive-safety-gate-explainers-for

Implemented read-only native disclosure gates in repository PR lists and details.
Each exposes the rule, source evidence and responsible action. The typed local
status model is explanatory only; server eligibility remains authoritative for
its existing policy evaluation and does not grant merge permission. LiveRound
and issue contexts explain advisory limits without fabricating PR receipts.

Source repository, repository ID, PR number, head/base and ballot revision,
last sync, loading/error/stale evidence and roster permission are explicit.
List items with no detailed GitHub evidence say unknown; opening details uses
the existing endpoint. Receipt links derive from the route's allowlisted
repository and PR number. Review receipts include commit identity. Human reviewer
identity still requires GitHub verification. Snapshot evidence is not live proof.

Audit: read repository instructions, README, repository-voting, pr-previews,
launch-merge-policy, accessibility and motion docs; inspected the shared contract,
server eligibility, pilot docs, GamePatches and live-round source. GitHub searches
for SHE-618 and safety gate found no matches. Open-PR search also identified
adjacent review candidates #231 (SHE-620 rehearsal), #230 (SHE-622 changelog), and
#229 (SHE-624 queue search). Their descriptions are process reports, not acceptance
evidence; none was imported or modified. Account GitHub CLI networking failed;
the connected GitHub read tool supplied the PR search results.

## Preserved policy

No policy, backend, storage, ballot, receipt or authentication changes. Pilot
merge lock remains disabled for automatic merges. Source defaults remain quorum
10, 24 hours, strict yes majority, at least one current-head approval, empty
base/check allowlists failing closed, disabled/dry-run and kill switch active.
The UI reads actual configured policy rather than replacing it with these defaults.
Non-HBL scopes remain disabled/dry-run; issues never merge. Human maintainer
review and explicit decision remain required; production requires a human-published
tagged release. Production settings and branch protections were not changed or
verified. No one-vote authorization is introduced.
