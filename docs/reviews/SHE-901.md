## Proposed v1 types (design, not an available endpoint)

Use JSON over a read-only simulation service; keep rendering independent of
transport. `proposalID` is the exact wire spelling in this new schema. Existing
`proposalId` URLs and recipes retain their spelling and semantics. A future
explicit adapter must validate and resolve them; never relabel a local recipe as
a saved proposal revision. These TypeScript sketches require runtime validators.

```ts
type Digest = string; // exactly 64 lowercase SHA-256 hex characters
// Bounds and allowed values below are normative for this proposal.
type Identity = {
  repository: 'adnanwahab/dear_congress';
  itemKind: 'civic-proposal' | 'fictional-sample';
  proposalID: string;
  revision: number;
  contentHash: Digest;
};
type Evidence = {
  kind: 'fictional-sample' | 'unreviewed-concept' |
        'source-backed-metadata' | 'measurement';
  sourceURL: string | null;
  sourceRevision: string | null;
  observedAt: string | null;
  limitations: string[];
};
type Handoff = {
  schemaVersion: 'civic-world-handoff.v1';
  proposal: Identity;
  sourceRevision: string; // exact source build commit, 40 lowercase hex
  scenario: {
    id: string;
    mappingVersion: string;
    modelVersion: string;
    assumptionsVersion: string;
    lawId: 21 | 22 | 23 | 83;
    implementationStrength: 0 | 0.25 | 0.5 | 0.75 | 1;
    population: 24;
    horizon: { value: number; unit: 'minute' | 'month' };
  };
  jurisdiction: {
    id: string;
    level: 'city' | 'county' | 'state' | 'federal';
    modelScope: 'synthetic';
    mappingVersion: string;
  };
  seed: number;
  budget: {
    status: 'unmapped' | 'reviewed-mapping';
    amount: number | null;
    unit: 'illustrative-national-USD-billion';
    period: string | null;
    mappingVersion: string | null;
  };
  evidence: Evidence[];
  advisoryOnly: true;
};
type Delta = {
  metricID: string;
  unit: string;
  time: number;
} & (
  { status: 'modeled'; baseline: number; edited: number; delta: number } |
  { status: 'unknown'; reason: string }
);
type Return = {
  schemaVersion: 'civic-world-return.v1';
  requestHash: Digest;
  proposal: Identity;
  resultKind: 'modeled-future';
  advisoryOnly: true;
} & (
  { status: 'completed'; modelVersion: string; mappingVersion: string;
    seed: number; pairedInitialState: true; deltas: Delta[];
    limitations: string[] } |
  { status: 'unsupported' | 'unavailable'; code: string;
    message: string; deltas: [] }
);
```

The proposal ID is an opaque public identifier of 1–80 ASCII letters, digits,
underscore or hyphen. Revision is a positive safe integer capped at 1,000,000;
resolve it to immutable public content, never the current revision. Fictional
sample IDs occupy a separate item-kind namespace. Never accept PR numbers,
journal IDs or browser vote identities as proposal identities. PR head/base
binding remains exclusively in the existing governance domain.

The seed is uint32 including zero. All numbers must be finite; no numeric strings,
coercion, clamping, NaN or Infinity. Versions and scenario IDs are 1–80 characters
from ASCII letters, digits, dot, underscore and hyphen and must match a reviewed
registry exactly. Law 21 accepts strength 1 only. Law 83 uses exactly 720 minutes;
21/22/23 use exactly 12 months. These are current sandbox bounds, not evidence
that every civic proposal maps to these mechanisms. A reviewed mapping must
justify the exact proposal revision, jurisdiction and mechanism; absent mapping
means unsupported. Browsing jurisdiction does not prove residence or authority.

Budget amount is nonnegative and finite or explicitly null, never inferred zero.
A missing period or mapping is `unmapped`; refuse fiscal execution with
`budget-unmapped`. A nonfiscal sandbox may remain accessible as a separately
labeled synthetic sample, without claiming the proposal was applied. Mapping
national costs into city treasury values requires separate reviewed conversion,
units and period; v1 does not invent that conversion. Any different currency or
cost unit requires a new agreed schema version.

Evidence records preserve provenance and uncertainty. Source-backed metadata is
not an endorsement or measured impact. Measurements require their actual period,
source revision and limitations. Fictional/unreviewed inputs retain visible
labels. Output always remains a modeled future, never an official claim,
enacted law, measurement or calibrated forecast. Missing metadata is explicit;
unknown source build/model/mapping cannot support a reproducible completed run.

## Identity, returns and compatibility

Canonical request bytes use RFC 8785 JSON canonicalization, UTF-8, SHA-256;
reject duplicate JSON object keys before canonicalization. Hash the entire
validated Handoff, including proposal identity, budget, seed and all versions.
This is a new proposed scheme, not the existing comparison JSON.stringify hash.
Maintain golden canonical byte/hash vectors in both apps before implementation.
Hashes establish content equality, not trusted provenance or authorization.

The provider validates before allocating work. It returns the requestHash and
exact proposal tuple. The consumer independently compares them with the active
request and checks model/mapping versions and seed; reordered/late responses
cannot overwrite a newer request. Changing any model input produces a new hash.
No silently upgraded model, latest-proposal lookup or live replacement on replay.
Old snapshot/plan/comparison endpoints and existing stored records stay intact.
New versions negotiate explicitly; unknown schemas or unknown fields fail closed.
Do not turn existing snapshot URLs into autorun links for this new contract.

Metric IDs/units must come from a versioned model registry. Delta is edited minus
baseline at the same recorded checkpoint and synthetic population, in the same
unit. Reject inconsistent arithmetic using published per-metric tolerances;
require unique metric/time keys, strictly ordered checkpoints within the horizon,
at most 100 checkpoints and 32 registered metrics per checkpoint. Fractions
remain fractions, not silently converted percentages. Unknown is a tagged value,
never zero. Do not infer paired deltas from unrelated runs or subtract separately
aggregated medians. Completed means at least one valid modeled metric; otherwise
return unavailable. Model-version determinism and common random draws need
provider tests; sharing a seed alone does not establish them.

Keep actor playback in the existing bounded receipt interface until a separately
reviewed adapter binds its exact request and model identity. This proposed
aggregate return does not fabricate actors, event IDs or causal explanations.
Use a 256 KiB request/1 MiB response limit, 45-second deadline and cancellation;
reject overflow before display. Resource limits require agreement with provider
owners and cannot weaken existing admission limits.

## Friendly read-only fallback and privacy

Unsupported schema, scenario, jurisdiction, proposal revision, mapping, budget,
model version or malformed return must clear previous modeled output. Present:
“Simulation unavailable for this proposal revision. You can still read the
proposal and its assumptions. No modeled effects were applied.” Include a plain
reason, a link to the exact public revision and a keyboard-accessible retry for
transient failures. A 404/evicted revision never substitutes today's proposal.
Timeout, network failure, 429 and 5xx are unavailable; never successful zero delta.
Use a status/alert region and text table, usable without WebGPU, motion or images.

No automatic run on opening a link. Show the public input summary before an
explicit run. New transport accepts only configured HTTPS provider origins,
credentials omitted, existing CORS/CSP restrictions retained. Never fetch an
arbitrary caller-supplied source/return URL. Prefer a public immutable request ID
in share links; retention/export policy must be agreed before durable replay is
promised. No postMessage bridge is needed; any future bridge requires exact
origin, source-window and payload checks, not wildcard trust.

Do not export journal text/IDs, precise location, derived personal needs,
identities, ballots, auth credentials or raw database/engine snapshots. Existing
snapshot location redaction is preserved. Return data cannot submit votes,
change a proposal, approve/merge a PR or claim official authority. Simulation
provenance remains separate from verified governance records and receipts.

## Required contract tests and acceptance gaps

One shared, versioned fixture corpus must be consumed by both apps' CI, pinned
to the same digest. Dear Congress tests producer serialization plus consumer
return validation; HBL tests request validation plus provider serialization.
Neither app passing its own mocks alone proves interoperability.

| Fixture / check | Required result in both apps |
| --- | --- |
| Valid reviewed synthetic transit, seed 0/max | Exact identity/hash echo, pinned versions, finite paired deltas |
| Same input replay; changed revision/seed/budget/model | Stable canonical bytes/hash; every changed input changes identity |
| Fictional and civic proposal with same ID | Distinct namespaces; no records or results cross over |
| Unknown schema/fields, duplicate keys, wrong types, invalid bounds | Reject before execution; read-only reason |
| Unsupported flood/text/jurisdiction, unmapped fiscal budget | No fabricated effect or automatic mechanism substitution |
| Wrong hash/revision/model/seed; stale response after edit | Reject and clear stale display |
| Unknown metric, bad unit/time, duplicate checkpoint, arithmetic error | Reject completed payload; no partial misleading chart |
| Missing metric/all unknown, timeout/429/offline/oversized payload | Explicit unknown/unavailable, no zero-fill |
| Identical baseline/edited; zero/negative/positive delta | Correct direction/units and tolerance checks |
| Privacy canaries in extra input fields | Rejected and absent from URL, outgoing JSON and logs |
| Legacy snapshot/comparison and governance regression | Records, receipts, votes and head/base isolation unchanged |
