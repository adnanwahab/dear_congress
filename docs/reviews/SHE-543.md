## Blocking defects and acceptance gates

These are local blocking acceptance criteria for this audit and each new or
extended interaction family. They have not been posted as external issues.

**D1 — swipe navigation loses topic context (source-confirmed).**
`Navigation.tsx` uses `topicStageUrl` for valid topics, preserving both topic and
proposal. `installStageSwipe` passes only proposal to `swipeDestination`, which
uses `stageRoute`. Reproduce from a workflow route with a valid `topic` query:
activate the next stage link and compare its destination with a qualifying swipe.
Acceptance: both actions resolve to the same validated stage/topic/proposal;
preserve `/vote` alias and boundary behavior. Cover invalid topics, no proposal,
vertical scrolling, multi-touch cancellation, controls, dialogs and map exclusions.
Do not carry arbitrary unvalidated query parameters or change proposal identity.

**D2 — explicit smooth Top action bypasses preference selection (source risk).**
`Navigation.tsx` unconditionally calls `scrollTo({behavior:'smooth'})`. Global CSS
sets reduced-motion scroll behavior to auto, but that does not establish that an
explicit JS smooth request is disabled. Acceptance: choose immediate scrolling
using the existing motion policy when reduced motion or app motion-off is active;
verify both preferences and a preference change in the actual browser. Also verify
keyboard focus remains visible after scrolling and does not strand the next Tab.

**D3 — recorded scrubber lacks semantic time value (source-confirmed).**
`LawBehaviorExplorer.tsx` names the range “Recorded simulation time” but its value
is `frameIndex` (0-based), while visible text describes `frame.time`, unit and
1-based checkpoint position. No `aria-valuetext` exposes that mapping.
Acceptance: every checkpoint announces actual recorded time/unit and position,
including irregular checkpoint spacing; preserve native min/max/step and keyboard
operation. Verify first/last, one-frame, no-frame, metric change, cancellation,
timeout and stale-result rejection; no fabricated data on error. Play/Pause must
remain operable without requiring motion or a successful remote call.

**D4 — dynamic move/reorder and visual-map equivalence require native evidence.**
Sponsor moves attempt to restore select focus; comparison reorders have no explicit
order announcement. County selection updates a visual map and detail section.
Acceptance: keyboard and both screen readers identify the moved/selected item,
new stage/order/detail and save failure without losing focus. All equivalent paths
must yield identical item IDs and results. Treat focus loss, silent ambiguous
changes, or detail available only by pointer/color as blocking defects if observed.
Do not report these unexecuted checks as confirmed browser failures.

**D5 — each family must pass its full state/device matrix before acceptance.**
No new gesture-only operation may ship without a named single-pointer alternative
and keyboard/AT action reaching the same result. Verify logical focus, cancellation,
visible state/units and error recovery. Do not use timing, color, hover or animation
as the only source of information. Missing evidence is an acceptance blocker.
