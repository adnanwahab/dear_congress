# SHE-722 universal question search review candidate

Refs: https://linear.app/shel-bernstein/issue/SHE-722/civicplaydiscovery-ask-a-civic-question-universal-search

## Audit and implementation

Read repository instructions, readme.md, docs/bill-catalog.md,
docs/legislative-metadata.md and docs/launch-merge-policy.md. Existing searches
were scoped to sample proposals, topics or editorial bills. GitHub search found
no SHE-722 PR; related search/catalog candidates included #45, #52, #104, #119
and #229. Their process-completion descriptions are not acceptance evidence.

Dashboard, Bills and Topic Hubs now offer an expandable question search. Opening
it loads a read-only index of editorial bill concepts, engine need definitions,
fictional sample drafts, their background references, sample outcome coverage
and the existing official bill metadata API. Official coverage polls every minute
while open, retaining failed-refresh labels and original hashes/check dates.
Editorial revisions, HFL IDs, need IDs and sample proposal IDs are preserved;
source kinds have distinct index identities. Topic chips reuse the taxonomy.

Matching is deterministic, case-insensitive AND matching after punctuation and
common question words are removed. It does not generate answers, classify new
records, infer source derivation, or establish legal status. Each result links to
its record or background reference and labels its scope and freshness. Outcome
matches explicitly describe hypothetical walkthroughs with no verified measured
outcome. Unknown checks remain unknown. Empty or unsupported queries receive
explicit guidance rather than fabricated claims.

Question/type parameters use `ask` and `askType`, preserving page-specific filters.
Submit/filter actions create history entries; popstate restores controls/results.
Native inputs, select, disclosure, buttons and anchors provide the same search,
focus and selection without transitions, WebGL or animation. Clear restores focus
to the question input. Search results use ordinary document navigation.

## Limits and remaining acceptance

This is a bounded cross-source index, not complete site coverage. Private browser
drafts, personal journals and citizen submissions are excluded. Background sources
are not official legislative records. Verified implemented outcomes are unavailable.
No semantic inference or stemming is used; users may need fewer keywords. The UI
states these limitations. A full public citizen-submission adapter and any broader
outcome dataset need their own projection/consent and provenance review before
claiming whole-site coverage. Accessibility/native browser and human acceptance
remain pending. No external messages, issue state changes, production data writes,
PR publication, merge or deployment were performed. Leave SHE-722 open.

## Validation

Seven focused search/catalog tests pass, including an isolated DOM journey for
question/type selection, URL snapshots representing back/forward, native source
links, focus retention/reset, empty official data and reduced-motion preferences.
Pure tests cover empty indices, unknown queries, stale and failed official metadata,
source identity isolation and hypothetical outcome labels. This is DOM evidence,
not a native screen-reader/browser certification.

`bun run typecheck` passes after frozen dependency installation. Full `bun test`
and `bun run test:routes` were attempted; server fixtures cannot bind port 0 in
this sandbox (`EADDRINUSE`). See final run results below. No server or security
checks were relaxed to work around the restriction.

## Preserved merge policy

No governance configuration changed. Source defaults remain disabled/dry-run,
quorum 10, 24-hour exposure, one current-head approval, fail-closed allowlists and
active kill switch. Advisory browser choices are not verified merge authority.
Required checks remain `bun test`, `bun run typecheck`, and `route smoke test`;
actual GitHub protection must require human approval. Live configuration was not
modified or verified. Human review and a human-published validated tagged release
remain required. See docs/launch-merge-policy.md.

Final local run: `bun test` reported **478 passed / 26 failed**. The failures
were local HTTP server fixtures blocked by port binding. `bun run test:routes`
failed during server startup with the same `EADDRINUSE` restriction. Typecheck
and `git diff --check` passed. The existing home-start DOM test now locates its
specific “How it works” disclosure, so the additional search disclosure does not
change the assertion's intended target.
