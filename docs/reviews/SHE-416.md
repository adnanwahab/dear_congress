# SHE-416 civic sampler implementation review

Refs: https://linear.app/shel-bernstein/issue/SHE-416/joyquest-two-minute-civic-sampler-without-pressured-voting

Implemented a demo sandbox on Feed, awaiting human review. Five fixed demo IDs
span five topics and city, county and federal scenario jurisdictions. Each card
has one editorial benefit/trade-off summary, original provenance and jurisdiction,
and an explicit unavailable official discussion status. References provide background,
not evidence that a fictional bill is introduced or under official discussion.
No popularity counts or model projections are included in the sampler.

Audited WorkflowScreen, DemoItem/DemoPayload and the demo API, source metadata,
watchlist storage, civic stage routes, stage swipe handling, motion and accessibility
docs. GitHub searches for SHE-416 and open sampler PRs returned no matching PRs.
The supplied live reference could not be fetched; implementation follows this
repository's existing components. No live service was written to.

The sampler consumes the existing parent `/api/demo` load, retry and failure states.
It requires all five curated fixtures and never silently substitutes an unrelated
policy if fixtures are missing. Save reuses the browser watchlist with sample-kind
identities and is idempotent. Invalid/full/unavailable storage leaves the card in
place and preserves existing saved data. No full API payload or vote is stored.
Opening context binds the original sample ID through the existing draft route.
Swipe in either direction only skips. The enclosing data-no-stage-swipe boundary
prevents gestures from navigating the civic stages. Vertical, cancelled and
interactive-control gestures are excluded. Native buttons and links are keyboard
and assistive-technology paths; progress returns focus to the sampler heading and
announces the action. All card updates are immediate regardless of motion settings.

## Validation and remaining review

Focused DOM tests cover five distinct topics, loading, failure/retry, missing
fixtures, context identity, save/restart idempotence, corrupt storage preservation,
completion, short/vertical/cancelled touch gestures, skipping and no form submission.
They run with both reduced-motion preference values. Typecheck passes.
Full `bun test`: 478 pass, 26 fail; server-backed tests report local listener
startup failures (`EADDRINUSE` on port 0). `bun run test:routes` fails at the
same Bun.serve listener startup step. These required checks are not passing
evidence and must run successfully in an environment that permits the listener.
`git diff --check` passes.

Actual browser keyboard/touch, screen-reader announcements, narrow-screen layout
and OS reduced-motion review remain pending. DOM control activation is not proof
of native keyboard or screen-reader acceptance. Keep the sandbox label and Linear
issue open until a human reviews the current revision and acceptance evidence.
