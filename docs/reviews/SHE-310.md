The current institutional-change penalty is `lambda * changeLevel / 6`;
reversibility is a separate positively weighted component. Clarify which behavior
the requested “reversibility penalty” means before introducing a distinct field;
do not silently rename lambda. Fairness currently measures strong opposition,
`clamp(1 - 2.5 * strongOppose)`, and is a score component, not a hard fairness
floor. The existing support floor is different. Rights-blocked proposals must
remain unselectable regardless of any approved rule.

Balanced uses supplied weights; Minimal change uses those weights with
`lambda * 3 + .3`; Most popular uses support alone and zero lambda. A comparison
must publish these package-specific derivations so users do not mistake all
three packages for the same scoring policy.

## Bounded pilot contract (proposed, not configured)

1. Start with a small consenting cohort and fixture data. Publish its eligibility
   rule, snapshot date, eligible count, quorum numerator/denominator, abstention
   handling, approval threshold, deliberation deadline, grace duration and named
   activation authority. Human organizers must decide these values; this review
   does not set quorum or invent an official governmental electorate.
2. Create an append-only rule revision containing parent revision/hash, schema
   version, public author attribution, rationale, six raw and normalized weights,
   budget/unit, precisely defined fairness floor and penalties, package derivation
   and authority-policy revision. Validate exact keys, finite nonnegative weights,
   positive total and bounded parameters. Reject an all-zero vector. Show each
   calculation as raw weight divided by total. Separate public author identity
   from private authentication identifiers.
3. Freeze a privacy-reviewed calculation input snapshot and engine/catalog
   revision, outcome mode/source versions, clock/seed, incumbents and challenger
   streaks. Calculate baseline and candidate against identical inputs through a
   new read-only preview path. Do not call the existing mutating synthesis route
   or fake extraEntries to suppress writes. Prove preview leaves every database,
   ballot, plan, streak and receipt unchanged.
4. Before deliberation can progress to approval, publish an immutable preview
   receipt with input/rule hashes, per-option old/new score and contributions,
   ranking, selection additions/removals, spend, exclusions and package-specific
   explanations. Show simulated versus real inputs separately. Describe winners
   and losers as modeled selection/score effects, not measured personal welfare;
   suppress identifying small cohorts and exclude private journals from exports.
5. Bind discussion and eligible ballots to the exact proposal revision and
   electorate-policy snapshot. Editing the rule creates a new revision and
   requires a new preview and approval cycle; prior ballots remain historical.
   Suggested states: draft, previewed, deliberating, approved-pending-grace,
   activated, rejected, withdrawn and superseded. Public advisory responses must
   remain visibly advisory and cannot satisfy the verified approval threshold.
6. Activation requires an explicit authenticated authorized maintainer action
   after quorum, approval and grace checks, with current active-parent and preview
   hashes rechecked atomically. Approval alone never changes the active pointer.
   Fail closed on expired authority, stale preview or concurrent activation;
   record an idempotent activation receipt. The sandbox pilot has no production
   activation capability. Production activation requires separately reviewed
   implementation and human authorization after the pilot.
7. Persist immutable rule/input/output receipts, not merely recomputation from
   today's catalog. Rollback appends an authorized activation referring to a
   prior rule; never rewrites old calculations or deletes votes. Historical
   views retain the original engine, inputs and outputs. Rerunning an old rule
   against new inputs is a new calculation with new attribution and hashes.

## Implementation follow-up — bounded fixture sandbox (2026-11-13)

The earlier disposition describes the analysis PR, not the new code. Audited
current recovered main `0268a4c` and read-only GitHub search/fetch of merged
PR #30: that PR changed only this review document. No existing SHE-310 working
implementation was found. This follow-up implements a first slice, not full
acceptance of SHE-310; keep the issue open for human verification.

`/synth` now includes a working scoring-rule sandbox using its weight, budget
and institutional-change controls. `POST /api/synthesis-rule-preview` accepts
exactly `{weights, lambda, budget}`. Six finite nonnegative weights with a finite
positive sum are required; lambda is 0–1 and budget 0–150 illustrative national
USD billions. Unknown fields (including activation requests) fail closed.
Normalization displays raw / total and effective weights. All-zero settings
block sandbox preview and the existing UI synthesis button.

The endpoint creates an isolated public seed-journal fixture with the existing
deterministic simulated population at a fixed clock. It has no live DB, saving,
voting, proposal-publication or activation dependency. It compares default
weights / lambda .25 / budget 40 with the candidate against identical inputs,
using the existing engine and all three package derivations. It exports only
option IDs/titles, modeled scores, selection flags, rights blocks and spend;
no journals, authors, voter IDs or private citizen ideas enter this fixture.
Rights constraints are unchanged. Fairness remains a score component; lambda
remains the institutional-change penalty, not a new reversibility penalty.

Walkthrough: open `/synth`, change a weight, read its raw-total normalization,
press **Compare rule in sandbox**, and expand Balanced, Minimal change and Most
popular to inspect old/new scores, signed deltas and textual Added/Removed/
Retained/Rights blocked indicators. The summary discloses package derivations,
fixture provenance and absence of approval. Changing settings clears the result;
a late response from older settings is discarded. Network errors permit retry.
The existing **Synthesize** action remains the existing live-input calculation
path; it is not rule approval. Sandbox comparison calls only the new fixture
endpoint and does not call the mutating `/api/synthesize` route.

Electorate, eligibility, quorum and grace period are explicitly **not configured**
in this sandbox. There is no approval or activation capability. No quorum or
verified authority is inferred from anonymous browser activity. Existing merge
policy documented above and in docs/launch-merge-policy.md is untouched, including
disabled/dry-run defaults, quorum 10 and human current-head review/checks.

Remaining acceptance: attributed append-only public rule proposals/versions;
privacy-reviewed frozen input/output receipts with engine/catalog hashes;
contribution/ranking/constraint explanations; hard fairness floor and clarified
reversibility semantics; verified electorate and revision-bound deliberation/
ballots; quorum/grace/authority enforcement; explicit authorized activation and
immutable rollback history. This response is ephemeral and is not an immutable
historical receipt. Validate a small pilot before production activation work.
Live-source alignment still needs a maintainer-identified deployed release/tag
and deployed walkthrough per SHE-281; no deployment or live acceptance is claimed.
