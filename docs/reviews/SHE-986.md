# SHE-986 — User-controlled browser watchlist

Refs: https://linear.app/shel-bernstein/issue/SHE-986/cs-l100097-make-watchlist-updates-honest-and-entirely-user-controlled

## Audit and implementation

Read AGENTS.md, readme.md, citizen proposal following documentation, the outcome
time explorer documentation, SHE-358 review and launch merge policy. Traced
ProposalFollow, local storage, WorkflowScreen, citizen proposal detail and their
public API projections. GitHub PR searches scoped to adnanwahab/dear_congress for
`watchlist` and `SHE-986` returned no matches. These searches are point-in-time
coverage, not proof that no related PR exists. No live production inspection or
production write was performed.

The existing watchlist offered removal, export and change comparisons but silently
observed revisited proposals and had no explicit refresh or last successful check.
It now exposes saved text locally even without a source request. Each entry has
Refresh saved proposal and Last checked. Refresh reads the matching sample ID
from /api/demo or citizen ID from /api/citizen-proposals/:id using an uncached GET
without cookies. Only public title/text and existing kind/ID are projected to
storage. Source revision dates remain explicitly unavailable; a local check is
not proof of progress, active status or official verification.

Only explicit refresh updates existing snapshots. Unchanged successful reads
advance last checked without overwriting the last changed-text comparison.
Failures, invalid responses, missing sources and storage failures preserve saved
text and the last successful check. Removing entries while a request is pending
does not recreate them. Old version-1 records remain readable without rewriting;
they show Never until an explicit successful check. Existing unfollow, delete-all,
export, kind isolation and text comparisons are retained.

The visible disclaimer and public guide explain no background checks, email,
web alerts or cross-device synchronization. No notification permission, signup,
identity field, delivery service or political targeting is added. Ordinary source
page loading elsewhere in the application remains independent of watchlist checks.

## Validation and limits

- Focused storage and DOM tests: 8 pass, 45 assertions. Covers explicit refresh,
  no fetch on mount/revisit, successful check times, changed/unchanged text,
  failed/missing/mismatched sources, identity isolation, removal during refresh,
  legacy saves, blocked writes, inspection, unfollow and deletion.
- `bun run typecheck`: passed.
- `bun test`: 645 passed, 27 failed (672 tests). Server-backed failures report
  `EADDRINUSE` while binding port 0 in this restricted environment. This run
  preceded the final additional legacy-storage test, which passed separately.
- `bun run test:routes`: failed at server startup with the same port-0 bind error.
- `git diff --check`: passed.

Required checks are not all green. Rerun the full suite and route smoke in a
server-capable environment before human acceptance. Native browser, mobile,
keyboard and screen-reader review remain unverified; DOM coverage does not
establish visual or accessibility acceptance. Cross-tab storage has no transaction
locking, as before. No source revision/status feed is introduced.

## Governance preserved

ballot, receipt, production record or merge configuration changed. Source defaults
remain disabled/dry-run, quorum 10, 24-hour exposure, current-head approval,

decision under docs/launch-merge-policy.md. Production requires a human-published
tagged release. No external messages, PR, merge, deployment, release or Linear
state change was made; the issue remains for human acceptance.
