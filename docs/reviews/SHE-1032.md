## Resolved identity contracts

PolicyOriginStore reuses publishCitizenProposal, makeVersion and saveVersion.
Only explicit server catalog creation accepts a template ID and confirmed public
publication; it accepts no user title, prose, mapping ID or provenance object.
Actual proposal IDs are created by the existing publisher and original signed-
browser ownership hash is retained. Future mounting must supply middleware's
trusted identity, never a raw browser header or JSON owner claim.

Baseline version1 contains the explicit nonempty clause:
“Implement” is not assumed: its exact text is
`Illustrative prior proposal: no added policy authorization. This is proposed text, not enacted law.`
Version2 retains that clause unchanged and adds the exact upstream clause/text.
This reconciles Civic's nonempty saved-version contract with an HBL add-clause
comparison: the unchanged disclaimer is omitted from the legal diff. It is not a
reconstruction of existing law. This adapter deliberately supports only the exact
added-clause templates; other mechanisms require separate review.

A separate explicitly configured SQLite file stores append-only source receipts:
original template input/hash/legal hash, repository/commit/handoff identity,
pinned model/mapping, configured Civic origin, actual proposal ID/owner hash and
complete saved v1/v2 snapshots/content hashes. Origin rows and transfer-consent
receipts reject update/delete. No database/storage default silently enables this.
Human/software-mapping acceptance remains separate from a source binding.

The configured existing JSON repository's persistence callback is awaited before
issuing the origin. Restart resolves the actual saved JSON record again and checks
ownership, public state, exact snapshots, content hashes and source/model identity.
Neither copied text nor a forged provenance flag can manufacture an origin row.
A missing record/origin, altered v1/v2, stale/nonexistent version, private flag,
journal source or lost consent fails closed. Site-origin drift fails rather than
rebinding old inputs. The returned payload is a strict allowlist: no journals,
problem narrative, comments, ballots, owner hash or credentials are transferred.

prepare requires explicit public-transfer consent and builds existing
policy-impact-preview.v1 inputs with actual Civic IDs/system/source URL. Canonical
legal hash is recomputed over that actual baseVersionId/diff; it is intentionally
different from the original template legal hash. Saved-version contentHash,
template hash and HBL diff hash are retained separately. Seed42/100pairs/24months
come from the frozen catalog, with no inferred numerical effects. Consent is
recorded against the exact payload hash; duplicate consent creates no extra row.
Unsupported constitutional or other saved revisions retain actual legal diffs and
Not Modeled without a remote payload. No fake preview ID/URL or remote result exists.

v3 may be saved through the existing version service. v2 remains bound to its
original payload; separate version ballots remain separate. The test exercises
an actual existing local unsupported preview record and confirms it survives;
it does NOT substitute that record for a successful HBL simulation. Old actual
remote preview persistence remains to verify after authorized integration.

## Persistence consistency and integration contract

Constructor: explicit separate database path, trusted CitizenProposalStore,
existing durable save callback and configured Civic origin. create(templateId,
trustedVoter,idempotencyKey,confirmedPublic) returns actual saved IDs/binding.
prepare(proposalId,trustedVoter,baseVersion,version,confirmedPublicTransfer)
returns a prepared payload or local unsupported diff. No network calls or shared
route changes. The existing HBL client remains the sole eventual submitter;
its returned model/input identities must be checked against this pinned metadata.

JSON and SQLite are not one distributed transaction. If JSON commits but origin
issuance fails, the proposal stays unbound/ineligible. Exact idempotent retry after
restart repairs that state without duplicating the proposal. Failed repository
save cannot issue an origin; the integration owner must retain the existing
mutation/rollback wrapper for in-memory errors. Concurrent issuers recheck the
receipt inside a SQLite transaction and reject conflicting configured origins.
No production durability, multi-writer scale or migration claim is made. Preserve
both stores and consent history in consistent backups; never reset participation
data or repoint this database at the JSON or existing ballot/review database.
