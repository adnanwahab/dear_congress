## Required implementation contract

First obtain a reviewed, versioned provider contract; do not claim new fields
already exist. It needs immutable run/comparison identity, model and executable
revision, complete input/configuration identity, seed, clock/horizon, paired
initial-state identity, and a bounded ordered event log for each branch. Each
event needs a stable ID, model time and ordering, executed rule/version,
referenced input and affected synthetic entity/metric IDs, and explicit output
links. Declare log truncation, unsupported rules and missing links. Do not derive
event identities from UI array indexes or interpret temporal proximity as cause.

Define deterministic replay and canonical comparison with the provider: replay
the pinned inputs and executable revision, compare ordered event identities and
payloads plus linked checkpoint outputs, and expose unavailable/mismatch states.
Specify numeric precision, ordering of same-time events, digest canonicalization
and retention. A hash supplied without recomputation is not replay verification.
Do not infer reproducibility from a successful HTTP response or matching totals.

Then extend this repository's receipt validation, trace export and existing
inspector. Bind selection to comparison, branch, checkpoint, metric or matched
synthetic actor/field; offer native keyboard/touch controls for changed elements
and an equivalent text list. Pause playback while inspecting. Display four
ordered stages with recorded values and source references, distinguish rule
execution from interpretation, and attach uncertainty/missing evidence. Input,
run, actor or checkpoint changes must clear or rebind selection so stale evidence
cannot be relabeled. Missing events must remain explicitly unavailable; existing
v1 receipts may retain the checkpoint inspector without claiming a full chain.

Keep explanations non-binding and advisory. No legal enactment, real-world
causation, official validation, empirical confidence or representative outcomes
may be inferred from model receipts. No journal text, identity, unpublished
proposal content or civic ballot should enter this read-only provider request.

## Acceptance verification to add with implementation

- A real provider transit and housing run: select changed outputs and matched
  actors; verify every displayed stage against the exact run's linked records.
- Replay identical pinned inputs twice and compare ordered logs and outputs;
  altered seed/configuration/code, missing logs, truncation and replay mismatch
  must never display verified agreement.
- Reject duplicate/dangling event IDs, wrong comparison/branch/rule identities,
  invalid timestamps/order, nonfinite outputs and oversized logs. Test supported
  no-change outputs without inventing events or inferring zero model-wide effect.
- Exercise unavailable mechanisms, provider errors, cancellation, stale response
  races and selection changes; retain source IDs and the original receipt.
- Verify keyboard/focus, touch, narrow layout, screen-reader text and reduced
  motion. Confirm no vote/proposal/record writes and unchanged repository,
  item-kind and PR head/base isolation.
