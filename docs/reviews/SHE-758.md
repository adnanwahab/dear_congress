# SHE-758 — Paper, Orbital and Terminal skins

Refs: https://linear.app/shel-bernstein/issue/SHE-758/civicplayinteraction-craft-paper-orbital-and-terminal-visual-skins

Implemented an optional, token-based appearance layer on the existing civic
components. Standard is the default and rollback. Paper changes neutral surfaces,
heading family and radius; Orbital uses cool surfaces and a larger radius;
Terminal uses green-neutral surfaces, monospace headings and small radius.
Body typography, semantic warning/vote colors, content order, choices, routes,
source identifiers and provenance components remain shared. No animations,
additional graphics, fonts, network requests or motion foundation were added.
Existing motion.ts and the System/Light/Dark switch remain unchanged.

The native labeled select is in AccountScreen, reachable through shared desktop
navigation and mobile More. It has a 44px minimum height and visible focus.
Changes mutate html[data-skin] and only civic-skin storage, without navigation or
remounting content; duplicate mounted selectors and storage events synchronize.
Browser native select semantics support keyboard, screen reader and touch.
Light/dark each supply neutral surfaces; forced colors uses system control colors.
No skin-specific animation runs, including on low-power/reduced-motion devices.

## Fallback

Choose Standard in the select to restore the baseline immediately while retaining
in-memory drafts. No reset or data deletion is required. If controls cannot be
used, append ?skin=standard to the current URL, or &skin=standard after existing
parameters. This overrides stored appearance for that document without changing
other query parameters or stored preference. Reloading can lose unsaved drafts;
prefer the select. Missing/invalid preferences fall back to Standard. Blocked
storage still permits selection for the current document. Removing the new CSS
and startup initialization is the source rollback; no data migration exists.
