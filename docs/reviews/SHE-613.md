## Documented heuristics and caveats

Ordered first-match grouping: test/spec paths; operations/workflow/configuration;
data/schema/migration/SQL/CSV/JSON; client/component/view/style/TSX/CSS/HTML;
engine/model/domain/shared. Unknown files fall into Operations with low confidence.
Recognized paths have medium confidence only. Each file summary reports GitHub
status and line counts, inferred role and uncertainty. This is a conservative
file-role guide, not an AST analysis or verified behavioral explanation.

Added-line links use allowlisted repository, exact canonical PR URL, full head SHA,
encoded filename and parsed changed-line number. No body URL becomes a receipt.
Deleted-line receipts are explicitly unavailable: GitHub's old hunk coordinates
refer to the merge base, while the existing payload supplies the current base tip.
Rename and absent/binary/truncated patch cases expose uncertainty and retain the
existing official PR link and raw diff fallback. No fabricated line links appear.
The pre-existing provider fetches PR metadata/files in separate requests; this
change does not add atomic provider snapshots or solve concurrent upstream pushes.

Native details/summary and anchors provide keyboard/touch interaction. Text wraps,
receipt lists expand independently and there is no animation, including under
reduced motion. These controls contain no writes, votes, approval or merge actions.
