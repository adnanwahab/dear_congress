## Current behavior and gaps

| Surface | Existing evidence | Missing for this issue |
| --- | --- | --- |
| `/votes`, citizen API | Published proposal text is immutable; actual advisory browser counts are separate from synthetic scoring; personalized reads include own response | Daily revision-bound aggregate artifacts and display provenance |
| `/api/demo`, dashboard/workflow | Fictional proposals have illustrative counts; workflow outcomes are simulated and browser-local | Explicit separate snapshot families; no conversion of fixtures into real public support |
| `/synth`, `/api/synthesize` | Engine uses weights, demand, proposal attributes, prior plans and challenger streaks; requests may supply time, outcomes, what-if journals and overrides; real synthesis can update persisted stability state | Complete frozen processing inputs and deterministic aggregate-only replay |
| `/api/plan` (`src/server/public-plan.ts`) | Detached read-only computation; public proposal allowlist, retrieval timestamp and package hash; explicitly `storedSnapshot:false` | Persisted input versions, signed canonical manifest, replay evidence; package hash alone cannot reproduce scores |
| `/api/simulation-snapshots` | Random ID, timestamp and frozen selected items; public route removes location | Only 500 retained; no scoring inputs, signatures or chain; entry ID and linked needs remain. Not a privacy-approved audit export |
| `/api/outcomes`, fetch script | Source names/URLs, observation years, fetched/generated timestamps and severity | Retained source bytes, content digests, transformation versions and immutable publication history |

`buildContext` excludes synthetic journals by default but does not exclude seeded
journals. It still defaults to the simulated POPULATION for statistics and blends
synthetic priors for mechanisms/goals. “Real-only” therefore does not mean all
score inputs are empirical. SHE-271 must resolve provenance before public counts
can be described as real participation. SHE-309 must align explanations with the
actual scoring/selection rules. SHE-300 must identify trusted build metadata;
do not infer a deployed commit from local HEAD or request-supplied metadata.

The engine's `Context` contains journals and the full DB. Never serialize it.
`publicJournal` intentionally exposes public journal text/author on journal
surfaces; it is not an audit export sanitizer. `deleteJournal` also mutates a
simulation snapshot's location. Reusing those snapshots as an immutable public
audit archive would conflict with both retention and privacy behavior.

## Proposed prototype boundary (not implemented)

Start with a disposable, wholly fabricated proposal/tally fixture and one
aggregate scoring example. No production DB ingestion, scheduling, publication,
keys or UI promises in the spike. Timebox the prototype before committing to
the estimated 3–6 week implementation. Demonstrate offline replay from exported
files in a clean checkout, without cookies, tokens, network access or original
journals. A tally replay demonstrates arithmetic from published totals, not
proof that votes were honestly collected or participants were eligible.

Define an explicit export DTO, separate from DB and Context. A candidate bundle
contains versioned public proposal wording, tally categories/denominators,
aggregate score sufficient statistics, frozen rule/weight versions, budget,
lambda, resolved time, outcome mode/overrides, incumbent proposal versions,
challenger streak state, synthetic prior version, simulation model/seed/config,
and expected scores and selected proposal versions. Preserve source repository
identity and item kind. Repository PR evidence must retain repository ID,
number, head SHA and base binding; civic responses must never be mixed into
verified repository ballots. Validate whether aggregate sufficient statistics
actually reproduce selection without exposing individual records before
promising full synthesis replay.

Specify canonical UTF-8 JSON serialization, sorted keys/collections, finite
numeric inputs, rounding at each engine stage, stable tie ordering, runtime and
dependency versions. Hash exact artifact bytes with SHA-256. A content-addressed
manifest should bind schema, UTC coverage interval, data cutoff, processing and
publication times, source commit/build identity, artifact lengths/digests,
redaction policy version, predecessor manifest digest, sequence and correction
references. Sign canonical manifest bytes with a dedicated asymmetric signing
key (candidate: Ed25519); publish key ID, public key, trust bootstrap, rotation
and revocation history separately. A signature authenticates the publisher,
not source truth. Do not reuse cookie/auth keys or accept an arbitrary key
embedded in an untrusted bundle as a trust anchor.

Archive official-source response bytes or a lawful reproducible extract with
exact query/series, retrieval time, observation period, URL, source digest and
transform version. A government homepage link is background, not endorsement
or evidence that fictional policy wording is official. Replay must not fetch
today's mutable upstream data. Missing source bytes or restricted evidence must
produce a stated verification limit rather than a fabricated fingerprint.

## Privacy and immutable history

Export only reviewed public proposal wording and approved non-personal
aggregates. Exclude journal text (including already-public journals), extraction
quotes, sourceText, answers/comments, authors, journal IDs, ownership hashes,
voter IDs, individual ballots, cookies, sessions, IPs, coordinates, fine-grained
timestamps, logs, credentials and private provenance links. Review proposal
wording itself for personal information before permanent export. Avoid hashes
of private text or predictable identities: they can permit guessing/linkage.

Choose and review a minimum population threshold rather than silently adopting
one. Suppress complementary cells and totals that reconstruct suppressed
values. Review differences across daily releases, corrections, overlapping
geographies and response categories; one changed vote must not become visible
by subtraction. A one-day threshold alone is insufficient. Prefer withholding
a breakdown/release until safe; if noise is chosen, document its privacy budget
and make clear replay verifies the published transformed aggregate, not an
exact private tally. Suppressed inputs cannot honestly support exact public
score replay: return an explicit unavailable/partial verification status.

Freeze only sanitized public artifacts in a separate append-only store. Do not
make the operational DB append-only or preserve deleted personal material in
an archive. Atomically capture a consistent cutoff under the existing
single-writer model; publish artifacts before making their complete manifest
discoverable. Repeated jobs for the same cutoff must be idempotent and recover
after partial failures. Define UTC daily windows and publication delay, empty
days, missed-run backfill and retention before enabling a scheduler.

Corrections append a new event with the earlier digest, reason code, corrected
bundle and processing time. Earlier claims remain addressable and visibly
superseded. Historical replays must not silently switch to latest rules or
sources. If personal data accidentally reaches an artifact, privacy incident
response takes priority: revoke access, publish a non-sensitive withdrawal
notice and record the integrity gap. Do not promise perpetual public retention
of accidentally exported sensitive data.

## Candidate reviewer workflow and display contract

Proposed CLI/API names below are design examples, not available commands:

1. Download a sample bundle and independently trusted public key; preserve bytes.
2. Run `audit verify <bundle> --trusted-key <key>` to check schema, lengths,
   hashes, signature, sequence and predecessor/correction links.
3. Run `audit replay <bundle> --offline` with the pinned implementation. Compare
   tally, score components, rounding and selected versions with expected output;
   reject unknown versions and return failure on mismatch or incomplete inputs.
4. Read a machine-readable verification report distinguishing valid signature,
   reproducible arithmetic, redacted inputs and source authenticity limits.

A future immutable GET-by-ID API can serve these bundles; a latest pointer must
resolve to the exact ID and expose supersession. Every displayed tally, score,
package and outcome must carry its own snapshot ID, source cutoff and processing
time, including API responses, exports and shared links. Mixed-source pages need
per-result bindings. Dynamic/private what-if views must clearly say no public
snapshot exists until a safe artifact is created; never attach a nearby daily
snapshot to different results. Preserve existing personalized response privacy.
Use understandable advisory/sample/model labels, keyboard-accessible provenance
links, readable timestamps and correction notices at narrow mobile widths.

## Verification and acceptance plan

Positive tests: independent clean-checkout replay of the fabricated fixture;
byte-identical exports for identical frozen inputs; tally replacement/removal
and empty states; time decay, priors, ties, rights exclusions, budget and
incumbent/challenger behavior; valid correction chains; restart and failed-job
recovery without duplicate publication; official-source digest reproduction.

Negative tests: artifact/manifest tampering, wrong or revoked keys, unknown
schemas/rules, missing parents/files, duplicate sequences, invalid numbers,
wrong proposal revision/repository/kind/head/base, mutable source substitutions,
and incomplete/suppressed replay. Seed sensitive canaries through every private
field and nested free-text path; assert none appears in bundle bytes or reports.
Test cross-day differencing and complementary suppression, including a single
response change. Existing records and receipts must remain unchanged.

Schedule integrity checks only after review: daily completeness, hash/signature
and chain checks; periodic clean-environment replay and independent retained
checkpoint comparison to detect history rewriting. Publish dated reports with
snapshot IDs and explicit missing-day or mismatch status; failures alert an
operator and stop publication rather than overwrite history. Key custody,
storage immutability, privacy thresholds and incident ownership need named
maintainer decisions before production use.

Human acceptance still requires a reviewer to reproduce a sample from public
bytes, source provenance review, privacy adversarial tests, per-display/API
traceability checks, correction preservation and mobile/keyboard/screen-reader
checks on production-equivalent recovered code. All done-when criteria remain
open; this document is a design review candidate.
