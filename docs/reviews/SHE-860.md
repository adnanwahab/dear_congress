# SHE-860 partner embed cards

Refs: https://linear.app/shel-bernstein/issue/SHE-860/cs-l100037-create-opt-in-partner-embed-cards-for-public-civic

## Audit and implementation

Read repository instructions, readme.md, docs/launch-merge-policy.md and the
SHE-536 review; inspected WorkflowScreen, DemoItem, ArgumentMap, embed renderer,
security headers, router and route smoke coverage. GitHub embed PR search found
#184, #18 and #120. #184 is merged into main and its existing implementation is
present here. Extend its `/embed/v1` card and opt-in Feed snippet rather than add
another route or full application iframe.

Cards now show the source label and sample ID, plus the existing transit example's
reasons, concerns, counterarguments and missing evidence. Editorial argument data
is shared with ArgumentMap without loading React or participant data on the card.
Other sample IDs and changed transit text explicitly have no available arguments.
Claims remain fictional, unverified and unassessed; background citations do not
substantiate them. The card discloses independent operation, non-binding beta and
no governmental authority. Existing responsive wrapping, native links, scrolling,
source citation, unchecked review dates and sample titles remain intact.

The route remains static and read-only: no scripts, forms, API connections,
images, analytics or cookie issuance. The existing opaque-origin CSP sandbox and
snippet sandbox remain; outbound navigation is explicit with no opener/referrer.
No participant records, vote counts, journals or auth state enter the projection.
Ordinary hosting requests still reach the hosting service. Public citizen proposal
embeds are not implemented: there is no reviewed public argument publication
contract in this path. This is a sample-only learning card, not proof of real
proposal acceptance or meaningful participation.

with willing partners remain human acceptance work; no tracking was added to measure
these. Keep the issue open pending that review and required passing checks.

## Preserved merge policy

No governance, auth, records, receipts, vote or PR head/base binding changes.
Source defaults remain disabled/dry-run merges, active kill switch, quorum 10,
24-hour exposure, current-head approval and fail-closed base/check allowlists.
Browser votes remain advisory. Required checks are `bun test`, `bun run typecheck`
and `route smoke test`, with at least one human approval. External protections
were not inspected or modified. Production needs a human-published tagged release;
no deployment, merge, release, external message or production-data mutation occurred.
