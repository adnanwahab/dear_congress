# SHE-620 — staged merge rehearsal

Refs: https://linear.app/shel-bernstein/issue/SHE-620/civicplaypatch-arcade-staged-merge-rehearsal-sandbox

Implemented a local metadata rehearsal in repository PR views. Each selected PR
loads through the existing read API and is checked against repository ID, number,
version, head SHA and base before staging. The staged receipt displays those
identities plus fetched base SHA. Local order controls and clear/remove never
submit votes, feedback, approvals or merges. Issues do not expose the sandbox.
Refresh failure, stale cache and changed source revision make displayed readiness
unknown. Source/loading/error and the sandbox's lack of merge permission are explicit.

Read existing GitHub PR search results before editing, including adjacent draft

review candidates, not implemented baseline or acceptance evidence. No remote PR,
Linear state, comment or other external mutation was made.

The GitHub detail response now includes optional fetched commit SHA metadata.
A dependency edge means another staged head occurs in that PR's commit list.
Earlier shared changed-file paths indicate possible conflicts. This is a metadata
approximation, not a Git merge-tree execution or proof of conflict freedom.
Unstaged dependencies, missing metadata, renames and changed merge bases can
require further review. No hypothetical merged SHA or successful merge receipt
is fabricated. Reordering can expose unmet staged dependency order.

## Preserved policy

The hard advisory pilot lock remains active. Configured source defaults stay
disabled/dry-run, quorum 10, 24-hour exposure, current-head approval, strict yes
majority, protected-base/check evidence, explicit production-base permission and
existing kill switch. No runtime production configuration is claimed verified.
Browser votes remain separate from verified ballots. Actual merges require a
separate permission-checked confirmed GitHub action and human maintainer review;
this sandbox offers no merge action. No deployment or release was performed.
