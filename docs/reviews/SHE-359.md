## Implemented behavior

The feed, advisory-vote detail and sample draft detail expose native labelled
checkboxes for two or three proposals, a viewed-proposal toggle, selection status,
ordered move controls and a share link. Criteria align summary/goal, jurisdiction,
exact draft text, groups, authority, cost, horizon, coverage, reversibility,
evidence strength, strongest pro/con and unintended effects. Missing values use
“No evidence supplied”; no structured claims are extracted from prose.

Share URLs contain ordered public editorial snapshots only: repository/demo scope,
ID, title, topic, jurisdiction, summary, current/proposed text, source and background
metadata. Mutable tallies, browser choices, private state and journals are excluded.
These exact serialized bytes identify the revision; this is not a cryptographic
hash or source authenticity proof. Parsing rejects invalid/duplicate IDs, wrong
counts, oversized data, unavailable items and changed revisions atomically. No
current text is substituted. Old links can become unavailable after editorial
changes; this does not implement a historical archive. URLs are relatively long;
transport limits may vary. The parser caps decoded payloads at 30,000 characters.

Each column's source/draft and advisory voting links are independent. The comparison
imports SHE-306's exact-text-bound ArgumentMap and existing provenance component;
it does not invent strongest rankings. Simulation caveats link to SHE-311's existing
package input comparison, explicitly distinct from these fictional proposals. No
executed model outcomes are claimed. Synthetic outcomes, unverified advisory
counts and official facts have separate semantic sections. Official bill metadata
continues in its existing separate lane. Nothing here submits votes or writes
storage, records, receipts or server data.

The criteria table has scoped headers and a focusable horizontal scroll region;
its width is constrained to the panel, with wrapping text and native controls.
Reduced motion explicitly disables animation, transitions and smooth scrolling.

## Validation and limitations

Installed existing locked dependencies with `bun install --frozen-lockfile`;
no manifest or lock changes.

- Five focused tests pass (49 assertions): two/three selection, ordered URL replay,
  revision/source/jurisdiction changes, missing/duplicate/invalid/oversized input,
  tally-independent revision identity, semantic criteria and lanes, reuse of the
  argument map, selection cap/removal/reordering and no browser storage writes.
  DOM tests exercise native focus and click activation. CSS assertions cover
  constrained overflow and reduced motion; they are not browser layout tests.
- `bun run typecheck`: passed after installing existing dependencies.
- Full `bun test`: 406 passed, 24 failed, 104,595 assertions across 118 files.
  Run included the first four comparison tests; the fifth DOM interaction test
  subsequently passed in the focused run. All 24 full-suite failures are HTTP
  server startup `EADDRINUSE` on port 0 before request assertions execute.
- `bun run test:routes`: fails at the same server startup. Required checks are
  not all green. No listener or check bypass was introduced.
- `git diff --check`: passed.

Remaining human acceptance: real browser keyboard-only interaction, screen-reader
reading order and announcements, 390px/zoom horizontal table scrolling without
page overflow, reduced-motion behavior, copy/open link in a fresh browser, and a
real same-need conflicting pair with reviewed evidence. General citizen/bill
variants and historical archive replay are outside this sample slice; they must
use their own immutable source/revision contracts rather than this demo namespace.
Test HTTP routes in an environment that permits local listeners. This review does
not establish deployed-source equivalence or complete SHE-359 acceptance.
