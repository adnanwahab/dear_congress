# SHE-863 plain-text advisory receipt review candidate

Refs: https://linear.app/shel-bernstein/issue/SHE-863/cs-l100039-make-the-non-binding-decision-receipt-exportable-as-plain

## Audit and implementation

Read AGENTS.md, readme.md, docs/launch-merge-policy.md and the existing SHE-402
receipt review; inspected the receipt, mutation, sample share and workflow modules.
Connected GitHub PR searches found no SHE-863 candidate. Receipt search identified
prior receipt PR #136 (SHE-402), adjacent budget receipt #207, and integration-test
follow-up #281. The existing receipt implementation is present in this checkout;
this work extends it rather than creating a second vote or sharing endpoint.

The acknowledged sample-proposal receipt now has a read-only plain-text preview,
explicit Copy receipt and local `.txt` download. The same formatter supplies all
three. It lists public proposal identity, local viewed-text revision, the three
options shown by the sample controls, independent non-binding beta disclaimer and
a public proposal link. It does not claim that each option was read or understood.
Chosen stance is omitted by default. A labeled checkbox includes it only after
explicit opt-in; unchecking removes it immediately. Each new acknowledged receipt
remounts the component and resets consent. No consent preference is persisted.
Clipboard denial retains a selectable preview and local download fallback.

Only explicit public fields are formatted. No cookie/storage serialization,
private journal fields, current URL query/hash, browser identity or vote receipt
identifier is exported. The canonical proposal URL is constructed from the public
proposal ID, not the browser URL. Source repository and sample kind stay explicit.
Copy/download never submit another vote or send a message.

The revision remains the existing local non-cryptographic viewed-text fingerprint,
not a server-bound ballot revision. Missing older revisions remain unavailable;
the linked current proposal can differ from the original viewed text. No server
schema, API, saved choice, existing receipt or PR head/base binding changed.
Public guide and README describe the export and privacy limits.

## Validation

- Focused receipt, mutation and public-guide tests: 14 passed, zero failures.
- Selection and provenance regression tests: 6 passed, zero failures.
- Receipt interaction checks cover all stances, opt-in/out, consent reset, download
  payload matching preview, clipboard success/denial, private URL/cookie exclusion,
  pending/missing acknowledgement, loading, empty state and reduced-motion DOM.
- `bun run typecheck`: passed.
- `git diff --check`: passed.
- Initial full `bun test`: 748 passed, 28 failed. One outdated default-stance
  assertion was updated and passes; provenance passes independently. Final full
  rerun: **750 passed, 26 failed**, all remaining failures are server-dependent
  tests blocked by the same port-0 `EADDRINUSE` startup error.
- `bun run test:routes`: blocked at Bun server listen with port-0 `EADDRINUSE`.

DOM tests do not establish actual browser download behavior, mobile layout,
screen-reader comprehension or usefulness. Human review should verify native
copy/download and consent controls on desktop/mobile, then assess whether users
understand the non-binding disclaimer and revision limits. No analytics or claim
that sharing creates meaningful participation was added.
