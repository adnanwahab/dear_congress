## Implementation

Both sample panels share AdvisoryVoteBars, keyed by proposal ID to prevent
animation interpolation across different proposals. Each choice shows its share
of all three response counts, count and percentage (one decimal; independent
rounding may sum to 99.9% or 100.1%). Empty totals show 0.0% and empty bars.
IntersectionObserver starts the fill on first visibility, then disconnects.
CSS transform transitions animate bars; a cancellable requestAnimationFrame loop
animates formatted counts, continuing from the current displayed count when
interrupted. Missing observer support starts on mount.

The existing write followed by payload refresh remains the confirmation boundary.
Only then does a confirmation sequence trigger a one-second highlight, including
when saving the same choice again. Failed saves/refreshes do not trigger success.
Selecting a proposal still makes no write. Existing pressed state/checkmark and
live success/error text remain. No API, source ID, identity, persistence, vote
payload, revision, count source or governance behavior changed.

The Non-binding pills remain beside the panels. Explicit “Illustrative responses,
not a representative poll” text sits directly above each group, with the existing
sample-count caveats below. Accessible button names include the authoritative
count and percentage, independent of decorative animated values. Reduced-motion
preferences bypass count animation and CSS motion, including preference changes
while mounted. Narrow screens stack text before the full-width track.
