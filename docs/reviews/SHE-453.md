ArgumentMap previously offered paired fictional claims bound to exact transit
proposal text. Neither it nor the inspected demo contracts supplies a consented
participant dataset for cross-goal analysis. Browser counts do not supply joint
responses, consent, verified people or a representative sampling frame. The new
feature therefore uses invented editorial aggregates only; it does not reconstruct
overlap from marginal vote counts or repurpose journals.

The implementation adds a read-only synthetic preview inside the existing
exact-text-gated ArgumentMap. Existing source-desk, advisory-voting and comparison
navigation and claim provenance remain intact. Three pairwise goal intersections
show support without a listed constraint, conditional support, and other/undecided
responses. Conditions remain explicitly unresolved. Pair counts may overlap;
adding pairs is invalid. These counts express goals, not approval of the proposal.

Readers can switch between pooled-response percentages and an equal-subgroup
mean, then inspect raw released counts and complete-response denominators.
The 20-response and 10-response invented groups are disjoint. No population
weighting, confidence interval, causal claim or representative poll is implied.
The source version and exact proposal scope are visible in the disclosure.
No endpoint, persistence, participant identity, API integration or write was added.
The public guide and README describe the same limitations.

## Privacy and source boundaries

Groups below 10 are excluded from both aggregations. Their exact sizes, counts,
labels and grand totals are absent from the fixture and DOM. Any nonzero bucket
below 5 suppresses the whole partition, including its complement. Invalid counts
also fail closed. No participant drill-down, dynamic subgroup intersections or
small-group contribution to a larger total exists. This bounded preview policy
is not a general privacy guarantee; arbitrary future data must not bypass it.

Unknown namespaces, IDs and changed proposal text cannot display this terrain.
No real-sample consent is claimed. Before real samples are displayed, implement
an explicitly consented collection and withdrawal contract, source/revision-bound
aggregate projection, source and response denominators, nonresponse reporting,
and reviewed protection against differencing across releases and overlapping
subgroups. Privacy filtering must occur before any real data reaches the client.
Do not substitute fictional counts when real data fails to load.

  retained focus, native disclosure activation, offline rendering, unavailable
  source scopes, and no network calls or storage changes.
- Suppression tests cover below/exact group thresholds, rare and complementary

  Integration tests retain exact proposal isolation and unchanged demo fixtures.

  content. Controls have visible focus and 44px minimum heights. A responsive grid

  parent loading/retry behavior remains unchanged and its integration test passes.
  Invalid source scope displays unavailable. A future real-data endpoint will
  need explicit loading, failure and retry checks before integration.

  actual 200% zoom, forced colors and reduced-motion checks remain unperformed.
  Follow docs/accessibility-acceptance.md on a disposable local instance; confirm
  all three tiles and expanded denominators remain readable and changes announce

This is a bounded implementation candidate. Consented real samples and human
