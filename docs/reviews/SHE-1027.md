## Contract and behavior

Import `createHeliosService` from `src/server/helios/service.ts`; instantiate once
per worker. `generate(unknown)` accepts only `helios/v1`, explicit human invocation
and opt-in, a repository/item/revision scope, and at most 40 exact sources.
Sources use SHA-256 of UTF-8 text (`hash(text)`); the combined digest canonically
sorts object keys and binds scope, full source content, objection response histories
and consent. Source array order is retained. The existing catalog revision remains
an independent authoritative revision identifier.

Every source needs a trusted consent receipt binding its exact content hash to
HELIOS generation and public output. External processing requires separate explicit
consent. Public publication or need aggregation alone does not grant this consent.
Private journals without it cause rejection before provider access, including in
fixture mode. The module cannot load any journal or other source independently.
`objectionSource` projects the existing SHE-307 type and strips record-only fields;
validation rejects unknown/ownership fields. All supplied objections are preserved
separately, including declined ones, and their verbatim text/severity/response
histories remain independent of model paraphrases.

The strict output includes distinct textual shared goals (empty when unsupported),
each objection's strongest unresolved case, exactly three distinct unordered drafts,
fixed host-defined no-change and abstention wording, amendments for every supplied clause with
replacement/tradeoffs, and nonempty uncertainty/missing-evidence lists. Alternatives,
claims, tradeoffs and amendments require supplied source ID citations; objections
must cite themselves and amendments must cite the exact clause. Unknown citations,
URLs, clauses, duplicate/omitted dissent, extra authority/action fields and wrong
versions fail closed. No inferred agreement, political score, approval, inferred
vote, official status or executable action field exists. Semantic accuracy,
neutrality, source relevance and completeness still need human review: an existing
source ID is not proof that a generated claim is supported by its text.

Every successful response records model, prompt version, generated time, fixture
status, source-set revision digest, individual source IDs/hashes and full consent
provenance. `status=human-review-required` and `binding=false` are host-owned fields.
This is an in-memory review artifact, not a durable publication ledger. The mounting
owner must persist this complete envelope with any draft they retain; this module
does not create a competing proposal/amendment store or write to existing records.

## Provider and resource configuration

Disabled unless `HELIOS_ENABLED=true`. Configuration comes from server environment,
not request fields. `HELIOS_PROVIDER=json-http` requires `HELIOS_ENDPOINT` (HTTPS,
no credentials/fragment), `HELIOS_MODEL`, and `HELIOS_API_KEY`. Endpoint configuration
is trusted operator configuration; never accept it from a browser. Redirects are
rejected. The adapter posts `{ model, temperature: 0, max_output_tokens: 4096,
store: false, messages }` to a configured JSON gateway, which must return the raw
`HeliosModelOutput` object directly. This is a documented provider adapter protocol,
not an assertion that arbitrary vendors support this exact wire format. The gateway
must enforce the output token ceiling and use an approved retention policy; the
module cannot independently verify a vendor's billing or retention behavior.

`HELIOS_PROVIDER=fixture` is accepted only with `NODE_ENV=test`; fallback is explicit,
synthetic, deterministic, and records its model/version. It fabricates no goals or
claim of consensus. A live outage always produces `MODEL_UNAVAILABLE`, never fixture
content. Provider messages/response bodies are not reflected in errors or logs.

Bounds per service instance:

- Request text: 48,000 JSON characters, 40 sources, 8,000 characters per source.
- Response: 64,000 bytes, strict bounded arrays/strings, unknown fields rejected.
- One active generation; default 20 attempts/hour, configurable downward or up to
  100 with `HELIOS_REQUESTS_PER_HOUR`. Failed attempts consume the reservation.
- Default deadline 10 seconds, maximum 30 seconds via `HELIOS_TIMEOUT_MS`; deadline
  races even an unresponsive transport and aborts fetch/stream work.
- Default hourly reservation budget $1, maximum $20 via
  `HELIOS_BUDGET_USD_PER_HOUR`. Conservative input reservation uses UTF-8 byte count
  as token upper bound, plus 4,096 output tokens. Input/output USD per million token
  ceilings are `HELIOS_INPUT_USD_PER_MILLION` (default 10) and
  `HELIOS_OUTPUT_USD_PER_MILLION` (default 30), maximum 1,000 each. Configure these at
  least as high as provider prices. Nonfinite/nonpositive/excessive limits fail closed.

Limits are process-local and reset after restart; they are not a fleet billing
ledger. Mounting must use a singleton plus shared quotas if running multiple workers
or requiring durable spend limits. No production provider was called or configured.

## Input/output privacy review

Reviewed the complete input projection, provider payload, error paths and result:

- No database, journal reader, cookie, owner hash, token, voter record or inferred
  demographic lookup is available. Only caller-supplied, explicitly consented
  sources reach generation. Private content is never fetched to test consent.
- Only consented source ID, kind, text and text hash are sent to the configured
  provider with scope and a synthetic response-shape example. Objection constituency,
  response history, consent receipts and other attribution metadata stay out of the
  provider payload. Source text itself can still contain sensitive details; minimize
  it before obtaining consent. API credentials appear only in the outbound
  Authorization header.
- Consent is purpose-specific and revision-bound; a receipt string is provenance,
  not independently verifiable authority. The authenticated host must resolve and
  verify receipts, revocation and source ownership, not trust browser flags.
- System instructions are separate from JSON source data. No tools/browsing or
  source-fetch capability is granted. Injection cannot add action fields, citations
  or silently remove objections. Malicious model prose remains possible; all text
  is untrusted and must be rendered as text, never HTML or executed instructions.
- Results contain consent receipts and verbatim consented dissent. They are not a
  public response by default. Before any output release, recheck consent/revisions,
  review for personal data and source leakage, verify citations and human neutrality,
  and apply the host's authorized audience, retention/deletion and no-store policy.
  Withdrawal must also remove retained derived artifacts under the host's policy.
- No raw request/response logging, telemetry, caching, local file writes or automatic
  publication occurs. `store:false` requests provider non-storage, but contractual
  vendor retention and deletion require operator verification before live use.

This code-path review is not an independent privacy approval. Live use and human
acceptance remain pending, including vendor privacy review and authorized output
review. No real private inputs or production data were used.

## Acceptance and integration boundary

Implemented tests cover protected dissent, source/revision and base isolation,
hallucinated citation rejection, stale/missing/external/private consent rejection,
no-change/abstention, strict output versions, malicious prompt data, missing clauses,
resource bounds, concurrent calls, snapshot immutability and unavailable models.

Integration owner must mount an authenticated, same-origin/CSRF-protected human
invocation; validate trusted source scope/consent; enforce shared quotas where needed;
retain provenance with drafts; apply no-store and safe text rendering; and recheck
current revisions and consent before output review/publication. HFL workbench mapping
requires its own exact full-source/revision adapter. No route is mounted here.
Human review must assess whether the goals are actually shared, objections faithfully
steel-manned, options neutral and distinct, tradeoffs complete, and citations support
claims. Neither a passing test nor a draft PR proves this acceptance. Leave the
Linear issue open for human verification.
