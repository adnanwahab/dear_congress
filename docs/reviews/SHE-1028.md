## Implemented component contract

Import `HeliosWorkbench` from
`src/client/helios-workbench/HeliosWorkbench.tsx`; pass `selection: RevisionKey`
and a stable `adapter: WorkbenchAdapter` defined in `contract.ts`. CSS is imported
by the component. This is an integration-ready component, not a registered route.
No network call occurs until the integrator supplies an adapter.

Selection is the tuple `(repository, kind, billId, revision)`; only
`adnanwahab/dear_congress`, `hfl`, and HFL-formatted IDs are accepted. Never map
these IDs to demo proposals, citizen proposals, official legislation or PRs.
A changed tuple remounts the session, discarding unsent drafts, selection, consent
and receipt state. Aborted/stale loads cannot update a different selection.

`load(key, signal)` returns a public `Snapshot`:

- `source`: exact complete UTF-8 source text; separate `textHash`; canonical
  catalog `revision`; attribution, provenance and human editorial status.
- `amendments`: immutable full alternative text/hash/revision, exact
  `parentRevision`, stable unique ID, AI origin, rationale, attribution/provenance,
  editorial status and its own optional published round. Ordering must be neutral
  and documented by the adapter, never a hidden recommendation. No generation
  service or private context is invoked by this component.
- `objections`: public exact-revision records with attribution, response and
  explicit unresolved/declined/accepted state. Private and cross-revision records
  are defensively omitted before rendering. The adapter/server must exclude them
  before transport, not rely on client filtering as an access-control boundary.
- Each `round`: unique immutable ID, explicit opensAt/closesAt, server-authoritative
  open/closed/blocked state, support/oppose/unsure counts and electorate description.
  Null means unpublished, never an inferred voting opportunity.

The adapter must supply the authoritative full source snapshot and its independent
text SHA-256, including any separately bound supplements; do not hash a UI summary
or confuse the existing catalog record digest with textHash. All hashes are checked
before enabling review. Wrong source, parent, hash, duplicate version/window or
invalid counts/window blocks the entire snapshot. A hash verifies byte agreement,
not authenticity: the server must independently bind those bytes to the canonical
revision and source provenance. Never fabricate missing text or review receipts.

`submit` accepts only one of:

- Exact RevisionKey + requestId + `action: objection`, bounded text and
  `consentPublic: true`.
- Exact target RevisionKey + requestId + `action: vote`, roundId, support/oppose/unsure
  and `consent: true`.

Resolve only after a durable receipt; identical uncertain retries retain requestId.
There are no optimistic count increments. Objections never submit votes. Selecting
another comparison version clears the choice and voting consent. All new versions
require fresh choices in their own published rounds. Old totals remain untouched.

The adapter/server owns authentication, authorization, same-origin/CSRF and rate
limits, bounds/privacy moderation, immutable revision/round binding, current human
review gates, server-time window enforcement, conflict detection, transactional
idempotency and durable saves. It must reject stale/closed mutations rather than
retarget them. Browser timestamps are never voting authority. Unknown editorial
states display explicitly as unreviewed; displayed status does not grant publishing
or voting permission. Existing catalog ballot GET/PUT can underpin the source
round, but the HFL objection/amendment service is still an integration prerequisite.
Do not route HFL objections to `/api/citizen-proposals/:id/objections`.

The UI does not publish amendments, resolve dissent, grant review approval, transfer
votes, call AI or imply consensus. The integrator must provide lawfully public,
consented AI inputs and provenance (model/version, generation source and human
review record where available). Unavailable alternatives are an empty list, never
fabricated output. No private journal/draft/storage data is read or attached.

## Acceptance and evidence

Implemented: full verified source; optional consented public objection; unresolved
and responded dissent; no-change beside equally presented AI candidates; complete
removed/added text with non-color labels; per-version attribution/provenance,
editorial state, window and denominator; fresh explicit response consent; generic
save/load errors that do not disclose backend/private error text.

Support/all uses N=S+O+U; support/decisive uses D=S+O. Both denominators are shown.
N=0 displays No responses and undefined ratios; D=0 displays undefined decisive
support. No threshold, quorum, electorate verification or consensus rule is
invented. Counts remain advisory and never establish agreement by residents,
governmental authority, or merge authority. Unresolved objections are not silently
resolved by popularity.

Automated focused tests cover source/parent/hash/window isolation, private objection
filtering, malicious source and amendment markup, zero/all-unsure denominators,
full redlines, loading/error live regions, labeled native controls, explicit
consent, retained input and stable retry IDs, durable receipts, error focus recovery,
exact amendment revision/round writes and revision reset. The DOM walkthrough runs
in a separate process to avoid global DOM interference with repository tests.
CSS uses fluid single-column controls, wrapping long source text/digests, 44px
buttons/selects, visible focus and no animation. Native forms/selects/checkboxes and
named regions support keyboard and screen-reader interaction.

Manual acceptance remains: actual 390px/200%-zoom layout, native keyboard-only
flow, screen reader announcement/redline comprehension, real adapter authorization,
server-time boundary/restart journey, and human assessment of AI neutrality,
provenance and privacy. DOM checks do not establish those results. No production
ballots or consenting-user pilot were exercised. Integration and human acceptance
remain outstanding; keep SHE-1028 open.
