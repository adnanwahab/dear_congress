## Implementation contract for follow-up

1. Establish a read-only, authoritative event projection before building playback.
   Bind every event to source repository, item kind, item ID, event ID and immutable
   before/after revisions. Include an explicit event category, source occurrence
   timestamp, verification provenance and a durable diff target that resolves
   those exact revisions. Keep official, citizen/unverified and demo namespaces
   separate; never infer eligibility from totals, polling dates or tracker labels.
2. Define substantive eligibility server-side: proposal text, cited evidence,
   revision or status changes only. Exclude tallies, repeated refreshes, cosmetics
   and synthetic activity. Deduplicate by stable event identity; order by source
   time with a stable tie-breaker. Fail closed on missing revisions, unavailable
   verification, withdrawn/private content or broken diff bindings. A failed fetch
   is unavailable history, not proof that nothing changed.
3. Use an opaque scope-bound cursor for the last successful visit, with a frozen
   response boundary and pagination. A first visit establishes a baseline without
   claiming unseen history. Do not advance it on failed or partial loading. Define
   retention gaps explicitly; do not silently drop events while promising a full
   recap. Browser storage failure must leave the ordinary site usable and explain
   that return-visit history is unavailable. Store no journal text or ballots.
4. Offer an explicit Play control and an always-available static summary. Show each
   beat's timestamp, source, category and exact diff link. Keep playback to 20
   seconds with a clearly described selection if there are more events than fit;
   retain the full eligible list in the static summary. Provide native Skip and
   Replay controls, stable focus and immediate cancellation on unmount/navigation.
   Opening, skipping and replaying must never publish, vote or contact an office.
5. Reuse `runViewTransition` with a new typed, scoped transition if animation is
   needed; respect unsupported and callback-only browsers. Reduced motion and
   motion-off expose the static summary without a timed sequence. Keep the
   20-second content clock independent of slow-mode visual duration scaling.
   Stop playback when motion preferences change, the page hides or a diff opens;
   require an explicit restart rather than advancing unseen beats.

## Required acceptance evidence

Test eligible and ineligible event fixtures, equal-time ordering, duplicate pages,
scope collisions, changed PR head/base, stale cursors, retention gaps, missing
timestamps/revisions and unavailable diff targets. Confirm demo counts, real
browser preferences and verified participation never share a recap projection.

Exercise loading, retry, true empty history, first visit, corrupt/blocked storage,
partial responses and navigation races. Verify a 20-second opt-in run, Skip,
Replay, no autoplay, static links, cancellation and zero write requests. Cover
touch activation, keyboard-only focus order, screen-reader announcements, narrow
screens/zoom, dynamic reduced motion, motion-off/slow and unsupported transition
APIs. DOM assertions alone do not establish native browser or assistive technology
acceptance. None of these recap-specific behaviors is implemented or accepted here.
