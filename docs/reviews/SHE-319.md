## Proposed bounded spike before the 3–6 week implementation

Use disposable local data and a separate prototype boundary. Timebox the first
spike to 3–5 working days; this is a planning proposal, not a delivery promise.
Prove offline refresh, encrypted persistence, crash-safe autosave, recovery and
excerpt-only publication with network capture before expanding to optional sync.
Stop for redesign if durable storage, lost-response handling or concurrent edits
cannot be demonstrated without draft disclosure or data loss.

1. Build a private editor with no dependency on public feed/schema availability.
   Cache only a versioned app shell/static assets for offline reload after an
   initial successful visit. Exclude API responses, private exports, admin pages
   and decrypted content from service-worker caches. First-ever offline visits
   cannot fetch an uncached application. Plan cache upgrade/rollback tests.
2. Store a versioned encrypted envelope in IndexedDB: opaque vault/entry IDs,
   revision/parent IDs, algorithm version, nonce and authenticated ciphertext.
   Encrypt text, title, timestamps and private metadata where feasible. Use
   transactions and revision comparison so stale tabs cannot overwrite a newer
   version. Display saved only after commit; quota/transaction failures keep
   unsaved text visible and offer export. Never silently fall back to plaintext.
3. Prototype a random vault data key and authenticated encryption using browser
   cryptography (candidate AES-GCM with a fresh nonce on every encryption and
   envelope identity/version bound as authenticated data). Wrap the vault key
   with a high-entropy recovery secret; persist only wrapped keys. Keep unlocked
   keys in memory, not localStorage. Cryptographic format and implementation
   need specialist review before use with real sensitive entries. If a passphrase
   is added, review its KDF and mobile work factors separately; no custom crypto.
4. Explain and exercise recovery before trusting the vault: losing both the
   unlocked device and recovery secret means losing access; server staff cannot
   reset end-to-end encryption. Import validates version, bounds and authentication
   before mutation; wrong keys/corrupt files leave current data intact. Encrypted
   export is default. Any plaintext export requires an explicit warning and action.
5. Add deliberate sharing of a separate editable excerpt. The exact final public
   text, display name, optional location, downstream extraction/provider use,
   public API visibility and deletion limits appear before explicit confirmation.
   Redaction is user-reviewed; automated suggestions cannot guarantee anonymity.
   Freeze that reviewed payload and invalidate confirmation on edits. Allowlist
   only its public fields: no private draft, key, private revision, attachment,
   selection context or hidden metadata in requests, URLs, errors or logs.
6. Add publication idempotency bound to browser owner plus exact public payload.
   Persist a local encrypted receipt/pending state so a lost response can be
   reconciled without duplicate posts or uploading the draft. Moderation-pending,
   rejected and published are distinct outcomes; private autosave must continue
   regardless. Do not queue publication automatically while offline: require
   explicit confirmation of the final excerpt when online.

## Optional sync and conflicts

Ship the local-only proof first. Sync is disabled until explicit, separate consent
explains remote ciphertext and metadata exposure, retention, account/device
authorization and recovery. A public share never opts the vault into sync.
Future sync needs an authenticated ownership contract independent of advisory
votes; do not treat the anonymous browser cookie as multi-device vault identity.
Stopping sync cancels queued uploads and does not publish or erase drafts.

Use opaque revision IDs and conditional writes against a known base revision.
Reject stale writes with a conflict response and retain both encrypted branches;
never use last-write-wins or a timestamp as authority. Decrypt and compare locally,
offer keep-both or an explicit merged revision, and retain both inputs until the
resolution commits. Treat import collisions and concurrent browser tabs likewise.
Deletion needs versioned tombstones so reconnecting devices cannot resurrect an
erased entry; concurrent edit/delete requires explicit resolution. Define remote
purge, device revocation, key rotation and backup retention before sync launch.
Do not infer these guarantees from an encrypted upload alone.

## Revocation, erasure and threat review

Keep share receipts separate from draft revisions. Revoke through verified public
entry ownership and refresh all active public surfaces; the private draft remains
unless separately erased. Explain cookie loss and maintainer removal options from
SHE-284. Removal cannot recall screenshots, third-party copies, provider retention
or independently reviewed proposal text. Preserve existing proposal/source IDs,
ballots, receipts and immutable PR head/base bindings.

Erase local drafts only after explaining the scope: encrypted records, wrapped
keys, local share mappings, pending operations and memory references. Handle open
tabs and in-flight saves so they cannot recreate erased data. Do not erase the
vision board, votes or unrelated storage. Browser/OS backups and physical media
make guaranteed forensic erasure an unsupported claim. Recovery files remain the
user's responsibility. Public revocation is a separate operation with its own
success/failure status, especially when offline.

Security review must cover locked-device theft/storage inspection, key/nonce
generation and reuse, envelope tampering, import denial of service, crash recovery,
stale tabs, service-worker upgrades, clipboard/download exposure and unlock/lock
behavior. At-rest encryption does not protect an unlocked page from same-origin
XSS, a malicious extension, compromised dependencies or an attacker controlling
the delivered application. Maintain CSP and dependency review; avoid third-party
scripts in the vault. Do not claim browser key deletion guarantees memory wiping.

Audit all fetch/beacon/WebSocket/EventSource traffic, previews, provider calls,
console/error reporting, request-body logging and hosting logs using a distinctive
private sentinel. No private text, keys or content-derived labels may reach them.
Prefer no vault interaction telemetry; any operational counts must be content-free
and explicitly documented. Recheck DEBUG_REQUEST_LOGS and failure paths, not just
successful publication. No third-party extraction of private drafts is authorized.

## Acceptance evidence required before implementation is accepted

| Criterion | Positive verification | Negative verification |
| --- | --- | --- |
| Offline autosave/refresh | On mobile and desktop, load once, disconnect, edit, await durable save, refresh and unlock identical text. | First visit offline, blocked storage, quota exhaustion and interrupted writes show honest status; no plaintext fallback or false saved indicator. |
| Excerpt isolation | Capture requests and persisted public state; only the frozen reviewed excerpt and approved public metadata appear. | A sentinel existing only in unshared text is absent from APIs, previews, SSE, provider mocks, caches, telemetry and logs; cancel/edit/offline causes no upload. |
| Export/import/recovery | Round-trip authenticated encrypted backup in a clean browser with recovery secret. | Wrong key, corruption, oversized/unknown versions and collisions do not destroy existing entries or expose decrypted content. |
| Revocation/erasure | Revoke one share through ownership; verify public feed/state/list/SSE/needs exclusion. Separately erase drafts across open tabs. | Other browsers cannot revoke; lost cookies do not grant ownership; reconnect/reload cannot resurrect deleted drafts; unrelated data and records survive. |
| Conflict handling | Concurrent tabs/devices/import retain both revisions and commit an explicit resolution. | Stale writes, clock skew, retries, interrupted resolution and edit/delete races never silently discard edits. |
| Keys/storage/telemetry | Reviewer inspects locked IndexedDB/cache/export and network logs with provider/error mocks. | No readable private text or raw persisted unlock keys; tampering fails closed; consent-off sync sends nothing after reconnection. |

Add explicit automated positive/negative tests and browser journeys against the
SHE-281 production-equivalent revision with disposable data. Exercise actual
`/journal`, not just older JournalView. Test keyboard-only unlock/share/conflict/
export/erase flows, dialog focus and restoration, labeled recovery controls,
screen-reader save/error announcements, 200% zoom and narrow mobile layout on
Safari/iOS and Chromium/Android. Native mobile/browser and accessibility acceptance
have not been performed here. Security review must record reviewer, revision,
findings and disposition; a proposed design is not a passed security review.
