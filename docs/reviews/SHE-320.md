## Proposed contract and architecture

Implement a separate opt-in ingestion prototype behind a disabled flag, using
disposable synthetic stores. Do not migrate existing journals or repurpose civic
votes, verified repository ballots, moderation logs or receipts. Reconciliation
must preserve original source repository IDs, source entry IDs, real/synthetic
classification and PR head/base revision binding. Never infer consent from an
existing public journal or claim legacy browser IDs for a new identity.

Flow: authenticated regional gateway → durable regional queue → validation and
PII quarantine → consent-aware analysis workers → regional contribution store →
privacy-filtered aggregation/read cache. A separate durable consent/deletion
control stream and audit store govern every stage. Infrastructure/vendor selection
is deferred to architecture review; the existing JSON DB is not that queue.

1. Gateway resolves tenant and permitted residency region from server-controlled
   credentials, not request fields or coordinates. Retain browser same-origin,
   cookie, body-bound and authorization protections; service clients need scoped
   credentials. Validate schema, size, consent and quota before accepting text.
2. Envelope: schema version, event ID, original source ID, tenant, residency
   region, pseudonymous subject, purpose/consent version, subject generation,
   server timestamp, idempotency key, payload digest and encrypted payload
   reference. Do not log text, precise location, raw IPs or identifiers. PII
   detection before provider egress remains mandatory; encrypted queues and
   quarantine are still personal-data stores, not exemptions from deletion.
3. Partition by tenant + residency region + hashed subject. Preserve per-subject
   order within a partition; use generations to handle cross-stream races.
   Keep cross-tenant workers, encryption contexts, storage authorization and
   regional routing isolated. Use dedicated partitions/quotas for large tenants
   when shared partitions produce hot spots. Do not key on political beliefs.
4. Return 202 with an opaque receipt only after durable replicated acceptance
   and an atomic idempotency record/outbox commit. Receipt means queued, never
   published, analyzed or counted. Ambiguous timeouts retry the same key.
   Scope keys by tenant, region, subject and operation; identical retry returns
   the same receipt, conflicting payload returns 409 without side effects.
   Proposed key window is seven days; expired keys return an explicit expiry
   response requiring a deliberate new publication, never silently replay.
5. Workers claim at least once. Commit contribution + processed-event marker
   atomically, then acknowledge. Crash/replay must not double-count. A new text
   with a new ID is not automatically spam or a duplicate: avoid suppressing
   legitimate repeated participation through global text hashes.
6. Validate purpose, generation and consent immediately before analysis and
   again at contribution commit. Provider calls require a separately recorded
   purpose grant and approved retention/deletion terms. When unavailable or
   unauthorized, hold safely or use an explicitly selected local method; never
   silently send text to another provider. Publish quality/fallback labels.
7. Serve aggregates from derived contributions, never from retained raw text.
   Apply minimum-cell suppression and query/privacy review; the current
   minimum-three geo heuristic alone does not prevent differencing attacks.
   Journal publication requires separate explicit consent and moderation.

## Consent, deletion and retention protocol (proposed)

Versioned grants distinguish private analysis, external-provider processing,
public journal publication and optional location. Default each off. Record policy
version, scope, server time and receipt without copying text into audit records.
Withdrawal advances a subject generation and denies new work immediately once
the authoritative write commits. A delete API returns a pending receipt, not a
claim of completed erasure. Lost-cookie recovery needs a reviewed support path;
anonymous IDs must not be presented as verified human identity.

Deletion controller enumerates raw objects, queue payloads, quarantine/DLQ,
analysis outputs, contributions, search/vector indexes if introduced, caches,
replicas and approved providers. Each adapter records a generation-specific
acknowledgement in the deletion ledger. Remove contributions and recompute or
subtract aggregates transactionally; invalidate versioned caches before marking
active-store completion. Retain content-free source references where needed for
existing proposal provenance; do not rewrite independently reviewed proposals or
governance history. Publication/removal policy must explain those separate records.

Consumers check the deletion fence on replay and before every output commit.
If consent authority is unreachable, analysis/publication fail closed. Reserve
control-plane capacity so deletion cannot starve behind an ingest flood. Keep
tombstones until all replayable queues/backups and idempotency windows expire;
prevent identifier reuse. Separate content-free long-lived audit requirements
from personal-data mappings and review the remaining linkability.

Provisional retention budgets, requiring privacy/operator approval before use:
raw text at most 24 hours from receipt, queue/DLQ payloads at most 24 hours,
quarantine at most 24 hours unless the user explicitly requests reviewed retention,
derived per-subject contributions at most 30 days and encrypted backups at most
30 days. Auto-expiry must remove dependent data, not just raw objects. Minimize
text by deleting it earlier on successful extraction. No unbounded retry storage.
Use erasable per-subject encryption keys where physical queue removal is impossible;
verify key copies/caches/backups cannot decrypt deleted payloads. Encryption alone
does not establish erasure. In a quarantined restore, apply current tombstones
before enabling any read or worker; test expired keys and external-provider copies.
Do not declare full deletion complete until backup expiry/key-erasure and provider
evidence satisfy the agreed policy. Unverifiable provider deletion blocks that claim.

## Explicit planning targets and capacity curves

All numbers below are design assumptions, not measurements. N = accepted unique
events/day, mean rate λ = N/86,400, peak factor F = 10 for a 15-minute burst.
Count duplicates, rejected attempts and retries separately. Model hostile traffic
as additional offered load; quotas reject it before expensive processing.

| N/day | Mean events/s | 10× peak events/s | 15-minute peak events | Payload GB/day at 2 KiB | Three-copy payload GB/day |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1M | 11.57 | 115.74 | 104,167 | 2.048 | 6.144 |
| 10M | 115.74 | 1,157.41 | 1,041,667 | 20.48 | 61.44 |
| 300M | 3,472.22 | 34,722.22 | 31,250,000 | 614.4 | 1,843.2 |

GB here is decimal; the 2 KiB envelope assumption excludes indexes, audit,
protocol framing, backup and derived-data amplification. At 300M/day the raw
three-copy 24-hour footprint alone is ~1.84 TB. Test 0.5/2/16 KiB mixtures and
the existing API's actual size boundary; 16 KiB is a stress payload assumption,
not a change to current limits. Test peak factors 3, 10 and 30.

Proposed service objectives: monthly durable receipt availability 99.9%; gateway
p95 ≤250 ms/p99 ≤1 s; receipt-to-aggregate p95 ≤60 s/p99 ≤5 minutes at admitted
mean and planned peak. Measure moderation latency separately. Deletion fence p99
≤5 s, active-store deletion p99 ≤15 minutes, all requests within 24 hours or
escalated as incidents; backup completion within the declared 30-day horizon.
These targets need owner review and full-system measurement, including failures.

For measured per-partition safe throughput c at the latency SLO, choose partitions
P ≥ ceil(peak/(0.7c)), then verify tenant skew and replica-loss performance. For
worker service time s seconds and utilization target 0.7, concurrent workers
W ≥ ceil(peak × s / 0.7). At 300M/day, s=0.02 requires ~993 concurrency slots;
s=0.2 requires ~9,921. These are sensitivity calculations, not a sizing result.
Provider concurrency, quotas, CPU, batching and queue bandwidth may dominate.

Queue growth is max(0, arrival−service) × duration. With workers at 2× mean and
a 10× burst for 900 s, backlog is 7,200λ events; at 300M/day that is 25M events
or 51.2 GB logical payload. At normal arrivals it takes 7,200 s to drain, violating
the proposed five-minute freshness SLO. Peak capacity or admission control is
therefore necessary; storage alone cannot make that SLO true.

Gateway quotas are bounded per subject, tenant and region with separate control
budgets. Proposed overload behavior: 429 + bounded Retry-After (1–60 s) before
enqueue when quota is exceeded or queue age reaches 60 s; use 503 + Retry-After
when durable storage/control authority is unavailable. Never return 202 for a
failed enqueue. Clients use exponential backoff with jitter and a retry budget,
retaining the same key; no automatic new-key retry. Gate payload bytes and worker
concurrency too. Compare this proposed queue-age policy with the latency budget
under replay; tune only through review, not by weakening existing beta limits.

### Cost model: reproducible sensitivity, not vendor pricing

Use 30-day months. Let q be total queue charge per million accepted events
including all operations, a be analysis cost/event, b be replicated storage
GB-days, r be storage cost/GB-day, h be measured worker-hours and w their rate.
Monthly cost = fixed regional overhead + 30N(q/1e6 + a) + b×r + h×w +
egress + audit/index/cache + backup + observability + abuse/retry overhead +
operations/support. Avoid double-counting worker compute if included in a.

For a simple independently reproducible curve ONLY, assume combined variable
cost v=$1, $10 or $100 per million events and fixed overhead $300/month:

| Daily volume | Monthly events | v=$1 | v=$10 | v=$100 |
| --- | ---: | ---: | ---: | ---: |
| 1M | 30M | $330 | $600 | $3,300 |
| 10M | 300M | $600 | $3,300 | $30,300 |
| 300M | 9,000M | $9,300 | $90,300 | $900,300 |

Formula is 300 + (30N/1e6)×v. These arbitrary sensitivity inputs are neither a
budget nor a quote; they omit any costs not covered by v. A provider call costing
$0.001/event alone would be $9M/month at 300M/day. Replace assumptions with dated
provider quotes and measured bytes/tokens/CPU, publish low/base/high scenarios
for retention, replicas, invalid traffic, duplicate rate, 30× peaks and regional
failure. Budget alerts should stop optional analysis, never bypass consent.

## Threat model, positive/negative tests and failure runbooks

Trust boundaries are public client→gateway, tenant→tenant, region→region,
queue→worker, worker→provider/store and operator→audit/restore. Attackers include
cookie churn/botnets, malicious tenants, replaying clients, poisoned text,
compromised workers and privileged operators. Prompt content never grants tools
or permission to disclose another tenant's data. Require scoped service identity,
encrypted transport/storage, key rotation, least privilege and audited break-glass.

| Scenario | Required test and operational response |
| --- | --- |
| Retry after lost acknowledgement/crash | Positive: same key returns same receipt after restart. Negative: changed payload gets 409; crash before/after contribution commit never doubles aggregate. Pause affected consumer, reconcile receipt/outbox, replay with dedup. |
| Flood, oversized body, poison event | Valid traffic retains its budget; invalid requests cannot reach analysis. Test cookie churn, spoofed forwarding headers, skew and 100× offered traffic. Trigger 429 before resource exhaustion; isolate tenant, bound retries and quarantine with TTL. Keep deletion running. |
| PII/prompt injection | Dummy contact strings held before provider; false-negative fixtures establish detector limitations. Assert no text/identity leaks in errors, logs or traces. Halt provider egress on leakage, quarantine IDs and invoke deletion; do not paste text into incidents. |
| Missing/revoked consent | Valid scoped grant enables only its purpose. Missing/stale/wrong-subject grant, expired credential and stale generation deny work, including after replay. Pause analysis if consent unavailable, repair authoritative fence, reconcile outputs. |
| Concurrent deletion | Delete during each worker boundary and retry it. Unauthorized tenant/owner gets no receipt or existence leak. Assert all adapter acknowledgements, contribution removal, cache eviction and replay denial; alert on 15-minute lag, stop affected reads if stale. |
| Tenant/region escape | Forged tenant/region/encryption context denied; same IDs across tenants do not dedup or delete each other. Query, cache, object and worker tests must prove isolation. Block route/credential, quarantine affected scope, audit accesses and rotate scoped keys. |
| Queue/disk/provider outage | No durable acceptance means 503, not false 202. Worker/provider outage produces bounded backlog and 429 admission. Page on oldest age >60 s or five-minute freshness breach; restore within quotas, replay small batches and reconcile counts before reopening. |
| Zone/region loss | Proposed acknowledged-event RPO 0 for a zone loss using regional quorum. For full-region loss, default to unavailable if no compliant replica; never silently move personal text across residency boundaries. Test permitted in-region recovery; target RTO 60 minutes with measured restore. Cross-region RPO/RTO stays uncommitted pending residency and replication review. |
| Backup restore/key loss | Restore only into quarantine, apply deletion ledger first, verify undecryptability and all negative reads before traffic. Corrupt backup must fail closed; test lost/rotated key recovery without resurrecting erased content. Never test with production backups here. |

Runbooks must name on-call and privacy/security escalation owners, dashboards,
scoped pause/recovery procedures, rollback revision and evidence locations before
a pilot. No on-call identity or support commitment is invented in this review.
For every incident, reconcile accepted receipts, consent generations and deletion
backlog before resuming. Rollback cannot drop tombstones or revert consent state.
