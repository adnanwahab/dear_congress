Refs: https://linear.app/shel-bernstein/issue/SHE-688/civicplayevidence-studio-data-source-health-console-with-human

## Audit and implemented scope

Read AGENTS.md, readme.md, launch merge policy and the SHE-315 outcome module
review; traced ProposalProvenance, PolicyMeasurements, Documentation/public-guide,
OutcomePoint/OutcomesFile, the fetch script and /api/outcomes. GitHub searches for
SHE-688 returned no PRs. Open PR results included adjacent community work #258–261
and motion work; these are review candidates, not acceptance. The supplied live
/outcomes reference could not be opened through the web tool. Local source is the
implementation authority; live parity is not established.

The existing outcome types retain provider name/URL/caveat, period, fetched date
and fetch errors. No shared ClaimProvenance type or durable human-review/schema
change registry was found in this checkout. Existing proposal background metadata
is editorial, and starter outcome fixtures must not be certified as primary data.

Added a read-only source console beside policy measurements. It consumes the
existing API without writing data, reports missing/conflicting/stale records and
retained-data incidents, and lists affected Needs conditions/measured synthesis
previews. The freshness threshold is explicitly an editorial 30-day threshold.
Recorded fetch date is distinct from observation year and live availability.
Schema changes and material-update human review display unknown/not recorded.
Needs and proposal backgrounds carry visible limitations; public guide and README
explain the console. Native buttons provide retry and copyable dated JSON for
export; visible incidents remain readable for print. Touch targets and visible
focus styles are provided. Raw provider error strings are not rendered as incidents
because URLs/errors can include sensitive connection details.

## Validation and acceptance gaps

- Typecheck passed; 14 focused tests passed, including existing provenance,
  documentation and policy measurement contracts. Three health tests pass after
  the final missing-identity guard change.
- Health evaluator tests demonstrate complete source metadata, conflicting and
  missing-source cases using explicitly fictional records. These are **not** a
  fully sourced real-world case or verification of public measurements.
- Isolated DOM integration covers loading, missing snapshot, offline failure,
  retry and copy/print-text export. Native button semantics support keyboard and
  touch, but real browser keyboard/touch/screen-reader and printed-layout checks
  remain unverified. DOM tests do not establish accessibility acceptance.
- Full `bun test`: 477 pass, 27 fail (504 tests). Server-dependent failures show
  Bun port-0 EADDRINUSE; the suite also reports a native proposal-comparison controls test
  failure. The full suite is not green. Logs: /tmp/she688-final-tests.log.
- `bun run test:routes`: fails at server startup with port-0 EADDRINUSE.
  Log: /tmp/she688-routes.log. No checks were bypassed.
- `git diff --check` passed.

Remaining implementation includes durable append-only material-update provenance
and authenticated human review, provider schema baselines/diffs and ingestion
coverage/release telemetry. The current console accurately exposes their absence;
it does not implement those systems. A steward must select and verify a real
fully sourced case, a substantive conflicting-source case and a missing-source
case, retaining claim kinds, dates and limitations. Provider URLs alone are not
acceptance evidence. No fake measurement fallback was added. Keep SHE-688 open
pending that implementation and human acceptance.
