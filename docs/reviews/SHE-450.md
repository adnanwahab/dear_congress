# SHE-450 — Evidence-first debate tabletop

Refs: https://linear.app/shel-bernstein/issue/SHE-450/joydeliberation-evidence-first-debate-tabletop

## Audit and implementation scope

Read AGENTS.md, readme.md, ArgumentMap and its callers/tests, demo source
contracts, SHE-306 review, motion and accessibility guidance and launch merge
policy. Read-only GitHub search found related argument-map PRs #34 and #60;
a SHE-450 search returned no results. These searches are discovery evidence,
not acceptance or a complete remote inventory. No remote branches were imported.
The live reference could not be opened through the web tool; no deployed-source
parity is claimed. Pre-existing before screenshots in .mini-symphony-evidence
were left untouched and are not evidence of the new behavior.

Implemented the tabletop in the existing shared ArgumentMap, retaining existing
Published, Votes and comparison navigation. The exact fictional transit revision
has equal-width Reasons for and Concerns tracks, each with a lead claim and
counterargument card. Native drag handles reorder within one track. Move up/down
buttons provide touch and keyboard alternatives with 44px minimum height, visible
focus, preserved keyed controls and polite order announcements. Reset restores
editorial order. Reordering is immediate with no animation, including under reduced
motion. Tracks stack on narrow screens.

Every card exposes its fictional editorial origin and stable scoped ID, explicit
missing claim-level source/citation, unreviewed quality, unassessed evidence and a
neutral Why this matters expansion. Proposal-clause links still open the exact
text. Neither agency background pages nor the fictional clause are represented
as empirical evidence. No review status, citation, human reviewer or civic
participation was fabricated.

Personal order lives only in component memory. It never writes storage, calls a
voting API, changes public ranking, or affects fixture tallies. Namespace, proposal
ID and exact text key the inner component, clearing order and pending drag on
scope/revision changes. Unknown or stale revisions retain the existing honest
empty state. Separate instances use unique clause IDs and independent drag state.
No API, persistence schema, source identity, ballot, PR binding, record or receipt
was changed. The public guide now explains this local-only interaction.

  both sides, unknown namespaces and stale revisions, button moves, preserved

  unchanged proposal/tally fixtures with no browser storage writes. The existing
  comparison integration tests also pass.

  network request, spinner or save state. Existing WorkflowScreen owns loading
  and retry; unavailable/stale maps show no reviewed arguments. Route/browser
  loading and offline retry acceptance remains unverified because the isolated
  server smoke could not start.
- Touch/keyboard: buttons are native and focus remains on a moved keyed control
  in DOM testing. Real touch, native drag, Enter/Space activation and screen-reader
  announcement review are still required; simulated DOM is not native evidence.
- Reduced motion: no transition, animation or timing is introduced. Native-browser
  reduced-motion, 320/390px layout, forced colors and actual 200% zoom remain to
  be reviewed using docs/accessibility-acceptance.md.
- Reviewed claims and citations remain outstanding: this repository has no reviewed
  claim-level dataset for this revision. Human evidence curation, source passages,
  review metadata and viewpoint-neutral review must precede labeling cards reviewed.
  The tabletop is a functional fictional prototype, not full issue acceptance.
