## Proposed implementation contract

Build permission and persistence foundations before adding the three UI entry
points. A display-only merge of these datasets would invent history and could
expose private work. No historical draft/source events should be fabricated from
current text, observation time, sample response counts or file modification times.

1. Add an additive, versioned session/artifact/event store with durable,
   server-authorized membership. Bind each artifact to source repository,
   item kind, immutable source ID and exact revision; include PR head and base
   when a repository review is referenced. Session membership must not authorize
   repository ballots or confer moderator/maintainer authority.
2. Record draft snapshots, source additions, decisions, disputes and review
   milestones only after successful authorized writes. Each event needs a stable
   ID, server sequence, recorded timestamp, original artifact reference, event
   kind, provenance and applicable permission revision. Distinguish occurrence
   time from recording time. Preserve raw records and receipts; corrections append
   superseding events rather than rewriting history. Persist action and event
   atomically, with idempotent retries and rollback on failure.
3. Default new shared-session artifacts to personal scope. Require explicit
   per-artifact selection of personal, invite-only or public scope with preview
   and confirmation. Session scope is an upper bound, not permission to widen an
   artifact. Invitation possession alone must not bypass intended-recipient
   authorization; expire and revoke invitations. Reject unauthorized reads,
   artifact links, exports and stream subscriptions on the server.
4. Credit a collaborator only with current, explicit attribution consent for the
   artifact and audience. Separate human self-described identity, verified
   reviewer authority, anonymous browsers, demo messages and synthetic attendees.
   Demo/synthetic content belongs in a visibly separate lane and never enters
   real collaborator counts. Missing consent means no name or identity inference.
5. Provide Leave session, Revoke sharing/credit and Report controls with clear
   consequences. Leave removes future invite-only access; the person's own
   artifact and credit controls must remain accessible through an authorized
   management path. Revocation blocks future reads/exports/stream delivery and
   clears displayed cached content on revalidation. Already downloaded public
   copies cannot be recalled; explain this before sharing.
6. Reports must enter a private moderation queue with bounded input, rate limits,
   authorized decisions and reasons. Moderation hides material from all relevant
   projections without deleting source identities or audit receipts. For
   authorized viewers a neutral unavailable marker may preserve sequence; for
   unauthorized viewers do not disclose hidden event counts, names or titles.
   A report alone must not grant access or automatically settle a dispute.
7. Derive unresolved disputes from the current authorized objection/decision
   ledger, retaining dissent and linking exact artifacts. Never infer resolution
   from inactivity, majority votes or a declined response. A real review milestone
   requires an authoritative review record bound to that exact revision, with
   separate pending, superseded and unverified states. A draft PR and agent exit
   status never imply acceptance.

Apply same-origin, signed-session authentication, CSRF where applicable, bounded
requests and existing write limits. Use expected session/artifact permission
versions for mutations; stale versions return conflict without widening access.
Recheck access on reconnect and every projection/export, not just at join time.
Cancel pending loads and clear prior-session data when switching sessions or on
denial; ignore late responses. Private material must not enter URLs, analytics,
public search indexes or service-worker caches. Audit storage requires a separate
restricted projection and retention policy; an append-only audit is not permission
to keep serving withdrawn content publicly.

## Integration and readable replay

- `CitizenProposals.tsx`: add an explicitly scoped retrospective entry point bound
  to the loaded citizen proposal and revision. Existing publication, comments,
  objections and vote counts keep their contracts. Do not automatically import
  browser drafts or interpret publication consent as session sharing consent.
- `LiveRound.tsx`: link only when an explicit authorized session/artifact binding
  exists. Current demo rounds remain labelled illustrative/advisory. Do not
  reconstruct attendees from voter hashes or equate round termination with review.
- `TopicHubs.tsx`: discover only explicitly public, curated retrospective artifacts
  with recorded topic consent. Personal/invite-only sessions must not leak through
  counts or empty-state wording. Preserve the current sample/human separation.

Use a semantic chronological list with event headings, readable timestamps,
artifact links and visible text scope labels. Manual previous/next controls may
step through events without autoplay. Summaries should show documented changes,
unresolved concerns and missing evidence; elapsed time alone cannot establish
that a process improved or stalled. Offer participant-authored reflection as
opinion with its artifact link, separate from recorded events. Keyboard focus,
status announcements, long-source wrapping, mobile reflow, reduced motion and
unavailable-artifact recovery are required before acceptance.
