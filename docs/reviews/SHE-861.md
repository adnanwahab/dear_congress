# SHE-861 implementation review

Refs: https://linear.app/shel-bernstein/issue/SHE-861/cs-l100038-add-a-launch-specific-homepage-for-journalist-and-civic

Implemented a public `/?audience=launch` overview before the existing interactive
homepage route. A single exact allowlisted value selects the same content for
every visitor. Duplicate/unknown values fall back to existing routing; values
are never rendered. Incoming query data and fragments are not propagated into
share or tour links. No audience storage, sensitive-attribute inference, referrer
inspection, contact collection, outreach or new telemetry is introduced.

The 30-second explanation precedes source methodology, evidence limits and a
self-paced tour of the existing fictional `demo-transit` source/draft/outcome
stages. The optional existing guided tour is linked separately. The page labels
independent operation, non-binding participation, illustrative counts, synthetic
measurements, simulated sponsor outcomes and missing/conflicting/stale evidence.
It does not alter records, source identities, votes, PR head/base bindings or
repository/item-kind isolation. The sole overview share destination is a fixed
relative URL, so it uses the current deployment origin without carrying private
query values. Sharing requires manual browser action.

Audit: read repository instructions, README, public guide, dashboard, tour and
stage contracts, launch merge policy and guarded merge workflow. GitHub search
across all PR states for SHE-861/referral/landing returned no matches; inspected
the recent open PR list, including adjacent launch work (#308 ballot isolation,
#307 telemetry, #305 outreach planning, #304 preview, #303 usability). These remain

## Governance preserved

No governance/workflow configuration was changed. Source defaults remain disabled,
dry-run, quorum 10, 24-hour exposure, one current-head approval, empty base/check
allowlists, active kill switch; browser choices are not verified merge authority.
The existing guarded-automerge workflow schedules eligibility checks and can
merge eligible non-draft main PRs; it skips draft/hold/sensitive/analysis-only work,
requires current-head checks and defers to GitHub protections. Its existence is
not proof that one human approval is enforced. Live settings and protection were
not changed or verified. Human approval and a human-published tagged release
remain required by the repository policy. No PR, merge, release, deployment,
external message or production-data operation was performed.
