## Evidence and audit

Read repository AGENTS.md, readme.md (including public-write security),
docs/launch-merge-policy.md, and the journal, public-security, action request,
advisory mutation and citizen proposal implementations and their tests. Connected
GitHub PR searches for SHE-931, `Retry-After`, and 429/rate-limit terms returned no matches. The local
GitHub CLI could not reach api.github.com; the connected tool supplied the search
results. This is a targeted related-PR audit, not a claim that every PR was reviewed.

The existing server already rejects protected writes before handlers run, shares
IP/anonymous-ID budgets across actions, and supplies remaining fixed-window seconds
in Retry-After. No new limiter or identity mechanism is needed. The actual
`/journal` route renders JournalScreen/JournalSharing, separately from legacy
JournalView. JournalSharing already preserves text and consumes consent on every
attempt, but discarded the error status and header, describing a definite rate
rejection as an unknown outcome and allowing immediate repeated requests. Citizen
proposal publication, votes and comments use a separate fetch helper that also
lost Retry-After, especially for non-JSON proxy errors. Legacy idea submission had
an uncaught rejection path. Existing advisory vote receipts already required an
acknowledgement and retained exact proposal/revision bindings.

## Changes

- Protected 429 responses retain the existing status/header and add
  `code: rate_limited` and matching `retryAfterSeconds`; the message says the
  attempt was rejected. Successful payloads and rate/auth policy are unchanged.
- Shared action errors and the citizen proposal request helper show retry timing,
  including non-JSON 429 responses. Delta seconds and HTTP dates are supported;
  malformed/missing headers use a conservative 60-second local fallback. No
  automatic resubmission is introduced.
- Journal sharing releases busy state, preserves draft/excerpt/name/categories,
  shows a cooldown, and disables Share until the deadline. Retrying requires fresh
  exact-payload review and consent. A new attempt clears any earlier success text;
  rejected attempts never call onPublished. Reload/navigation still loses these
  in-memory drafts; this work does not silently persist private text.
- Advisory upserts reuse the parser while retaining exact-choice retry behavior.
  Legacy idea errors are caught without clearing unsent answers, and a vote save
  attempt clears its previous success notice before making the request.
- Public guide and README describe retry and draft retention limits.

These runtimes are not comparable latency estimates: the passing test waits for
expiry and exercises additional checks. No production latency claim is made.
The final tests additionally cover a 429 after a previous publication, preventing
stale success text from describing a rejected attempt.

For nine protected action paths, deterministic ten-second windows return 429 with
Retry-After 9 after advancing 1.1 seconds; rejected handlers execute zero times,
and an explicit request at expiry succeeds. This preserves the existing boundary
reliability while checking the new structured response and no-store headers.
Advisory tests confirm no receipt until acknowledgement, exact-choice recovery,
and no automatic retry. Citizen request tests cover publish/vote/comment 429s
with non-JSON bodies.
