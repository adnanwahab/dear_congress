# SHE-419 — Who decides? implementation candidate

Refs: https://linear.app/shel-bernstein/issue/SHE-419/joyquest-who-decides-jurisdiction-matching-game

Added a collapsed, explicitly sandbox-labeled four-task matching game beside the
existing browse picker on its existing screens. Reuses the Jurisdiction type and
preference, native controls and workflow provenance styling. Existing civic stage
navigation stays in its shared shell. Browse choice prioritizes its exact scope,
retains other levels for comparison, and resets answers to prevent stale feedback.
No exact location, storage for answers, API calls or new dependencies are used.
All examples are authored educational tasks, separate from real votes, fictional
workflow proposals and model projections. Feedback identifies task-specific
responsibility and explains overlapping authority rather than absolute rules.

Audit: read AGENTS.md, readme.md, launch policy, SHE-347 review; inspected picker,
workflow, source provenance component, shared civic context and simulator snapshot
integration. GitHub PR searches for SHE-419 and open jurisdiction PRs returned no
matches. Existing screenshot evidence files were left intact. The simulator API
creates frozen plan snapshots, not authority facts; invoking it would mix unrelated
model output into this exercise. No simulator integration is appropriate here.

Sources opened 2026-11-14 (linked alongside every task):

- City of Houston 311: https://311.houstontx.gov/
- HCFCD: https://www.hcfcd.org/About
- Texas DPS: https://www.dps.texas.gov/section/driver-license
- State Department: https://travel.state.gov/en/passports.html

Sources support specific service/governance examples, not universal rules or
legal advice. Flood control is explicitly a special-purpose district governed by
Commissioners Court, not a generic county monopoly. Source pages can change.

The game is bundled static content, so it has no independent loading or remote
failure state. It remains usable when surrounding proposal APIs fail. External
source failure has a named-publisher fallback. Native selects/buttons work with
keyboard and touch, controls use 44px minimum heights, feedback has a polite live
summary, and the game adds no animation or motion. Browser visual, touch and
screen-reader checks and civic-content review remain outstanding; DOM tests do
not establish human acceptance. Leave the issue open.
