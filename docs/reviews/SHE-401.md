# SHE-401 — build-a-plan workbench

Refs: https://linear.app/shel-bernstein/issue/SHE-401/joytouch-build-a-plan-budget-workbench-with-draggable-policies

Implemented a separate initially empty $40B fiscal construction kit in each
synthesis package/lane. HTML drag/drop and native Add/Remove buttons use the same
local handler. Totals use integer millions; exceeding the budget retains selections
and explains the exact shortfall. Rights-blocked and invalid/unknown-cost options
cannot be added. No further policy compatibility model exists in Proposal, so the
UI explicitly limits its claims to fiscal arithmetic and rights gating rather than
inventing policy conflicts or rerunning score optimization.

Source IDs, jurisdictions, estimate provenance/caveats, lane labels and an ordered
inspectable change log remain visible. State is component-local and resets with
the existing package/lane key. No API writes, votes, publication, official records,
saved synthesis, existing ledger revisions or ledger download contracts change.
The typed plan-rerank helper handles unsupported transitions and reduced motion.

Audit: read repository instructions, README, fiscal helper/types, motion docs and
launch policy. GitHub PR search for SHE-401 or budget returned the earlier budget
ledger PR #112 (SHE-360); this implementation preserves that ledger. No PR, issue
state, deployment or external message was created by this work.

Validation: focused PlanBudget/PlanWorkbench tests pass (4 tests, 25 assertions),
and bun run typecheck passes. Tests cover loading, empty data, caveats, disabled
rights/invalid-cost options, button activation, drop handling, shortfall/removal,
change history, unchanged inputs and reduced-motion transition skipping. Native
buttons supply keyboard/touch activation without custom gesture requirements;
physical touch, keyboard navigation, assistive technology and rendered responsive
layout still require browser/manual verification. Route smoke was attempted and
failed because Bun cannot bind its isolated server (EADDRINUSE on port 0).
Full suite results are recorded below; this is a review candidate, not acceptance.

Governance remains as documented in docs/launch-merge-policy.md: disabled/dry-run,
quorum 10, 24-hour exposure, current-head approval, fail-closed base/check
allowlists and active kill-switch defaults. No configuration changed. Live policy
and GitHub protections were not independently verified. Human review and required
checks remain necessary; no merge, release or deployment is authorized.
