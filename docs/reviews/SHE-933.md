# SHE-933: traffic quality controls

Refs: https://linear.app/shel-bernstein/issue/SHE-933/cs-l100067-detect-automated-traffic-without-conflating-it-with-unique

## Evidence and scope

Reviewed base ac5212b, AGENTS.md, readme.md participation/privacy/metrics guidance,
docs/launch-merge-policy.md, AccountScreen, launch-stats, launch-stats-http and
public-security with their focused tests. GitHub PR searches for SHE-933 and
traffic/abuse/stats found no matches; the open-PR listing includes parallel
SHE-968 SLO, SHE-973 dependency monitoring and SHE-977 fixture isolation work.
Those candidates are not acceptance evidence and were not modified.

The existing protected dashboard separated accepted page views and saved choices
but called cookie-derived identities “voters.” Existing controls reject origin,
payload and rate-budget violations without recording quality reason totals.
Cookies cannot prove one human; successful API calls cannot prove human intent.

## Implemented candidate

Add a separate additive SQLite daily reason-counter table; preserve all old rows,
identity hashes, repository/item scopes, target revisions and receipts. Observation
is opt-in (`TRAFFIC_QUALITY_MODE=observe`), limited to rejected page-view POSTs.
Only day, fixed reason and count are written. Existing guards, status codes,
retry headers, auth, cookie behavior and acceptance rules remain unchanged.

The authenticated dashboard separates suspicious request totals, route event
counts and saved-choice identities; it never subtracts suspicious requests from
choices or promotes unflagged requests to verified humans. Signals cover rejected
page-view requests only, not all server traffic or automated ballot submissions.
No fictional participation is introduced. Existing snapshot field names remain
compatible; human-facing “voter” headings are corrected.

Account guidance documents same-origin, allowlisted route, 1 KiB JSON and
120-per-network-address per configured window limits (default ten minutes).
The existing limiter can also reject at its capacity/shared page-view budget;
`rate_limited` reports the guard outcome, not proof of a particular IP offender.
The public issue tracker accepts rule review requests with route, approximate time
and status, without credentials or IPs. Shared networks and broken clients are
explicit false positives. No private appeal channel or review SLA is configured.
Human usability/privacy review of this limited appeal path remains outstanding.

## Reversible staged rollout

1. Keep collection off; review this revision and all required checks locally.
2. A human release owner may authorize a tagged release and a time-bounded
   observation pilot. Existing protections stay enabled. Compare completeness,
   errors and dashboard latency against the off baseline using disposable local
   data first; review shared-network false positives before any broader pilot.
3. Roll back collection by unsetting the flag and restarting. Existing counters
   remain historical, not evidence of current collection; no civic data deletion
   or destructive schema rollback is needed. Observation never enables new blocking.

No production rollout, public load test, external message, merge, release, issue
transition or production data write occurred. Leave Linear open pending human
acceptance and operator evidence.

## Local measurements and validation

In-process, sequential, 100 cross-origin page-view requests per mode against
in-memory SQLite, no listener or public network. Off baseline: p50 0.00150 ms,
p95 0.00604 ms, expected 403 responses 100/100. Observe: p50 0.01996 ms,
p95 0.03738 ms, expected 403 responses 100/100. These tiny local samples include
warm-up/order effects, omit disk/network costs and are not a production latency
claim. The added observation cost warrants a bounded operator pilot.

Focused launch-stat tests: before 9/9 passed (40 ms); after 10/10 passed
(67 ms), including opt-in behavior, each reason, unchanged saved choices and
no exposed private identity/address. Suite durations are not request latency.
Dependencies were initially missing; `bun install --frozen-lockfile` restored them.
`bun run typecheck` passed. Required route smoke was attempted but cannot bind
Bun's local listener in this environment (EADDRINUSE on port 0). Full `bun test`: 665 passed, 26 failed in 24.07 seconds; failures occurred
in listener-dependent integration tests with server startup/bind errors. These
failures are not passing checks. `git diff --check` passed.
