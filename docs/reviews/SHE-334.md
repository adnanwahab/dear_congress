# SHE-334 — stage prerendering

Refs: https://linear.app/shel-bernstein/issue/SHE-334/demomotion-prerender-the-next-stage-so-page-changes-feel-instant

Read AGENTS.md, readme.md, launch-merge-policy.md and the SHE-323 review. Audited

Initial HTML now includes document speculation rules matching only same-origin
/published, /feed, /votes, /draft, /sponsors, /outcomes, /map and /journal anchors,
including query-bearing proposal links. Downloads and explicit target links are
excluded. Moderate rules cover all eight destinations; eager rules prioritize the
next route from shared civic stages. There is no fetch/prefetch fallback; browsers
without Speculation Rules retain ordinary links. Chromium can decline speculative
work based on resources or user settings, so latency cannot be guaranteed.

The HTML response is no-cache (not no-store); the security wrapper has no blocking
Clear-Site-Data or sandbox header. CSP grants only inline-speculation-rules, keeping
inline executable scripts blocked. This narrow token is necessary for inline rules.
Implementation follows Chrome's platform guidance:
https://developer.chrome.com/docs/web-platform/prerender-pages

startPageViews suppresses all recording, including history navigation, while
prerendering and records the current path once on activation. It currently has no
production caller in this checkout; this change does not newly enable analytics.
The existing journal EventSource in LegacyApp waits for activation and closes on
unmount; JournalScreen itself loads read-only entries/schema and has no EventSource.
Eligible stage mount requests are GETs; votes, journal publication and other remote
writes require user interaction. No API write paths, identities or stored records
were changed.
