## Candidate behavior

`src/shared/claim-provenance.ts` defines revision-bound claims, source identity and
version, section/page/line/excerpt locators, retention permission, reported redirect,
classification, dates, limitations and per-revision provenance/human review history.
Anchor IDs depend on claim ID/revision and source identity/version/locator, not
claim ordering or display text. Corrections must receive new revisions; old records
must remain available. This is a typed local contract, not a durable ingestion or
editing API, and it does not enforce append-only history in a database.

`ClaimEvidence` uses native links to highlighted retained passages, accessible
section targets and descriptive external links. Unsafe/credential-bearing URLs
are rejected. External-only records omit excerpts from UI and export. Missing
quotes, links and sources and reported redirects stay visible. No redirect probe
or external availability verification is claimed. Loading/offline/error presentation
preserves supplied quotes; this component makes no network requests.

The outcomes measurement area offers a separate, explicitly labeled demonstration:
application behavior supported by a pinned repository source, conflicting fictional
wait/fare metrics, an unsupported fictional user claim, and a synthetic estimate.
These demonstrate all four evidence classes. The primary source is application
code, not evidence of real-world policy effects. All review states remain Pending.
Existing scenario background links are not promoted to claim evidence.
ProposalProvenance accepts optional explicit claims, preserving its current defaults.
The public guide explains anchors and limitations; Documentation uses that guide.

Plain text fallback includes dates, limitations, review state and source versions.
Print CSS exposes nested measurement/evidence disclosures and external URLs. Native
links and padded controls support keyboard/touch; focus and target outlines provide
non-color-only location cues. Native browser keyboard/touch, screen reader and
actual print/PDF layout still require verification; static markup tests cannot
establish those acceptance criteria. Offline states are supplied explicitly; this
is not a service worker or offline shell cache.
