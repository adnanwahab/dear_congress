## Proposed operational flag matrix

One validated, revisioned operator configuration supplies these four booleans.
Names are proposed interfaces, not runnable environment settings. Normal defaults
are false. A minimum severity is cumulative; an operator may pause writes at any
level immediately. Clients may request stricter motion, never weaker controls.

| Level | DISABLE_ANIMATIONS | BYPASS_SIMULATION | CACHED_PUBLIC_READS | PAUSE_WRITES | Public behavior |
| --- | --- | --- | --- | --- | --- |
| L0 normal | false | false | false | false | Existing behavior and participation disclaimers |
| L1 calm | true | false | false | false | No decorative animation, audio or transitions; retain focus/status feedback |
| L2 compute shed | true | true | false | false | Stop new synthesis/model calls, previews, automatic retries and autoplay; retain labeled prior results |
| L3 read-only safe | true | true | true | true | Serve allowlisted public snapshots; reject mutations before side effects |

At L2, unavailable compute returns 503 with a bounded Retry-After (initially 60
seconds) and a stable `simulation_paused` error; do not replace it with fictional
results. Cancel browser requests and discard late results; remote cancellation
may not stop provider execution. Saved synthesis is also blocked by the compute
gate. Existing completed results retain original model/version/time labels.

L3 must gate every mutation and alias, including journal/publication/correction,
votes and ballots, proposals, live sessions, feedback, snapshot creation, reset,
moderation, signed internal jobs, sync and outbound publication. Inventory reads
that create cookies, sessions or SQLite/cache records; suppress those effects or
exclude them from the safe surface. Drain already admitted work before declaring
the write fence active; record unresolved operations as unknown, never successful.
Do not acknowledge blocked requests with 200/201/202 or create success receipts.
Return 503, `writes_paused`, Retry-After and no-store. Existing 429 admission
limits retain their meaning and auth/CSRF checks remain enforced. No implicit
client queue or automatic replay of ballots/submissions on recovery.

UI copy: “Read-only mode: new submissions and votes are temporarily unavailable.
Nothing from this attempt was saved. Public information below was last refreshed
at [UTC time].” Use the nothing-saved statement only for pre-admission rejections;
timeouts after admission say “Save status unknown; check the existing record
before retrying.” Disable controls with visible reason and accessible status,
retain unsent text locally in page memory without adding persistent storage.

## Cache and privacy contract

Initially allow only reviewed static `/`, `/documentation` and `/docs` snapshots
and their content-addressed assets. A normal HTML shell that fetches live APIs
is not an adequate fallback: the safe shell must suppress live fetches, telemetry,
simulation and writes. Add other public pages only after route-specific review.
Never cache `/api/state`, accounts, cookies, journals, personalized feeds, auth,
admin pages, live sessions, ballots or receipts in shared storage. Exclude unknown
query strings. Keep health/version uncached and tied to the responding process.

Key snapshots by repository identity, release SHA, route, locale and schema;
publish atomically with a generation timestamp and a five-minute maximum age.
If absent/expired, return a minimal informative 503 page, not a fabricated feed.
Preserve CSP/security headers; do not replay Set-Cookie. Dynamic publication or
tally caches require a separate deletion/moderation invalidation fence: if it
cannot be guaranteed, exclude them. Never resurrect removed content on rollback.
Existing synthetic/sample labels remain; stale counts cannot imply current or
verified participation. No voter inference or new identity tracing is introduced.

## Proposed SLOs, thresholds and ownership

These are initial engineering targets, not measured production commitments.
Use aggregate route-class histograms without identity, journal bodies or query
payloads. Count timeouts and failures; separate intentional 429/503 shedding
from successful service so the dashboard cannot hide lost write availability.
Target public read availability 99.9% per rolling 30 days and p95 <=1 second in
five-minute windows; admitted writes target 99.5% durable acknowledgement and
p95 <=2 seconds. Track all offered valid write attempts separately, including
paused attempts. Liveness must not substitute for either SLI.

| Trigger | Minimum response |
| --- | --- |
| Read p95 >1 s for two consecutive 5-minute windows, >=100 samples each | L1; inspect CPU, event-loop delay and dependency latency |
| Read p95 >2 s or compute failure/timeout >5% for one 5-minute window, >=100 samples | L2 |
| Read 5xx/timeouts >2% or admitted write failures >1% for 5 minutes, >=100 samples; persistence failure or suspected false acknowledgement at any volume | L3 immediately for durability faults; otherwise operator confirms L3 |
| Too few samples | Mark insufficient evidence; investigate discrete failures and use operator judgment, not a claim that SLO passed |

Proposed accountable owner: repository maintainer Adnan; primary incident
operator and backup must explicitly accept a dated shift and escalation channel
before rollout. This document does not claim acceptance. Operator records level,
config revision, reason, timestamp and release SHA; maintainer owns reopening
writes. Privacy/security reviewer owns cache and deletion review. Follow the
launch-alerts escalation plan; no messages are authorized by this review.

## Reversible rollout, measurements and rollback

1. Implement flags default-off in an isolated branch; enumerate all dispatch and
   background paths. Use disposable JSON/SQLite state, dummy identities, no
   service credentials or outbound network. Verify source/repository/item kind,
   PR head/base and ballot/receipt isolation remain unchanged.
2. Before enabling a flag, collect baseline at L0 on that exact candidate build.
   Proposed safe local plan: sequential read mix of the allowlisted pages and
   fixture APIs, then at most 5 requests/second, concurrency <=2 for five minutes.
   Use synthetic mutations only in disposable storage. Stop on any data invariant
   violation, memory >75% of sandbox allowance or >5% unexpected failures.
   This plan authorizes no traffic against the public Fly URL.
3. Repeat identical workload/seed at each level, then L0 recovery, three times.
   Record timestamp, build/config revision, machine/runtime, sample count,
   offered/accepted/rejected/unknown writes, read/write p50/p95/p99 in ms,
   timeouts, response codes, CPU/RSS, event-loop delay and persistence drain time.
   Compare paired baseline/after runs; report shedding separately from latency.
   At L3 prove zero newly admitted mutations, unchanged persistent records,
   no new success receipt, no background outbox send and no cross-user cache data.
4. Exercise stale/missing cache, deletion, provider outage, in-flight write fence,
   restart, lost acknowledgement, every alias and config disagreement. Browser
   verification covers desktop/mobile, keyboard, reduced motion, readable stale
   banner and rejection/unknown wording. Required checks must pass on that SHA.
5. Human review selects a release and confirms owners/thresholds. Any later
   production pilot needs separate authorization, a human-published tagged
   release and provenance verification; no production rollout occurs here.

Recovery requires no persistence errors, reconciled unknown writes and a drained
save queue, plus read p95 <800 ms, read errors <0.5% and admitted write errors
<0.1% for three consecutive five-minute windows with adequate samples. If writes
are paused, prove durability with isolated probes rather than assuming zero
admitted errors means healthy. Restore one level at a time with 15-minute
observation. Reopen writes only on explicit maintainer decision and reconciled
records; never replay requests automatically. Re-escalate immediately if a
threshold recurs. For a bad flag implementation roll back to the last reviewed
compatible image/config while retaining the external write fence until verified.
Never restore an older database, discard votes/receipts or reset governance.
