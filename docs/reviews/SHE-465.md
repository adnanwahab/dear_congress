## Behavior and typed contract

`POST /api/live/:code/questions` accepts `QuestionAction` from
`src/server/live-questions.ts`, returns `LiveSnapshot`, and broadcasts through the
existing coalesced SSE stream. The existing signed browser identity, same-origin,
bounded JSON, no-store responses and shared IP/identity limits apply unchanged.
Actions are submit, approve (optional approved groupId), hide, next, upvote, report.
Unknown actions and invalid text/names are rejected. Round end/expiry rejects all
question mutations, including moderator actions.

Questions accept optional self-described names, otherwise Anonymous. Every
submission waits for owner-browser moderation. Only the presenter receives
pending text/names and report counts. Public projections contain approved questions
and the current browser's own upvote/report flags, never browser identity sets.
Text is rendered as React text, not HTML. The submit notice explains publication,
privacy, cookies and temporary retention; failures preserve the draft for retry.
The public guide explains the same trust boundaries.

On approval, NFKC/case/punctuation/spacing-normalized exact matches group
automatically. A presenter can select an existing approved group for differently
worded duplicates. Grouping retains the first approved wording/name and counts
submissions, not unique people. Matching is deliberately deterministic rather
than a claim of semantic equivalence; presenter review handles other duplicates.
Hidden/merged originals remain private in round memory, not deleted or migrated.

Show next question fairly selects the least-shown approved group, using insertion
order for ties. Each selected group increments its turn counter. Counts survive
reconnect. Upvotes do not affect this rotation. Rotation is manual, with no timers,
transitions or animations introduced, including under reduced motion. Hiding the
current group clears the screen. Reports are idempotent advisory browser signals
for presenter review, not automatic censorship or verified abuse findings.

Abuse bounds: 500 characters of question text, 60 of name, five submissions per
browser per round, 200 total submissions per round, 10,000 browser interactions
of each kind per question. Pending/hidden IDs cannot be used by audience clients
for reports or upvotes. Clearing cookies can evade browser limits, so this is
not unique-person verification. Existing shared-IP write limits can constrain a
busy town hall and have not been weakened.

The board is separate from round ballots, database votes, synthesis, attendance
and merge authority. Question upvotes never change ballot totals. Existing round
expiration, one-process in-memory storage, capacity and restart-loss limits remain.
Multiple replicas still require shared storage/pub-sub before use.

## Remaining human acceptance

This is not full browser or accessibility acceptance. On a disposable local server:

1. At desktop and 390px touch widths, join from a separate browser. Submit anonymous
   and named questions; confirm pending text/names are absent from audience GET/SSE.
   Approve, manually group a differently worded duplicate, report, review and hide.
   Check no overflow and that touch controls work without accidental ballot changes.
2. Use Tab/Shift-Tab, Enter/Space and native select keys through submission,
   grouping, approval, fair-next, upvote and report. Confirm visible focus and
   understandable labels/status with VoiceOver/Safari or NVDA/Firefox. Verify
   current-question polite announcements and no disruptive focus movement.
3. With reduced motion enabled, cycle questions: manual changes must not animate
   or auto-advance. Verify existing vote bars retain their reduced-motion behavior.
4. Interrupt GET/POST/SSE connectivity. Confirm initial retry, retained failed draft,
   reconnection projections, busy feedback and accurate eventual freeze after end
   or two-hour expiry. Verify reporting is visible only to the presenter and reporter.
5. Run all required checks and accessibility checks before human acceptance. Test
   actual devices/proxy streaming; DOM tests do not prove touch or screen-reader UX.

## Preserved merge policy

Configured source defaults remain disabled/dry-run, quorum 10, 24-hour exposure,
one current-head approval, empty fail-closed base/check allowlists and active kill
switch. Repository/item-kind isolation, source identities, PR head/base binding,
existing ballots, records and receipts are unchanged. Required checks remain
`bun test`, `bun run typecheck`, `route smoke test`, plus existing stricter checks;
at least one human approval is required. Hosted protections and runtime overrides
were not verified or changed. A draft PR/test result is only a review candidate.
Production deployment still requires a human-published tagged release and operator
gate. No automatic merges or relaxed quorum/auth/checks are authorized.
