## Implemented candidate

An optional challenge appears only inside the existing exact-text-bound fictional
transit map. It reuses DemoItem and the existing provenance/source disclosure;
existing stage navigation and selection are unchanged. Other namespaces, IDs and
revised proposal text fail closed. The keyed exercise is discarded on revision
change. It requests a counterargument, source metadata and a short passage or
page reference explaining relevance. Source text is rendered as ordinary text,
never fetched or treated as verified evidence.

Feedback uses a visible self-review rubric: fidelity to the actual objection,
evidence relevance/assumptions, and completeness of trade-offs, affected people
and disconfirming evidence. It acknowledges the exercise regardless of agreement
and suggests revisiting unchecked criteria. It does not independently assess the
response or certify it as the strongest argument. No political leaning is asked
for, inferred or scored. AI scoring is explicitly off with model limitations
explained; starting is optional and clear/skip removes all exercise state.

Everything stays in React memory. No persistence, external evaluator, network
request, ballot handler or model projection is involved. The simulator contract
accepts reviewed numeric mechanisms, not prose or a fidelity assessment; sending
this response to it would create an unsupported interpretation. Existing real
browser choices, fictional totals, source identities, revision bindings, records
and receipts are untouched.

Native labelled textareas, checkboxes and buttons support keyboard/touch; focus
outlines and 44px button minimum height are provided. Layout wraps and textareas
fit the container. This synchronous local exercise has no loading/network failure
state or animation; reduced motion needs no alternative transition. Missing input
has an announced alert; self-review results use a status region. Parent proposal
loading/retry behavior remains unchanged.
