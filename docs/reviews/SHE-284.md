## Implemented behavior and remaining limits

- `/privacy` is a static, initial-HTML notice with metadata and sitemap inclusion,
  usable without JS or an API. It explains stored text/display names/browser IDs,
  optional location, public API access, extraction providers, indefinite active
  retention, drafts, deletion, cookie loss, and backup/log/public-copy limitations.
  Footers link it in civic, citizen-proposal and repository screens, loading and
  static 404 pages. No private support mailbox or retention guarantee was invented.
- Public entry projections omit coordinates and tile IDs on creation, state,
  list aliases and stream events. Source IDs/flags, author, text and extraction
  remain intact. Snapshot responses also omit location, including historical
  snapshots. Persisted coordinate/source data is not bulk rewritten. Existing
  aggregate geo cells and minimum-three-real-entry suppression are unchanged.
- All three journal publication aliases record a domain-separated browser ownership
  hash in private `journalOwners`. Only `/api/state` returns the current browser's
  owned entry IDs. `DELETE /api/journal/:id` and fork undo verify the server-issued
  signed identity; headers/display names cannot select an owner. The existing
  same-origin and combined rate limits apply. PATCH label edits remain disabled.
- The Journal feed offers **Delete my entry**, including after reload. A successful
  deletion saves through the existing atomic JSON writer and emits a feed update.
  Future needs calculations exclude the removed entry. Independent proposals,
  their source entry IDs, reviewed text, comments and ballots remain unchanged.
  Linked frozen snapshots retain plan/source identity while losing location.
- Old entries have no secure ownership evidence. They cannot safely be assigned
  to a visitor; legacy/lost-cookie cases use the existing public removal-request
  link with an ID only. GitHub requires an account, is public, and requests need
  maintainer verification. Existing proposal copies and external copies are not
  erased automatically. This is not a blanket delete-all-data endpoint.
- Civic `/api/votes` accepts validated `withdrawVotes: [proposalId]` and goal
  choices of `null`. Clicking a selected choice clears it; stance changes retain
  the existing **Save votes** step. Errors remain visible. Tallies and active
  participant counts use remaining choices; unrelated browsers' votes persist.
  Empty voter maps remain stored to preserve migration semantics. No repository
  vote/audit storage or immutable PR revision bindings were changed.
