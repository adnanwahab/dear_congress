## Behavior and isolation

TownHallGame is offered in the catalog and six sample workflow stages. The demo
controls link to `/bills#townhall`, removing tour mode before interaction; the
existing tour's inert and read-only behavior remains intact. Starting practice
requires an explicit button. Three fictional scenes show a speaker queue,
question/need conflicts and hypothetical time slots. No countdown pressures the
reader. Decisions cover first-turn access and accommodations, interruption rules
and checking understanding, then accurate records and equal follow-up. Feedback
and the completion count reward procedure, never a political preference or
consensus. Every scene and the complete transcript explicitly identify fiction.

Skip advances without credit. Restart clears choices and feedback; Exit clears
all game state and returns focus to Start. Scene changes and feedback return
focus to the scene heading; feedback also has a status announcement. Native
buttons and details/summary support touch and keyboard operation. The complete
text explanation includes every queue, time budget, decision and feedback before
starting and after completion, without requiring a playthrough.

Game state uses React memory only. The component has no request, storage, voting,
proposal, repository, auth or persistence dependency. No resident input is copied
into scenes. Existing workflow reads/selection behavior is unchanged. Source
chips use the existing badge/source-status classes with a fictional label; theme
colors use the existing card/ink/line/accent variables. No official source claim
or bill identity is assigned to the game.
