## Changes

- Home and feed browse buttons consistently say “View proposal,” use outline
  styling and carry no vote checkmark or pressed state. Existing card/title
  highlighting denotes the proposal being viewed.
- Home selection now updates the proposal URL parameter while preserving other
  parameters. Feed and votes retain their existing URL selection behavior.
- Home and votes panels say “Cast advisory vote”; each submitting button names
  its action and Support / Oppose / Not sure choice. Nearby text explains
  viewing does not vote and choices are non-binding.
- Vote checkmarks remain derived from server-returned browser choices.
  Confirmation still follows successful write and refresh. Selection is disabled
  while saving, preventing a confirmation from appearing beside another proposal.
- No API, identity, proposal IDs, counts, persistence, vote payloads, citizen
  responses, repository/item-kind or PR head/base binding changed.

The React DOM regression in scripts/proposal-selection.test.tsx covers all three
routes: selecting makes no write, URL/restored selection, delayed acknowledgement,
rejected write, retry and confirmed choice. Run with
`bun test scripts/proposal-selection.test.tsx`. It is not a visual browser test.
