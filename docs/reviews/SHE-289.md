# SHE-289 — client bundle reduction

## Audit and scope

Baseline: `75e56a2` on the supplied main-based checkout. Read `readme.md`,
repository voting, community batch, PR preview docs and relevant build, route,
map and governance modules. No AGENTS.md exists in this workspace. GitHub
read-only PR searches on 2026-11-13 returned no open PRs and no PRs matching
`bundle` in any state. PR #1's repository voting implementation is already in
this baseline. No other product's requirements were applied.

The issue's 2.1 MB/deck.gl description predates this checkout: deck.gl is absent
from the dependency manifest and client source. MapLibre was dynamically imported
in two map effects, but Bun.build lacked `splitting:true`. Its CSS was eagerly
imported by main.tsx. Production minification was already configured in server.ts,
and NODE_ENV=production is already configured by Docker/Fly/start.

## Implementation

- Centralize the existing Bun browser build, enable splitting and retain production
  minification. Explicitly define React's environment so production output is also
  reproducible when invoked from tests or development tooling.
- Load MapLibre CSS through a same-origin, security-header-protected read-only
  endpoint. Insert its stylesheet link only when a map effect requests MapLibre;
  avoid Bun collecting map CSS into the initial HTML stylesheet.
- Retain the two existing dynamic map effects, style checks and disposal checks.
  Both use the shared loader. Map views are on `/needs` and `/synth`; `/` and
  `/votes` do not mount them. Repository voting stays dynamically imported.
- Add a production artifact test tracing static imports from HTML, checking the
  total initial gzip JS budget, a distinct dynamic map chunk and exclusion of
  MapLibre CSS from emitted shell stylesheets.
