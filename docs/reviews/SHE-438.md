## Finding

The current contracts cannot support a reviewed cost-versus-modeled-outcome
frontier. They provide package costs without executed package outcomes, and
separately provide law-mechanism outcomes without corresponding policy costs.
Joining these by title, law number or visual proximity would invent attribution.
A sandbox label would not make that join valid. No fabricated points, assumed
zero costs, synthetic confidence intervals or substitute score axis were added.

| Inspected dependency | Existing behavior | Frontier limitation |
| --- | --- | --- |
| `src/client/PlanBudget.tsx`, `src/shared/plan-budget.ts` | Validates integer-million annual allocations, exact replacement IDs, missing estimate dates and unknown uncertainty; local fiscal revisions preserve original package | Fiscal export explicitly is not a synthesis replay; no outcome observations |
| `src/server/policy-comparison.ts`, `src/client/PolicyComparison.tsx` | Content-hashed, persisted pair of default-setting public packages, 100 run seeds and 1/5/10-year horizons | Explicit `outcomes: unknown`, null receiving model version, no executed outcomes or quantiles; does not capture customized client plans |
| `src/server/simulation-snapshot.ts`, `server.ts` snapshot routes | Stores frozen package IDs/items/costs and provides handoff URL; GET redacts location | Creation synthesizes again with defaults and current inputs/history; passing a package name cannot freeze an already displayed customized package. Creation persists data; it is not a read-only frontier query |
| `src/client/LawBehaviorExplorer.tsx` | Validated same-seed paired law receipts; bounded runs, cancel/retry, request identity and version checks | Separate mechanism sandbox explicitly does not apply the frozen civic package. Metrics include different engines, units and horizons; no annual policy-cost or calibrated uncertainty contract |
| `src/client/civic-law-context.ts` | Allowlisted law/strength/seed/population/revision/version URLs, no automatic run | Exact mechanism inputs can reopen; this does not bind legal text, package revision or a fiscal allocation to the result |
| `src/client/ProposalProvenance.tsx`, `src/shared/civic-stages.ts` | Background source disclosures and proposal-preserving stage routes | Background reference is not fiscal/outcome evidence. Demo-item identity must not be coerced into synthesis proposal identity |

Do not use synthesis welfare/support/effectiveness scores as measured or executed
model outcomes. Do not treat model treasury balance or synthetic household rent
as annual public-program cost. Transit minute-series and housing month-series
are incomparable without an explicitly reviewed conversion and scope.

## Bounded implementation contract

Before plotting reviewed points, define a versioned public scenario record that
binds exact source repository/revision, scenario/configuration revision, immutable
package or reviewed mechanism identity, complete allowlisted parameters, fiscal
source/version/date/units, receiving model version and result identity. Retain
seed schedule, population, horizon, baseline, metric definition, direction of
improvement and geographic/model scope. Model and fiscal reviewers must establish
that cost and outcome describe the same intervention. Public records must omit
private journals, votes, identities and location. This work does not authorize
another repository's implementation or product requirements.

Reuse existing fiscal arithmetic, source disclosures, stage navigation, safe
scenario URLs and simulator validation where their contracts actually match.
Provide a clearly labeled **Demo / sandbox — model projections, not forecasts**
entry on `/synth`. Keep real advisory votes, synthetic examples and projections
separate. Do not call snapshot creation on point selection or re-synthesize from
today's inputs to reconstruct a historic scenario. Selection opens the captured
configuration and provenance; an unavailable revision stays unavailable.

For each chosen outcome, compare only scenarios sharing units, direction,
baseline, population/scope, horizon and compatible model/fiscal versions. Within
that cohort, a point is Pareto-undominated when no other point has cost no greater
and outcome no worse with at least one strict improvement. Equal points stay tied;
dominance is relative to the loaded reviewed set, not all possible policies.
Label highlighting “undominated on these two modeled dimensions,” never “best.”
Rights, feasibility and unplotted distributional impacts remain separate caveats.

Display missing costs/outcomes in a companion table, excluded from geometric
ranking rather than plotted as zero. Unknown uncertainty is explicit; known
intervals retain their method, sample count and level. Central-estimate dominance
does not establish dominance under uncertainty. Missing distributional impacts
and incompatible metrics are named, not collapsed into a composite benefit score.

Use native buttons or links for every point and an equivalent text table with
stable scenario IDs. Both must open the same exact configuration via keyboard,
touch and pointer. Provide visible focus, adequate touch targets and no
hover-only information. Loading announces progress; partial/failing results
retain their statuses and retry cannot silently replace scenario versions.
Cancel/ignore obsolete responses. An empty comparable set explains why no
frontier exists. Prefer a static plot; any optional transitions must follow
`docs/motion.md`, including reduced-motion and motion-off behavior.

## Required acceptance evidence

- Arithmetic fixtures: strict dominance, tradeoffs, equal ties, zero values,
  missing/nonfinite data and incompatible cohorts; input-order invariance and
  no mutation of source configurations or existing records.
- Receipt fixtures: wrong configuration/version, missing fiscal lineage,
  unavailable mechanism and expired revision refuse plotting or exact replay;
  unknown uncertainty remains distinct from zero-width intervals.
- UI journeys: plot/table parity, exact point selection, source inspection,
  empty/partial/loading/failure/cancel/retry and stale responses; keyboard,
  screen reader, touch, 320px/reflow, theme/forced-color and reduced-motion checks.
- Rerun required checks and human product/model review before acceptance. A draft
  PR or successful process does not establish reviewed policy scenarios.
