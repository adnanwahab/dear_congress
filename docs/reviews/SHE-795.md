# SHE-795 source-status chips

Refs: https://linear.app/shel-bernstein/issue/SHE-795/cs-l100006-mark-every-entry-point-with-an-unmissable-source-status

## Audit and implementation

Read this repository's AGENTS.md, README, bill catalog, launch policy, native
model loop docs and SHE-349/SHE-545 reviews. Audited existing GitHub PRs via
connected search: #101 compact source disclosures, #175 shared provenance schema,
#203 evidence explorer, #237 build provenance, and #120/#123 native model work.
These are context, not acceptance evidence. No separate SHE-795 candidate was
returned. Existing detailed provenance is retained rather than replaced.

SourceStatus provides four explicit editorial classifications with one static,
outlined, wrapping text treatment: Fictional sample, Unreviewed draft,
Source-backed metadata and Modeled scenario. The shared header shows their guide
and independent advisory beta/no agency endorsement limits. Status is visible
without hover, expansion, color recognition or animation. It uses existing
light/dark ink/card tokens and system colors in forced-colors mode.

Adopted on home proposal gallery/selected vote, daily sample question, sample
walkthrough, curiosity mission, stage navigation cards, shared scenario disclosures
(Feed, Published, Votes and other consumers), illustrative patch comparisons and
sponsor cards. Catalog cards and detail pages are unreviewed drafts; the Bills
navigation link also carries that chip. Official legislation records receive only
metadata status, retaining legal-status uncertainty and exact source citations.
Both frozen-plan simulation controls and native law behavior entry/actor cards
are modeled scenarios, including before a result arrives. Mixed event-directory
content is not blanket-labeled fictional; only its sample walkthrough is.

A real background link never upgrades a fictional proposal to sourced metadata.
The guide describes a vocabulary, not a combined provenance classification for
the whole page. Browser advisory votes remain explicitly unverified activity;
chips classify proposal/model content, not voter eligibility or participation.
Existing detailed origins, source identities, source links, revision digests,
exports, counts and records remain unchanged. No APIs or persistence changed.
