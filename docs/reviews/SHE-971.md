# SHE-971 — launch operator health

Refs: https://linear.app/shel-bernstein/issue/SHE-971/cs-l100083-make-a-launch-operator-health-panel-with-one-screen

## Audit and implementation

Read repository instructions, readme, launch merge policy, launch alerts, launch
readiness, existing stats/auth, persistence and build identity modules. GitHub
search found no SHE-971 PR; related PRs #262 (source health) and #284 (SSE proxy
failures) cover distinct concerns. This panel does not infer health from either.

Added `/admin/health`, sharing existing ADMIN_TOKEN stats authentication, with
no-store, noindex, security headers and no cookie issuance. Empty configuration
fails closed. Credentials never enter page markup or the logs URL. Public
`/healthz` and `/version` responses remain unchanged.

The panel uses image build identity, current serialized JSON write depth and
failure counts, idea-design concurrency and bounded process-local minute buckets
for registered API responses. Route templates retain no request IDs, query strings,
request bodies, credentials or exception messages. Five UTC minute buckets include
the current partial minute; pre-start buckets are missing, not zero. Counters
reset on restart. Failures count 5xx and thrown handlers, including auth wrapper
responses. Streaming body and proxy errors, unmatched routes, fleet aggregation
and durable history are outside this measurement.

There is no managed DB pool saturation instrumentation, governance outbox observer
or upstream health feed. These remain unknown, never green. Queue pressure is not
DB utilization. The page does not initialize governance or probe external services.
Snapshots have generated/start timestamps and a 60-second freshness instruction;
refresh is manual. The fixed Fly monitoring link requires independent provider
login, contains no access token and uses no-referrer/noopener protections.
Rollback instructions require a human owner, compatible previously validated
image, isolated restore verification and the existing tagged release gate.

## Preserved controls and acceptance limits

No vote, repository identity, PR head/base binding, records, receipts or governance
configuration changed. Defaults remain disabled/dry-run, quorum 10, 24-hour
exposure, active kill switch, current-head approvals and checks, with issue scopes
never merging. Production environment values and live branch protections were not
inspected. Main checks remain bun test, bun run typecheck and route smoke test;
at least one human approval is required under docs/launch-merge-policy.md.
No merge, release, deploy, production write, message or Linear transition occurred.

This is a partial operations implementation: external dependency telemetry and
actual DB saturation require further instrumentation and human acceptance.
Do not mark the issue accepted based on this review candidate. Desktop/mobile
browser validation and an authorized deployment remain outstanding.
