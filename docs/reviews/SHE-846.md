# SHE-846: shareable sample proposal context

Refs: https://linear.app/shel-bernstein/issue/SHE-846/cs-l100032-make-copied-urls-preserve-the-readers-topic-and-proposal

## Audit and implementation

Read AGENTS.md, readme.md (including Topic hubs), the launch merge policy,
WorkflowScreen, ProposalSearch, jurisdiction preferences, journey history,
shared topic/stage helpers, JourneyRibbon and bottom navigation.
GitHub searches in adnanwahab/dear_congress found no PR matching SHE-846.
Reviewed open-PR search results, including proposal/topic results; these are
review candidates, not acceptance evidence. No external messages or issue-state
changes were made.

Feed previously canonicalized the selected proposal only after an explicit card
click; filter-driven selection and initial selection could leave the copied
address without the displayed proposal. Topic URL values were passed through
stage links but did not initialize the filter. A recipient's stored jurisdiction
could exclude the requested proposal and silently select another fixture.

All workflow stages now synchronize the displayed sample ID and validated topic
filter into the address bar, preserving history state and other existing URL
context such as demo mode, comparison snapshots and time ranges. Generated stage
links contain only proposal/topic context. No advisory stance, search text,
sponsor draft, office choice or tracker data is serialized by this change.
Fresh proposal/topic links start with all jurisdictions without overwriting the
recipient's stored locality. Existing history entries retain their local filters;
popstate restores topic/query context. Unknown proposal IDs retain the existing
unavailable state. Public guide and README describe the sharing behavior.

## Validation and remaining review

- Focused proposal selection, public guide and jurisdiction tests: 5 passed,
  82 assertions. Coverage includes opening and reopening copied Feed, Draft,
  Sponsors and Outcomes URLs after clearing browser state, conflicting saved
  locality/selection, filter-driven Feed URLs and no vote writes while browsing.
- `bun run typecheck`: passed.
- `bun run test:routes`: blocked at Bun.serve, reporting EADDRINUSE for port 0.
  The router smoke assertions could not run in this environment.
- Full `bun test`: 750 passed, 26 failed. Server integration tests encounter
  the same listen failure. Required checks must pass in a server-capable runner
  before a human considers merging.

These automated DOM checks do not establish deployed browser parity or usefulness
and comprehension. Human review should copy the address bar on all four stages,
open in another browser profile, compare title/topic and confirm that recipient
advisory votes remain independent. No claim is made that sharing creates meaningful
participation. This remains an independently operated, non-binding sample beta.
