## Implementation follow-up — 2026-11-14: journal provenance and shared feed

This section supersedes the original source-blocked conclusion for this bounded
slice. Recovered source is present at baseline `0268a4c`; see
`docs/source-recovery.md`. Read the recovered journal, persistence, moderation,
privacy and publishing paths before finishing the existing uncommitted journal
origin work in this workspace. Repository-scoped GitHub PR search for SHE-271
returned the historical review PR #4 and recovery PR #18. Their descriptions are
history, not current acceptance evidence; the search did not establish PR state.

Implemented:

- Journal writes record `origin: sample | simulated | real`. Seeds are sample;
  synthetic ingest and what-if entries remain simulated with `synthetic=true`;
  ordinary journal submissions are real. Origin describes the submission path,
  not verified identity or factual accuracy. Client-supplied origin is not trusted.
- On database load, an idempotent migration classifies existing journal rows from
  their stored seed/synthetic flags, preserving all other fields. Flags take
  precedence over conflicting origin values. Legacy unflagged journal writes use
  the original ordinary-submission classification (real); no vote inference or
  vote migration is performed. This relies on the recovered seed path marking
  all catalog rows `seeded=true`, rather than matching prose.
- Public journal serialization includes origin and continues to omit coordinates,
  tile IDs and private ownership fields. Moderation filtering still runs first.
- Shared journal defaults to real entries with separate sample/simulated buttons,
  origin badges, empty states and repetition counts/time ranges. The sample text
  shortcut remains synthetic. Real entries do not receive a sample badge.
- `GET /api/entries?origin=real|sample|simulated|all` filters before pagination.
  Filtered simulated reads collapse exact text with identical source AND author
  within 24 elapsed hours of the newest group member, inclusive. Adjacent gaps
  cannot extend the group beyond that anchor. No stored row is removed or merged.
  Different sources/authors remain distinct; no similar-text matching is used.
  `/api/entries/events` supports the same origin filter and grouping for initial
  snapshots and updates. Unfiltered API reads retain the raw-record contract for
  compatibility. The journal screen uses paginated reads, not a new SSE connection.
