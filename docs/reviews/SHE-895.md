## Implemented review candidate

Report an error links appear in sample proposal/background provenance, citizen
proposal details, official metadata cards, curated draft details and static
sample embeds. Sample proposal and background-source targets use separate kinds
with the original sample ID; snapshots retain the background URL and publisher.
Citizen IDs, Congress.gov IDs and HFL IDs are unchanged and isolated by kind.
Official metadata uses its existing sourceHash. Other reports use a SHA-256
fingerprint of the displayed public snapshot. Catalog snapshots include the
canonical catalog revision and HFL-051 supplement, where present. These report
fingerprints do not introduce or modify any ballot revision contract.

`GET /report-error?kind=…&id=…&revision=…` validates the current target and
revision, displays that binding and explains privacy and human-review limits.
`POST /api/error-reports` revalidates the revision and stores the exact snapshot,
reason, receipt UUID, creation time, pending status, version and correction note.
Unknown targets and stale revisions are rejected. A changed source requires
reopening its current link; existing accepted reports keep their original snapshot.
Retries reuse the form UUID; changed content with that UUID returns 409. Text
stays available after network/error responses, and successful intake displays a
receipt. No source/evidence URL is fetched, no official claim is invented, and
reporting never changes text, votes or governance authority.

`/admin/error-reports` is the private authenticated queue, using existing
ADMIN_TOKEN Basic/Bearer verification (disabled without a configured token).
Maintainers record pending/reviewing/corrected/declined and a mandatory note via
`POST /api/admin/error-reports`, protected by authentication and exact same-origin
checking. Version checks prevent stale decisions; history appends each decision.
Marking corrected is a recorded human decision, not an automated content edit.
Any actual correction needs its own reviewed source change. Reports, notes and
snapshots are escaped, no-store and absent from public state/proposal responses.

No reporter name, email, cookie identity, IP, ownership hash or user agent is
stored in a report. The shared public boundary still issues its normal browser
cookie and enforces existing same-origin and IP/browser rate limits. Hosting
request logs remain possible; submitted text itself may contain identifying data,
so the form warns against it and the queue is private. Public guide and privacy
copy explain this distinction. Nothing is sent to GitHub, Linear or another inbox.

The optional errorReports database field is additive, survives demo reset and
uses existing serialized atomic snapshot saving. Report/decision mutations are
serialized and rolled back in memory on save failure. No migration or existing
record deletion is performed. This retains the existing single-writer database
limitation; it does not provide multi-writer transactions, WORM retention or a
cryptographically signed decision log.

source, safety and editorial review as required. The existing Outcomes evidence
