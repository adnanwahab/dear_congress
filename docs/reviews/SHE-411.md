# SHE-411 — Daily curiosity mission

Refs: https://linear.app/shel-bernstein/issue/SHE-411/joyquest-daily-curiosity-mission-featuring-an-unfamiliar-civic-topic

Implemented a clearly labeled demo/sandbox card in Dashboard using its existing
read-only `/api/demo` payload. DailyQuestion remains a separate advisory activity.
Reused DemoItem/DemoPayload, TopicChip, ProposalProvenance and civic stage links.
Inspected the simulator integration: no projection is necessary for this reading
mission, and no simulator requests or model claims were added.

Selection uses the Chicago date's UTC calendar ordinal, sorted topics and sorted
proposal IDs. Topics receive equal daily turns; proposals within a topic rotate on
successive topic cycles. Shuffle traverses a deterministic topic-interleaved deck.
An optional explicit familiar-topic exclusion offers discovery without deriving
interests from journals, votes or political ideology. Without a preference, the UI
states that unfamiliarity cannot be known. With a stable pool, all visitors with
the same date and exclusion see the same starting proposal. Pool changes may alter
selection; no immutable daily server assignment is claimed.

Learn more exposes current-rule context and proposed text, each labeled sample.
Completion requires the visitor's reading confirmation, never a vote. Skip records
no completion. All progress and the familiar-topic choice stay in page memory.
No browser storage, telemetry, vote writes, server changes or data migration added.
Actual legislative metadata stays in its separate lane. Background sources retain
their identities and limitations; samples never become actual introduced bills.

Audited local README, accessibility/motion docs, provenance components, daily question
and simulator boundaries. GitHub searches on November 14 found no curiosity PR;
open adjacent drafts include #128 (first visit), #168 (passport), #169 (sampler),
#172 (roleplay), #173 (budget puzzle). These may overlap the dashboard integration;
this implementation does not assume they are merged or accepted.

Validation: focused selector and isolated React DOM tests cover stable API ordering,
popularity independence, equal daily topic turns, familiar-topic exclusion, loading,
failure, Learn more, reading completion, shuffle resets and skip/resume. Existing
home-start test now targets its own disclosure instead of the first details element.
Controls are native buttons/select/links with visible focus and 44px minimum touch
height; layout wraps. No motion is introduced, including with reduced motion.
Browser layout, real keyboard/touch and screen-reader checks remain unperformed in
this restricted environment and are required before human acceptance.

Governance remains unchanged: disabled/dry-run defaults, quorum 10, 24-hour exposure,
current-head approval/check binding, fail-closed allowlists and active kill switch.
No auth, votes, PR bindings, records or receipts changed. Human review and configured
required main checks remain necessary under docs/launch-merge-policy.md. No external
messages, issue closure, merge, deployment, release or production writes performed.
