# SHE-947 — public text boundary fixtures

Refs: https://linear.app/shel-bernstein/issue/SHE-947/cs-l100078-fuzz-public-text-and-html-sanitization-boundaries

## Evidence and scope

Reviewed readme.md, AGENTS.md, docs/citizen-proposals.md,
docs/legislative-metadata.md and docs/launch-merge-policy.md, plus journal
publication/public projection, proposal/comment handlers, React journal rendering,
page metadata, official metadata parsing and advisory SVG generation.
GitHub connector PR search scoped to adnanwahab/dear_congress for sanitization,
XSS or SHE-947 returned no matches. CLI open-PR inventory failed connecting to
api.github.com; the search does not establish a complete overlapping-PR audit.
No external messages, public load tests or production writes were performed.
Pre-existing untracked orchestration screenshots were left untouched.

These fields are plain text: preserve source bytes (apart from existing input
trimming/limits), encode at the HTML/XML sink, and serve API results as JSON.
Stripping markup during ingestion would alter original evidence and is unnecessary
for text nodes. Reviewed React sinks use text interpolation, not raw HTML.
Existing CSP, signed identity, moderation and publication consent remain in force.

The seeded corpus exposed a reliability defect in server-rendered rich previews:
String.replace interpreted `$&`, `$\`` and `$'` in the encoded replacement string.
A replacement callback now inserts metadata literally. This was output corruption,
not demonstrated script execution. The SVG renderer is exported for direct tests;
its output and production callers are unchanged.

## Automated coverage

src/client/public-text-boundaries.test.tsx uses 17 named attack atoms plus 64
compositions from deterministic seed 947. It exercises:

- Public excerpt preparation and actual no-inference journal publication handler,
  with inference dependencies that throw if called.
- Actual proposal submit, comment submit, detail and source-journal API handlers
  using an isolated in-memory store. JSON content type and exact readback are checked;
  proposal counts remain zero.
- SharedJournalFeed server rendering parsed into a DOM, checking exact text,
  forbidden active elements, event attributes and executable URL schemes.
- Identity-bound Congress.gov metadata parsing with malicious title, sponsor and
  action strings, preserving congress-gov source identity.
- Actual rich-preview page generation and parsed OG attributes, including literal
  dollar substitution tokens, entities, Unicode, tag/attribute breakouts and scripts.
- The actual advisory SVG card renderer, parsed as XML, checking inert structure
  and exact description text even when text attempts to close SVG elements.

Happy DOM parsing is a structural oracle, not proof of native-browser execution
safety. Existing journal consent UI and security tests supplement these fixtures.
This corpus does not mount the citizen comment UI, exercise every imported field
in its final UI, or provide native-browser end-to-end fuzzing of /embed. /embed is
an existing app shell with a separate frame CSP, not a new public-text card API.
SVG export coverage does not establish complete /embed acceptance. Keep the issue
open pending human acceptance and the remaining browser coverage.

was used for measurement. A bounded in-process loop rendered/read the same preview
1,000 times with title `$&` and checked for literal `<title>$&amp; |`:

| Metric | Before | After |
| --- | ---: | ---: |
| Corrupted outputs / 1,000 | 1,000 | 0 |

Timing is a single noisy local sample, not a latency improvement claim. The
reliability result is the meaningful comparison. The seed test initially passed
6,995 assertions; adding journal publication checks raises it to 7,157.

Required commands were attempted:

- `bun run typecheck`: passed after fixture type corrections.
- `bun test`: 654 passed, 27 failed (681 tests). Local server tests fail binding
  `0.0.0.0:0` with EADDRINUSE; the production bundle budget test reports 250,218
  bytes against a strict 250,000-byte limit. Neither limit was weakened.
- `bun run test:routes`: failed at local server startup with the same bind error.
- Focused security/preview/publication/import/UI tests: 36 passed, zero failed
  across eight files (7,891 assertions). `git diff --check` passed.

Full required checks must pass in a socket-capable runner before merge. This
work does not establish production safety or acceptance.

## Reversible staged rollout and governance

Stage 1 is this local test corpus and callback fix, with no data migration,
configuration change or deployment. Stage 2 is human review of the current diff,
completion of the overlapping-PR audit, green required CI, and native-browser
journal/proposal/comment/embedded-card checks on an isolated disposable instance.
Use only fictional test records and no real identities or participation claims.
Stage 3 requires a separately authorized human-published tagged release under the
existing release policy; no rollout is authorized here. A maintainer can revert
the callback change without rewriting any stored text, identities or receipts.

Configured source governance stays disabled/dry-run with quorum 10, 24-hour
exposure, one current-head approval, empty fail-closed base/check allowlists and
active kill switch by default. Browser advisory votes are not verified merge
authority. Preserve all stricter runtime settings. GitHub protection still needs
human approval and required `bun test`, `bun run typecheck`, `route smoke test`;
live protection/runtime state was not verified or changed. No merge, release,
deployment, vote, PR binding, ballot, production record or issue state was changed.
