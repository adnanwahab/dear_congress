## Current behavior and privacy gaps

| Surface | Evidence | Consequence |
| --- | --- | --- |
| `src/client/MapScreen.tsx` | CivicHeader, national county shapes, FIPS-derived requirements, local plan revisions, searchable county buttons; explicit synthetic/unavailable-real-participation disclosures | This is a county sandbox, not neighborhood stories. Preserve its identity and demo tour behavior when adding a separate atlas view. |
| `src/engine/types.ts` JournalEntry | Original text, author, source/origin, optional location/tile ID; no atlas-publication consent | Journal publication and providing a location do not establish consent to this new use. |
| `src/server/geo-cell.ts` | Real coordinates floored to 0.01 degrees | Coarsening alone does not protect sparse locations or authorize publication. Never infer addresses or residence from wording. |
| `server.ts` needsGeo | Public located entries, real/simulated buckets; suppresses real cell totals below three entries | No explicit atlas consent gate. Counts are entries, not distinct people. A retained cell can still expose a per-need count of one. This is not sufficient atlas suppression. |
| `src/server/journal-privacy.ts` | Public projection removes coordinates/tile IDs but retains author/text; deletion clears related simulation locations | Do not use public journals as story exemplars or join them to atlas cells. Atlas withdrawal/cache invalidation does not exist. |
| `src/server/need-clusters/pilot.ts` | Operator manifest binds private consent to journal revision; exact wording/source/locality/month groups; pending private output, member IDs/hashes, distinctParticipants=null, no exemplars | Private clustering consent is not public-atlas authorization. Never send the sidecar to the browser. Its free-form locality is not a validated coarse-area registry. |

The existing public guide warns that published wording can contain locations.
Neither moderation nor coordinate removal guarantees redacted stories. The safest
first public atlas exposes approved aggregate need labels only, without quotations,
authors, journal IDs, source-member links, hashes or hidden HTML payloads.

## Implementation contract to review

1. Add an explicit neighborhood-atlas view starting in MapScreen, sharing the
   existing civic navigation. Keep the county sandbox and its synthetic labels
   intact. A disposable demo atlas must have its own fixed fixture provenance
   and say “Synthetic example — not verified civic participation” in both views.
   Real unavailable, empty, suppressed and failed are distinct states.
2. Before real aggregation, implement ownership-protected, purpose-specific,
   revocable consent for public coarse-area need aggregation. Bind it to entry
   revision, geography version and policy version. Require trusted source
   eligibility, published moderation state and approved coarse-area selection.
   Missing, stale, withdrawn, deleted, unknown or ambiguous records fail closed.
   Client-controlled source/synthetic flags do not verify real participation.
3. Use a versioned allowlisted coarse-area registry and fixed publication windows.
   Never recover residence from text, display names, IPs or coordinates; never
   publish journal coordinates, tile IDs or inferred addresses. Separate repository,
   source-client and item-kind identities privately. Preserve source records.
4. Set and document a reviewed minimum group threshold before publication. Apply
   it to every released area/topic/window group and every exposed breakdown,
   not merely the parent cell. Decide whether the unit is entries or privately
   deduplicated contributors; do not label entries, browser cookies or repeated
   submissions “people.” If the policy requires distinct people and evidence is
   unavailable, publish no real group. The existing threshold of three entries
   is an observation, not an approved new privacy policy.
5. Publish fixed snapshots with no arbitrary sub-cell, time or demographic queries.
   Review complementary suppression, totals and successive releases for subtraction
   attacks. Omit suppressed group identifiers, exact suppressed counts and sparse
   subcategories; do not report suppressed as zero. Withdrawal must invalidate
   current output and caches before further serving, without exposing the withdrawn
   member. Previously copied releases cannot be recalled: explain this limitation
   during consent and adopt a retention/release policy before enabling real output.
6. Introduce a typed, runtime-validated public aggregate projection only after the
   privacy rules exist. Proposed fields: schema/policy/geography/taxonomy versions,
   repository, source class, fixed window, publication revision, generated-at,
   count unit, threshold, methodology and approved groups (coarse area ID, catalog
   need ID, safe count). Use an explicit allowlist serializer. No JournalEntry,
   pilot sidecar or raw-text field belongs in that contract. Validate version,
   bounds, identity and demo/real separation on both sides; malformed responses
   fail closed. This is a design proposal, not an API added by this review.
7. Provide a permanently available non-map table using the identical published
   groups, labels, counts, source status and methodology. Explain population,
   eligibility, exclusions, coarse geometry, window, threshold, suppression,
   count unit, recency, update/withdrawal limits and representativeness. Do not
   imply polling, consensus or verified participation. Internal protected provenance
   may retain source revisions; public provenance must not identify members.

Do not attach this to votes, synthesis weights, merge authority or records/receipts.
An aggregate story view provides exploration, not a verified civic mandate.
