# SHE-850 social-preview regression coverage

Refs: https://linear.app/shel-bernstein/issue/SHE-850/cs-l100033-refresh-social-preview-regression-tests-for-every-major

## Implementation candidate

Audited README, page renderer/tests, production route smoke runner, citizen proposal,
curated catalog and legislative metadata docs, and launch merge policy. GitHub
connector searches for social-preview work and SHE-850 returned no matching PRs;
CLI access to api.github.com was unavailable. This is a limited audit, not proof
that no overlapping work exists.

The existing required `route smoke test` now fetches initial HTML for Home,
three synthetic citizen proposals, HFL-001 and HFL-051, and three missing routes
(generic, proposal and bill). It checks HTTP status, exact decoded titles and
descriptions across ordinary/OG/Twitter metadata, exactly one canonical tag,
canonical/OG URL identity without tracking parameters, Twitter card type, image
URLs, successful PNG responses and 1200×630 dimensions. Metadata must occur once.
Images are fetched through the local production asset route, never from production.

Synthetic proposals exist only in the smoke runner's temporary DB. They include
quotes, angle brackets and ampersands to exercise escaping. No API publication,
real resident record, vote, source identity or receipt is modified. Existing smoke
checks continue against this isolated database. A renderer-level regression test
runs the same preview contract without a socket bind.

Citizen previews now append “Citizen-submitted advisory proposal; not enacted
law.” Curated bills retain “Unreviewed editorial draft concept; not introduced
legislation.” These remain distinct source kinds; publication means publication
within this independently operated, non-binding beta, not governmental enactment.
No sharing benefit or meaningful-participation claim is made.
