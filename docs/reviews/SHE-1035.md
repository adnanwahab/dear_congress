## Integration contract for SHE-1032 / SHE-1029 / SHE-1036

`exportPolicyPreviewSource(store, voter, selection, siteOrigin, reviews)` is read-only.
Pass the actual server citizenProposals collection and authenticated publishing
browser identity, never a deserialized proposal or browser amendment. Existing
PR #450 public saved-version shape is accepted structurally without importing a
module absent on this worktree's older base. The version-1 fallback exactly follows
PR #450, including synthetic section-0 vs citizen section-1. Canonical store scope
is Dear Congress citizen proposals only; HFL editorial concepts, private amendments,
repository ballots and journal sources are not valid input adapters.

Selections bind proposal ID, selected and baseline version IDs, both expected saved
hashes, and explicit transfer confirmation. Saved-version hash uses PR #450's
JSON.stringify({type,title,clauses}) identity. HBL source.contentHash instead hashes
the entire legal object with recursively sorted keys, array order and exact strings.
Clause ordering follows existing legalDiff: baseline order, then newly added IDs.
No Unicode normalization, trimming, rewriting or line-ending conversion occurs.

Output has source, legal, baseline, local metadata and status. Send only
source/legal/baseline through the reviewed outbound adapter, adding schemaVersion
and validated simulation settings there. `no-change` and `not-modeled` are local
results: do not send empty clauses or null sourcePolicyId values. Jurisdiction,
publication status, repository and saved hashes stay in local metadata because
HBL rejects extra source fields. Source URL uses the canonical public version
permalink; URL sanitation strips queries/fragments and rejects credentials and
non-HTTP(S) schemes. No arbitrary source URL from request content is used.

The new module does not write or register a publication route, replace existing
createPreview, or change existing previews. SHE-1032 must explicitly wire this reader
into the existing workflow after dependency review. Do not blindly import/copy the
whole return value as an HBL request. PR #450 permits only its exact synthetic demo
mapping; this new reader defaults to no mappings. Before enabling a modeled export,
a human must establish a server-owned registry of ReviewedPreviewMapping records.
Never accept mapping reviews in an HTTP body. Each binds repository, proposal,
base/selected IDs and hashes, stable clause ID, one of h_lots/f_drainage/t_brt and a
review URL. A URL is an evidence reference, not proof that approval occurred;
registry authorization is the integrator's responsibility. Constitutional changes
always remain unmodeled here. Modify contains exact text only: HBL's existing
parameter diff assigns no inferred numeric effect to wording changes.

No enactment verifier exists in the canonical model. This reader intentionally
supports only prior-proposal-version, even if a caller describes a proposal as law.
A future current-law adapter requires independently reviewed enactment evidence,
not a status string or URL heuristic. Official bill corpus adapters also require
canonical text/version/source provenance; none is invented here. Inspected
src/server/legislation/import.ts and its tests: the official Congress archive
contains detail metadata and raw metadata responses, not full legal clauses.
Do not reinterpret latestAction or proposedChange summaries as enacted text.

HBL binds source version identity to a legal diff hash. A different baseline for
an already-submitted version must not silently reuse its remote identity; local
comparisons remain useful, but the orchestrator must reject incompatible remote
resubmissions under the existing HBL immutable-version rule.

Privacy is enforced by public-store/owner/consent boundaries and an explicit field
allowlist, plus existing contact-detail and precise-coordinate checks on text sent.
Those heuristics cannot prove prose contains no identifying information; explicit
human content review remains required. No problem narrative, journal IDs/text,
account/browser identifiers, locations, votes, publication keys or ownership hashes
are returned. No new vote collection is created and no ballots are copied.
