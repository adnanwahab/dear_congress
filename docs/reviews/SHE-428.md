## Behavior and provenance

HouseholdImpacts offers an optional, lazy-loaded demo. A versioned local ledger
simulator generates both runs for the same synthetic household. Seed 428 modulo
three IDs chooses demo-household-003; the native selector offers all three IDs.
Both columns repeat population identity/size, seed, assumption version, common
monthly inputs, starting state and the sole differing input: a $150 monthly demo
credit versus $0. IDs are fixture identities, not inferred residents. Seed chooses
the default ID; the ledger itself uses no stochastic sampling.

Every displayed narrative line comes directly from a typed ledger event with its
signed dollar change and resulting balance. Expandable source details identify
run/household/month/event kind and assumption version. No mental state, emotion,
policy benefit, probability or real-world representativeness is inferred. The
three-month horizon and omitted processes are disclosed. Existing source chip
styling identifies the synthetic sandbox separately from real votes and measured
outcomes. No journals, account fields, fetch calls, storage writes or server API
mutations supply the model or receive the selection. The optional JS chunk is
loaded locally; a failed load/generation offers retry.

## Interaction and validation

Native buttons, labeled select and details support keyboard/touch operation.
Controls have 44px minimum heights. The table has scoped headers, a caption and a
named keyboard-focusable horizontal overflow region; touch scrolling is excluded
from stage swipe handling. The story has no animation or automatic stepping, so
reduced-motion users receive the same static content. Loading disables repeated
activation; live status reports loading, failure and selection. Close removes the
story and its selection. Pending load completions are ignored after unmount.

Focused tests: 4 pass, 167 assertions. They cover deterministic replay across all
IDs, paired common inputs, event identity, balance reconciliation, expected paired
state differences, invalid IDs, loading, load failure/retry, selector changes,
source-log correspondence, close and no storage/URL changes. The existing private
preset interaction test remains passing. DOM tests do not prove actual browser
layout, native keyboard/screen-reader behavior, touch scrolling or zoom acceptance;
manual desktop/mobile and assistive-technology review remains required.
