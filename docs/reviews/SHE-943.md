# SHE-943 — asynchronous synthesis scoring

Refs: https://linear.app/shel-bernstein/issue/SHE-943/cs-l100074-stop-synchronous-scoring-from-blocking-synthesis

## Evidence and scope

Read AGENTS.md, readme.md, docs/launch-merge-policy.md, source-recovery.md,
SHE-344's live-preview notes, and the engine, idea reports, outcomes, SynthView,
rule sandbox and synthesis route/tests. GitHub read-only PR searches for
`synthesis scoring` (all states) and `synth` (open) in adnanwahab/dear_congress
returned no matches. This is a limited search, not proof of no related PR.
Existing SHE-344 debounce, AbortController and response/transition version guards
were already present. Scoring, idea fit tests and real/blended/shadow calculations
still ran synchronously in the server request handler. Old packages also stayed
visible while sliders showed new inputs.

## Implementation

Extracted the existing calculation into a pure request-snapshot function with the
same real/simulated separation, scoring, package IDs, outcomes and idea reports.
Both ordinary and comparison requests now run in disposable Bun workers, including
explicit saved-plan runs. At most two jobs execute simultaneously; excess work
returns 503 without a queue. Abort terminates the worker, releases capacity and
prevents persistence. A 30-second deadline, worker errors and cloning errors also
clean up capacity and return retryable failure. There is no blocking error fallback.

Only the parent handler writes a plan. Preview, synthetic-only and what-if
persistence exclusions remain unchanged. Before saving a worker result, the parent
compares the database with the request's serialized revision. An intervening
change yields 409 and requires retry. This conservative check includes unrelated
database changes too. Time is frozen once at dispatch. Request abortion after
computation is checked again before saving; it cannot undo an already completed
explicit save.

Changing inputs immediately clears package panels, tabs, diffs and measured
previews. Existing response-version and delayed transition checks remain. AppState
replacement also cancels/recomputes the preview. Historical plan movement remains
an explicitly previous-plan comparison. The fixed-size fixture rule sandbox stays
on its existing path, with its own input-change clearing and sequence guards.

## Local before/after measurements

Reproduce: `bun scripts/benchmark-synthesis.ts` (Bun 1.4.2, macOS arm64).
This script uses 5,000 explicitly sample entries, fixed time, five successive weight
adjustments and real/blended/shadow calculations. It sends no HTTP requests and
writes no database. The before mode runs the extracted unchanged calculation
inline; the after mode includes worker startup, input cloning and result delivery.
A 5 ms timer measures event-loop delay, not browser PerformanceObserver long tasks.

| Work / execution | Total latency, five samples (ms) | Maximum event-loop delay per sample (ms) | Samples with delay >50 ms |
| --- | --- | --- | --- |
| Ordinary / inline | 107.1, 76.5, 73.0, 64.3, 51.0 | 102.4, 71.5, 68.0, 59.3, 46.1 | 4/5 |
| Ordinary / worker | 110.1, 102.7, 101.7, 96.4, 81.5 | 0.6, 0.7, 0.7, 0.6, 0.7 | 0/5 |
| Comparison / inline | 127.2, 103.5, 94.6, 104.5, 76.8 | 122.2, 98.5, 89.6, 99.5, 71.9 | 5/5 |
| Comparison / worker | 160.0, 144.2, 135.3, 131.0, 110.5 | 1.5, 0.6, 0.6, 0.7, 0.6 | 0/5 |

Worker startup increases completion latency while freeing the server event loop.
These small local samples are not production percentiles or browser interaction
latency evidence. They exclude React rendering, HTTP serialization and saved-plan
revision serialization. Cloning and serialization still run on the parent and may
become expensive at much larger sizes; a worker pool or narrower snapshots can be
considered only if subsequent profiling justifies them.

## Reversible rollout and remaining acceptance

1. Local stage: run parity, cancellation, stale-view and persistence tests, then
   the bounded fixture benchmark. No public-site traffic is needed.
2. Human-reviewed staging stage: start the same revision with default worker
   execution and disposable data. Profile pointer/keyboard changes and A/B/C plan
   tabs on desktop/mobile with browser long-task observation. Rapidly adjust
   weights while responses/transition callbacks arrive out of order. Confirm old
   score panels disappear immediately, the newest settings win, and unrelated
   requests stay responsive. Verify Bun's real HTTP disconnect signal terminates
   work, plus timeout, retry and concurrent-write behavior. No public load test is
   authorized; any future test needs an explicit bounded plan first.
3. Human release stage: only after required checks and approval, use the existing
   human-published tagged-release process. Observe latency, 409/503 rates and
   worker memory in a limited release. Operator rollback is
   `SYNTHESIS_EXECUTION=inline` plus process restart (restores blocking scoring,
   retains stale-view guards and persistence checks), or revert this revision.
   No production configuration or release was changed here.

Browser long tasks, visual responsiveness, real disconnect cancellation and
production memory remain unverified. Keep SHE-943 open for human acceptance;
this implementation is a review candidate.
