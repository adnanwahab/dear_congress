# Uncertainty stack contract

The `/outcomes` stack is a read-only synthetic teaching example, separate from
existing activity, observed condition series, ballots, synthesis and storage.
It is not a real policy estimate or evidence of implementation.

## Source manifest (fixture v1, authored 2026-11-14)

These are the complete original invented inputs, not externally observed values.
The corresponding source identities in the UI refer to these sections. Source
paths identify repository documents, not archived public data releases.

### measurement

90–110 sites in a fictional shade installation program. Unit: sites. The range
represents assumed counting uncertainty. No real inventory was consulted.

### model

1–1.2 design allowance multiplier. Assumes some sites need extra installations;
this is an editorial modeling choice represented by synthetic bounds.

### cost

800–1200 dollars per installation. Fictional prices, no currency-year adjustment,
procurement quote or economic appraisal. Conflict fixture includes an invented
unverified user report of 500–700; the original bounds remain visible.

### implementation

1–1.25 delivery allowance multiplier. Assumes overruns only. Missing-source fixture
removes both the source/date and the bounds; it must never become a zero factor.

## Method

For a function y = a × b × c × d with all factors nonnegative and bounded, the
function is monotone in each factor. Thus the product of all lower bounds and
the product of all upper bounds enclose every admissible combination. The fixture
produces 72,000–198,000 dollars. Dependencies can narrow attainable results but
cannot invalidate this enclosing range if the asserted bounds hold jointly.
This is a scenario envelope, not a probabilistic confidence interval. It offers
no coverage probability and does not account for omitted mechanisms. No variance
addition, independent-error assumption, normal approximation, Monte Carlo or
averaging conflicting evidence is supported. Negative, reversed, missing,
nonfinite or overflowing values block propagation. All four unique components,
a supported method, source, calendar date and limitations are required.

## Provenance and review

`EstimateClaim` is local to this estimate contract. This checkout has no shared
claim-provenance schema; draft PR #175 proposes a different shared foundation and
must be reconciled before wider adoption. Existing DemoItem source identities and
ProposalProvenance are unchanged. Primary source, editorial inference, user claim
and synthetic estimate are distinct labels; a citation never upgrades invented
numbers to observations. No primary-data case is claimed here.

Material edits must append a revision log with input IDs, date, rationale and
human-review state. Current fixtures are pending human review. There is no editing
or approval endpoint and no durable user-created estimate store. Future real-data
work requires archived sources, methodology review and authenticated append-only
revision/review recording, not a browser assertion of approval.

## Fallback contract

Cases ship in the browser bundle, so no separate async loading state exists.
They remain usable after page load if network/API calls fail. Before initial page
load, offline availability is not promised. Native select, text list and read-only
textarea provide touch and keyboard access; no hover-only or color-only content.
JSON export contains the full input, review log, method and blocked/result state.
If download APIs fail, the copyable record remains; browser print includes the
stack. External source availability never changes missing evidence into success.
